# 벗 안내서: 방장용

> **경고 1:** 토큰과 단어 코드는 채팅, 파일, 화면 공유에 남기지 않는다.
> **표시:** (미확인) = 시험하지 않았다. 자세한 수동 명령은 [운영_한장.md](운영_한장.md)에 있다.

## 0. 벗이 무엇인가
- 조마다 방장 PC 하나가 방 서버가 된다. 방 서버는 일 목록, 규칙, 화면을 담당한다.
- 팀원은 자기 가지(`member/<이름>/…`)에 제출한다. **방장만 승인하고 합친다.**
- 외부 접속은 **서버장**이 준비한 도메인을 쓴다. 방장은 서버장에게 받은 **방장 열쇠**으로 방을 만든다([안내서_서버장.md](안내서_서버장.md)).

## 1. 준비물
> **주의:** 이 문서의 `python` 명령은 벗 폴더의 가상환경 Python이어야 한다. 시스템 `python`으로 실행하면 `No module named 'uvicorn'` 오류가 난다. 아래처럼 가상환경을 먼저 켠다. `beot.exe`를 쓰면 필요 없다.
> ```powershell
> .\.venv\Scripts\Activate.ps1
> ```

1. Python 3, git, 이 프로그램(벗 폴더).
2. **서버장 주소**(도메인)와 **방장 열쇠**(`bh_…`). 서버장에게 받는다.
3. GitHub 방식이면: **공개 저장소**(README 파일이 있어야 한다)와 그 저장소 하나에 쓰는 GitHub 토큰. 만드는 법은 [방장_GitHub방식_준비.md](방장_GitHub방식_준비.md).
   - **비공개가 필요하면:** 벗의 GitHub 방식은 공개 저장소다. 공개하면 안 되는 자료(기획 문서, 키, 데이터 등)는 저장소에 올리지 않고 **구글 드라이브**로 공유한다. 저장소에는 공개해도 되는 코드만 둔다. (Gitea 방식은 지원하지 않는다. 비공개는 로컬 보관 방식을 쓴다.)

> **exe로 쓸 때:** **설치 파일**(`beot-setup-버전.exe`)을 실행한다(관리자 권한이 필요 없다. 같은 곳에 덮어 설치하면 업데이트다. 앱이나 방 터널이 켜져 있으면 설치가 이유를 알리고 멈춘다. 앱을 트레이 **종료**로 끝내고 다시 설치한다). 설치 없이 쓰려면 압축을 **폴더째** 푼다. 설치 폴더나 압축 폴더에는 `beot.exe` 하나와 `app` 폴더가 있다(`beot.exe`만 따로 옮기지 않는다). **`beot.exe`를 더블클릭하면 앱 창**이 열린다(창 X는 앱을 끝내지 않는다. 아래 8-6절). PowerShell에서는 `python -m beot start` 대신 `beot.exe start`처럼 같은 파일을 명령으로 쓴다. 처음 실행하면 Windows가 "PC를 보호했습니다(알 수 없는 게시자)"라고 막을 수 있다. 출처가 확실하면 **추가 정보 → 실행**을 누른다. exe로 켜면 방 서버는 창 대신 알림 영역 아이콘으로 돈다(아이콘 → 방 끄기). (미확인: 다른 PC에서의 실행·경고 화면)

## 2. 방 만들기
**방법 A — 입구 웹에서 만들기(추천):**
1. 브라우저로 `https://<서버장 주소>`(예: `https://example.com`)를 연다.
2. **방장** 탭을 연다. 처음이면 "처음이면 · 방장 열쇠로 들어가기"를 펼치고 닉네임, 비밀번호(8자 이상), 서버장에게 받은 방장 열쇠(`bh_…`)를 넣어 **계정을 한 번 만든다.** 다음부터는 닉네임과 비밀번호만 넣는다. 계정 없이 열쇠로 바로 들어갈 수도 있다(탭을 닫으면 지워진다). 비밀번호를 잃으면 서버장에게 "계정 풀기"를 요청한다.
3. **방 만들기**를 누른다. 방 코드와 실행할 명령이 나온다.
4. 방장 PC에서 그 명령을 실행한다. 이 PC가 그 방을 켠다.
```powershell
python -m beot start --code <방 코드>
```
- 앱(`beot.exe`) 홈 화면에서 내 방 목록(켜짐/꺼짐, 만료까지 남은 날), **방 화면 열기**, **코드 복사**, **닫기**를 쓸 수 있다.

**방법 B — 터미널에서 바로 만들기:**
```powershell
python -m beot start
```
- 처음 한 번 질문에 답한다.
  1. 방 이름(영문자·숫자·`-`·`_`)
  2. 프로젝트 이름(팀원 PC의 폴더·마당 프로젝트 이름. 비우면 방 이름. 나중에 `--project 이름`으로 바꿀 수 있고 새로 들어오는 팀원부터 적용된다)
  3. 방장 이름
  4. git 방식(1 = GitHub), GitHub 저장소(`소유자/이름`), GitHub 토큰
  5. 서버장 주소(예: `example.com`)와 방장 열쇠
- 토큰은 입력이 화면에 보이지 않는다. 설정 파일에는 저장하지 않고, 이 PC 사용자 환경 변수에만 저장한다.
- 프로그램이 하는 일: 저장소 점검과 규칙 설정, 방과 방장 만들기, **방과 터널 만들기(서버장 Worker)**, 방 서버 켜기, 잠자기 방지.
- 화면에 **로그인 토큰**(방 화면용, 다섯 단어 `xxxx-xxxx-…`)이 한 번 나온다. 안전한 곳에 둔다. 서버장에게 받은 방장 열쇠(`bh_…`)와는 다른 값이다.
- 화면에 **방 코드**(예: `amber-river-moss-123`)와 입구 주소가 나온다. 팀원에게 전달한다.
- 방 서버가 켜지면 **브라우저가 방 화면을 자동으로 연다.** 첫 실행이면 로그인도 자동이다. 다음부터는 로그인 토큰(다섯 단어)을 넣는다. 자동으로 열지 않으려면 `--no-browser`를 붙인다.
- 방 화면을 다시 열 때는 **`beot.exe` → 방 화면 열기**나 트레이 아이콘의 **방 화면 열기**를 누른다. 방장으로 로그인된 채로 열린다(일회용 로그인 링크, 2분·한 번). 입구의 방장 탭에서 **방 화면 열기**를 눌러도 된다. 터미널에서는 `beot.exe start --room 방이름 --open-ui`다.
- 방 화면의 로그인 화면은 **방 계정**(닉네임·비밀번호)이다. 입구(서버장 주소)의 계정과 다르다. 방장 비밀번호를 잃으면 방 서버 PC에서 `beot.exe server set-password 방장닉네임`(방장 닉네임으로 바꿔 쓴다)을 실행한다.
- **한 PC에서는 방을 하나만 켠다**(포트 8780). 방이 여러 개 있으면 `beot.exe`의 방 목록에서 고르고, 켜진 방을 먼저 끈다. `beot.exe`는 선택한 방의 상태를 그 방의 기록(pid)으로 본다.
- 콘솔에서 한글이 깨지면(PowerShell 5.1) 최신 `beot.exe`는 콘솔 출력을 UTF-8로 바꿔서 나온다. 그래도 깨지면 `chcp 65001`을 먼저 실행한다.
- **방은 백그라운드로 돈다.** `.exe`는 기본이고, 소스 실행은 `--background`를 붙인다. 설정이 끝나면 터미널 창을 닫아도 방은 켜져 있다.
- 끄거나 닫을 때는 시계 옆 알림 영역의 **트레이 아이콘**을 우클릭한다(방 화면의 버튼도 같다).
  - **방 끄기**: 방만 멈춘다. 방 코드와 터널은 그대로라서 다시 켜면 같은 방이다.
  - **방 닫기**: 방 코드와 방 주소가 사라진다. 팀원은 못 들어온다. 방 데이터는 이 PC에 남는다.
- **컴퓨터를 켜면 묻는다.** 방을 처음 켠 뒤 "컴퓨터를 켤 때마다 방을 켤지 물을까?"를 한 번 묻는다. 예를 고르면 Windows 로그인 때 "방을 켤까?"가 뜬다. 끄려면 `python -m beot start --no-ask-at-login`.
- 다음부터는 `python -m beot start` 한 줄로 켠다. 방 코드는 그대로다.
- `--dry-run`을 붙이면 켜지 않고 할 일만 보인다.
- 서버장 주소를 비우면 이 PC 안에서만 켠다(외부 접속 없음).
- Gitea 방식(비공개 저장소)은 지원하지 않는다(2026-11-12 제거). 비공개가 필요하면 로컬 보관 방식이나 위의 "비공개가 필요하면"(구글 드라이브)을 쓴다.

**고정해 둘 것:** 방장 PC가 꺼지거나 잠자기에 들면 방은 닫힌 것처럼 보인다. 이 프로그램은 켜 있는 동안 잠자기를 막는다. 노트북은 덮개를 닫지 않는다(전원 설정에서 바꿀 수 있다).

## 3. 팀원 초대
1. 방장 화면의 "멤버" 구역에서 "팀원 추가"를 누른다.
2. 이름과 역할을 정한다. GitHub 방식이면 팀원의 **GitHub 사용자 이름**도 넣는다.
3. 나온 창에서 "안내문 복사"를 누른다. 창을 닫으면 단어 코드를 다시 볼 수 없다.
4. 안내문에는 입구 주소, 방 코드, 단어 코드, 실행 명령이 있다. 팀원에게 안내문과 `join.py` 파일을 보낸다.
5. 팀원에게 [안내서_팀원.md](안내서_팀원.md)를 준다.
- 단어 코드는 24시간 안에 한 번만 쓸 수 있다. 잃었거나 `join`이 실패하면 멤버 줄의 "코드 다시 받기"를 누른다.
- 팀원이 비밀번호를 잃으면 멤버 줄의 **"비밀번호 재설정"**을 눌러 코드(24시간, 한 번)를 받아 전달한다. 방장 본인이 잃으면 방 서버 PC에서 `python -m beot server set-password <내 이름>`을 쓴다.
- 팀원은 처음 입장할 때 닉네임을 한 번 바꿀 수 있다(GitHub 방식, 로컬 보관 방식, git 없는 방). 배정한 일의 담당은 바뀐 이름으로 따라온다.
- 내보내려면 멤버 줄의 "내보내기"를 누른다.
- 틀린 시도: 같은 주소에서 5번, 방 전체에서 20번 틀리면 10분 동안 입장이 닫힌다.

## 4. 일 만들기와 승인
1. 화면의 "새 일"로 일을 만든다. 담당을 고를 수 있다.
2. 순서가 있으면 "먼저 승인돼야 하는 일의 번호"를 넣는다.
3. 팀원이 제출하면 "검토 대기"에 나온다.
4. 변경을 확인한다. 아래 "검토 도우미"를 쓰면 편하다.
5. "승인"을 누르면 PR이 합쳐진다. 반려는 사유가 필수다.
6. **보호 파일 경고**가 있으면 그 파일(`CLAUDE.md`, `.claude/` 등)의 내용을 직접 읽는다. 문제없으면 "확인했고 승인"을 누른다.

### 검토 도우미 (`--review`)
방장 PC에서 실행한다. 제출된 가지를 검토용 작업 폴더로 열고 PR 링크와 변경 요약을 보여 준다.
```powershell
python join.py --review <일 번호>
```
- 방장의 작업 폴더(`C:\Users\<내 이름>\Beot\room`)가 기본이다. 다르면 `--dest <폴더>`를 붙인다.
- 마당이 켜져 있으면 마당 작업 폴더로 열고 PR 링크를 붙인다. 승인과 반려는 화면에서 한다.
- (미확인) 방장 PC에서 실제 방으로 쓴 시험은 하지 않았다.

### 검토 권한 주기
팀원에게 검토를 맡길 수 있다. 검토 권한이 있는 팀원은 "검토" 화면에서 제출물을 승인하거나 반려한다.

**주의:** [보호 파일도 승인]을 켜면 그 팀원은 `CLAUDE.md`, `.claude/` 같은 에이전트 설정 파일을 바꾼 일도 승인한다. 병합되면 모든 팀원의 에이전트가 그 파일을 따른다. 믿는 팀원에게만 켠다.

1. 화면의 "멤버"를 연다.
2. 검토를 맡길 팀원의 [검토 권한]을 켠다.
3. 보호 파일 변경도 맡기려면 [보호 파일도 승인]을 켠다. [검토 권한]이 꺼져 있으면 켤 수 없다.
4. 권한을 거두려면 [검토 권한]을 끈다. [보호 파일도 승인]도 같이 꺼진다.

- 검토 권한자는 자기가 제출한 일을 승인하거나 반려할 수 없다. 방장이나 다른 검토자가 검토한다.
- 보호 파일을 바꾼 일은 [보호 파일도 승인] 권한이 없는 검토자가 반려만 할 수 있다.
- 권한은 방장만 줄 수 있다. 검토자는 다른 사람에게 권한을 줄 수 없다.
- 누가 승인했는지는 기록에 남는다. 팀원을 내보내면 권한도 사라진다.
- 검토 도우미(`--review`)는 지금 방장만 쓴다.

## 4-1. 계획서로 업무 한꺼번에 만들기
에이전트가 쓴 계획서(.md)를 가져오면 업무가 선후관계가 있는 트리로 만들어지고 담당이 정해진다.
1. 방 화면 "업무"의 **계획서 가져오기**를 누른다.
2. **계획서 만들기 프롬프트 복사**를 눌러 에이전트(Claude 등)에게 붙여 넣는다. 에이전트가 목표와 인원수를 묻는다. 답하면 `계획서.md`를 쓴다.
3. 그 파일을 방 서버 PC의 `plan` 폴더(창에 경로가 나온다)에 두거나 창에서 **파일 올리기**로 올린다.
4. **미리보기**에서 트리, 오류(줄 번호), 경고를 본다. 오류가 있으면 문서를 고쳐 다시 한다.
5. `팀원1~N` 칸마다 실제 멤버를 고른다(담당 없음도 된다). **가져오기**를 누른다.
- 형식: `인원: 3` 한 줄, 업무는 `- [키] 제목 | 담당: 팀원1 | 선행: 키, 키` 목록. 들여쓰기(2칸)는 "위 업무가 승인된 뒤에 시작"이다. 업무는 100개, 깊이는 6단계까지.
- 다시 가져오면 같은 키의 업무는 건너뛰고 새 줄만 만든다. 그러니 `[키]`를 직접 정해 두는 것이 안전하다.
- 가져온 뒤 일은 평소처럼 맡기·제출·승인한다. 선행 일이 승인되기 전에는 후행 일을 시작할 수 없다.

## 5. 평소 운영
| 하고 싶은 일 | 방법 |
|---|---|
| 켜기 | `python -m beot start` |
| 끄기 | 창에서 `Ctrl+C`. 방은 만료 기간 안에는 남아 있고 방장 PC가 꺼져 있는 동안 팀원은 들어올 수 없다 |
| **방 닫기(팀플 끝)** | `python -m beot start --close`. 서버장에서 방 주소와 터널이 지워지고 팀원은 더 들어오지 못한다. **방 데이터는 이 PC에 그대로 남는다.** 다시 `python -m beot start`를 하면 새 방 코드로 새 방이 열린다 |
| 방 만료 | 14일(서버장 설정) 동안 켜 있지 않으면 자동으로 닫힌다. 켜 있는 동안은 6시간마다 자동으로 알린다 |
| 백업 | 방장 화면 멤버 구역의 "백업" 버튼. zip에 비밀값이 있다. 다른 곳에 두고 쓴 뒤 지운다. 파일 탭 방은 원본도 들어간다(8-7절) |
| 긴급 공지 | 대화에서 "긴급"을 체크하고 보낸다 |
| 로그인 토큰 바꾸기 | [운영_한장.md](운영_한장.md) 5장의 `rotate`. 방 서버와 같은 환경 변수(`ROOM_DB` 등)가 필요하다. (미확인: `start.py`로 켠 방에서 실행해 보지 않았다) |

## 6. 문제가 생겼을 때
| 증상 | 확인할 것 |
|---|---|
| `서버장 Worker 오류 401` | 서버장에게 받은 방장 열쇠가 맞는지, 폐기되지 않았는지 서버장에게 묻는다 |
| `동시에 열 수 있는 방 수를 넘었다` | 쓰지 않는 방을 `python -m beot start --close`로 닫는다. 더 필요하면 서버장에게 한도를 요청한다 |
| 팀원이 방을 찾지 못한다 | 방 코드 철자, 방 서버가 켜져 있는지, 방이 만료·닫힘 되지 않았는지 |
| 팀원이 코드가 틀렸다고 한다 | 24시간 만료, 이미 사용 → "코드 다시 받기" |
| 승인에서 "가지가 바뀌었다" | 팀원이 다시 제출해야 한다 |
| 터널 토큰을 잃었다 | `python -m beot start`가 서버장에게서 자동으로 다시 받는다(방장 열쇠가 있어야 한다) |
| `이 PC에서 방 서버가 이미 켜져 있다(포트 8780)` | 한 PC에서는 방을 하나만 켠다(포트와 터널 설정이 8780으로 고정). 켜진 방의 창을 닫거나 Ctrl+C로 끈 뒤 다른 방을 켠다. 방 두 개가 필요하면 PC 두 대를 쓴다 |
| `beot.exe`가 원격 데스크톱(AnyDesk 등)에서 멈추거나 창이 사라진다 | 원인을 확인하지 못했다(이슈 #1). `%LOCALAPPDATA%Beotlauncher.log`의 마지막 줄(패닉·창 오류)과 Windows 버전, 원격 프로그램 이름을 이슈에 알려 준다. 임시로 터미널에서 `beot.exe start --room 방이름`으로 켜고 트레이 아이콘을 쓴다 |

## 8. 앱의 새 기능 (1.0.0)
> **표시:** 이 절의 화면 이름은 앱 화면의 글자를 코드에서 읽고 썼다. 실제 화면에서 다시 확인하지 않았다.

### 8-1. 저장 폴더 (방 데이터가 쌓이는 곳)
- 방 데이터(`room.db`)와 파일 탭 원본이 이 폴더에 쌓인다. 문서가 많으면 용량이 커진다. 큰 디스크에 두려고 정한다.
1. 앱 홈의 **새 방 만들기**를 연다.
2. **저장 폴더** 칸에 폴더 경로를 넣거나 **폴더 고르기**를 누른다. 비어 있는 폴더를 고른다. 비우면 기본 위치다.
3. **만들고 켜기**를 누른다.
- 방 줄 아래에 `저장 폴더: …`가 보인다. **용량 보기**로 쓴 크기를 본다.
- 방을 만든 뒤에 옮기려면 먼저 방을 **끈다**. 그 뒤 폴더를 직접 옮긴다. 앱에는 폴더 이동 기능이 없다.
- 저장 폴더는 `beot.exe`가 있는 폴더와 별개다. 앱을 다시 설치해도 저장 폴더는 지워지지 않는다.

### 8-2. 파일 탭 (원본 파일을 방장 PC에 두고 관리)
- 준비: 이 PC에 **git**을 설치한다. 새 방 만들기의 **자료 공유 방식**에서 **로컬 보관**을 고른다.
- 원본은 방장 PC의 로컬 git 저장소다. GitHub가 필요 없다. 이 방식은 비공개 작업에 쓴다(한계는 9절).
1. 방이 켜진 줄의 **파일** 버튼을 누른다(로컬 보관 방에만 보인다).
2. **원본 파일**에서 **올릴 파일**에 이 PC의 경로를 넣거나 **파일 고르기**를 누른다. 폴더로 나누려면 **원본에서의 경로**(예: `docs/a.pdf`)를 넣는다. **올리기**를 누른다.
3. 파일 하나는 **50MB 이하**여야 한다. 넘으면 올릴 수 없다. 큰 파일은 구글 드라이브로 나눈다.
4. 파일을 지우려면 **지우기**를 누른다. 팀원이 이미 받은 사본은 남는다.
5. 팀원이 [완료]를 제출하면 **검토 대기**에 나온다. 바뀐 파일 목록을 읽는다.
6. 맞으면 **승인**을 누른다. 원본에 합쳐진다. 아니면 **반려 사유**를 적고 **반려**를 누른다(사유는 필수다).
- **보호 파일 경고:** 에이전트 설정 파일(`CLAUDE.md`, `.claude/` 등)이 바뀐 제출은 병합되면 다른 팀원의 에이전트가 따른다. 내용을 직접 읽는다. 괜찮으면 **확인했고 승인**을 누른다.
- 병합이 충돌하면 방이 자동으로 풀지 않는다. 팀원에게 새 원본에 맞춰 다시 제출하라고 알린다.
- 팀원은 원본의 `main`에 올릴 수 없다. 팀원은 `member/<이름>/…` 가지로만 제출한다. 폴더별 접근 범위는 없다. 팀원 전원이 전체 파일을 받을 수 있다.
- 방장 PC가 꺼지면 팀원은 사본을 받거나 제출할 수 없다.

### 8-3. [결정] 목록
- 팀원의 에이전트가 중요한 일을 물으면(`decide` 요청) 앱 홈 위에 **결정 요청 N건**이 나온다. 앱이 켜져 있어야 한다.
1. 요청 내용을 읽는다.
2. 선택지 버튼을 누르거나 **직접 답하기**에 적고 Enter를 누른다.
- 에이전트는 `decide`에 스스로 답하지 못한다. 사람의 답만 올라간다.
- 에이전트의 **자료 요청**(`ask`)에는 다른 에이전트가 답한다. 사람의 답이 필요 없다.
- (미확인) 실제 에이전트가 `decide`를 보내는 흐름은 실제 방에서 시험하지 않았다.

### 8-4. 방 삭제
- 꺼진 방의 **삭제**를 누른다. 방이 켜져 있으면 버튼이 없다. 먼저 **끄기**를 누른다.
- **경고:** 방 설정과 데이터를 지운다. 되돌릴 수 없다. 백업이 필요하면 먼저 백업한다.
1. **삭제**를 누른다.
2. 상자에 방 이름을 그대로 입력한다.
- 서버에 등록된 방이면 먼저 닫는다. 방 폴더와 저장 폴더의 벗 파일만 지운다.

### 8-5. 로그인 유지
- 로그인 화면의 **로그인 유지** 칸을 켜면 이 PC에서 비밀번호 없이 들어간다. 기본은 꺼짐이다.
- 비밀번호가 아니라 세션을 Windows 사용자 암호화로 저장한다. 같은 Windows 사용자 계정으로만 쓸 수 있다.
- **경고:** 공용 PC에서는 켜지 않는다. 이미 켰다면 홈 화면의 **로그아웃**을 누른다.

### 8-6. 트레이 (창 X는 종료가 아니다)
- 창 오른쪽 위 X는 창만 닫는다. 앱과 켜진 방은 계속 돈다. 시계 옆 알림 영역에 아이콘 하나가 남는다.
- 아이콘을 두 번 누르면 앱 창이 다시 열린다. 아이콘을 우클릭하면 **앱 열기**, **방 끄기**, **종료**가 있다.
- **종료**를 누르면 켜진 방이 있을 때 "방도 끌까요?" 상자가 나온다. **예**는 방도 끄고 끝낸다. **아니요**는 방을 켜 둔 채 앱만 끝낸다. **취소**는 아무것도 하지 않는다.
- 앱을 작업 관리자에서 강제로 끝내면 방 터널(`cloudflared.exe`)이 남을 수 있다. 남으면 설치가 거부된다. 작업 관리자에서 `cloudflared.exe`를 끝낸다.
- 방 목록은 자동으로 갱신된다.

### 8-7. 백업과 복원
- 백업 zip에는 `room.db` 등과 함께 **파일 탭 원본**(번들)이 들어간다. 백업 zip 안의 `README_복원.txt`가 복원 방법이다. 그 파일을 따른다.
- 요약: `git clone --mirror origin.bundle files/origin.git`을 실행하고 `files_state.json`을 원본 폴더 옆에 둔다.
- zip에 비밀값이 있다. 다른 곳에 두고 쓴 뒤 지운다.

## 9. 비공개와 한계
파일 탭은 원본을 방장 PC에만 둔다. 접근은 초대된 팀원의 토큰으로만 된다. 그래도 아래 일은 막지 못한다.
1. **에이전트:** 팀원의 AI 에이전트는 받은 사본을 읽는다. 읽은 내용은 그 AI 서비스로 전송된다. 비공개로 둘 파일은 팀원이 에이전트에게 열어 주지 않게 정한다.
2. **팀원 PC의 사본:** 팀원에게서 접근을 끊어도 이미 받은 사본은 지워지지 않는다. 팀플이 끝나면 팀원에게 사본 삭제를 요청한다.
3. **방장 PC가 꺼지면 멈춘다:** 사본 받기와 제출이 멈춘다. 방장 PC가 유출되면 원본도 같이 유출된다. 백업 zip도 비공개로 둔다.
4. **Cloudflare 터널:** 전송이 Cloudflare 터널을 지난다. 연결은 암호화돼 있다. 터널을 지난다는 사실은 알고 쓴다.
5. **전체 읽기:** 폴더별 접근 범위가 없다. 팀원 전원이 원본 전체를 받는다.
- (미확인) 실제 터널의 본문 한도(약 100MB)와 시간 제한(약 100초)은 실제 시험에서 확인한다.

## 10. 알려진 한계
- 방장 PC가 꺼지면 팀원은 들어올 수 없다. 닫지 않고 끄면 만료까지 방 주소와 터널이 남는다.
- GitHub 방식은 공개 저장소다. 팀원별 가지 제한이 안 된다(팀원이 다른 팀원의 가지를 바꿀 수 있다).
- 이 PC 밖의 다른 PC에서 에이전트까지 실행하는 전체 흐름은 이 PC 안에서만 확인했다.
- (미확인) 휴대폰 화면, Windows가 아닌 PC.
