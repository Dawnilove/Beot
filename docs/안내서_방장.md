# 벗 안내서: 방장용

> 현재 판: 1.1.5

> **경고 1:** 토큰과 단어 코드는 채팅, 파일, 화면 공유에 남기지 않는다.
> 자세한 수동 명령은 [운영_한장.md](운영_한장.md)에 있다.

## 0. 벗이 무엇인가
- 조마다 방장 PC 하나가 방 서버가 된다. 방 서버는 일 목록, 규칙, 화면을 담당한다.
- 팀원은 자기 가지(`member/<이름>/…`)에 제출한다. **방장만 승인하고 합친다.**
- 외부 접속은 **서버장**이 준비한 도메인을 쓴다. 방장은 서버장에게 받은 **방장 열쇠**으로 방을 만든다([안내서_서버장.md](안내서_서버장.md)).
- **첫 경로(추천):** 팀 밖의 1명(강사 · 동아리 담당 등)이 서버장을 한 번 맡는다. 방장은 그 사람에게 방장 열쇠만 받는다. 방장은 Cloudflare를 다루지 않는다.
- **둘째 경로:** 방장이 서버장을 겸한다. 그러면 [안내서_서버장.md](안내서_서버장.md)의 설치를 먼저 하고, 자기에게 방장 열쇠를 만든다.

## 1. 준비물
> **주의:** 이 문서의 `python` 명령은 벗 폴더의 가상환경 Python이어야 한다. 시스템 `python`으로 실행하면 `No module named 'uvicorn'` 오류가 난다. 아래처럼 가상환경을 먼저 켠다. `beot.exe`를 쓰면 필요 없다.
> ```powershell
> .\.venv\Scripts\Activate.ps1
> ```

1. Python 3, git, 이 프로그램(벗 폴더).
2. **서버장 주소**(도메인)와 **방장 열쇠**(`bh_…`). 서버장에게 받는다.
3. GitHub 방식이면: **공개 저장소**(README 파일이 있어야 한다)와 그 저장소 하나에 쓰는 GitHub 토큰. 만드는 법은 [방장_GitHub방식_준비.md](방장_GitHub방식_준비.md).
   - **비공개가 필요하면:** 벗의 GitHub 방식은 공개 저장소다. 공개하면 안 되는 자료(기획 문서, 키, 데이터 등)는 저장소에 올리지 않고 **구글 드라이브**로 공유한다. 저장소에는 공개해도 되는 코드만 둔다. 비공개가 필요하면 로컬 보관 방식을 쓴다.

> **exe로 쓸 때:** **설치 파일**(`beot-setup-버전.exe`)을 실행한다(관리자 권한이 필요 없다. 같은 곳에 덮어 설치하면 업데이트다. 앱이나 방 터널이 켜져 있으면 설치가 이유를 알리고 멈춘다. 앱을 트레이 **종료**로 끝내고 다시 설치한다). 설치 없이 쓰려면 압축을 **폴더째** 푼다. 설치 폴더나 압축 폴더에는 `beot.exe` 하나와 `app` 폴더가 있다(`beot.exe`만 따로 옮기지 않는다). **`beot.exe`를 더블클릭하면 앱 창**이 열린다(창 X는 앱을 끝내지 않는다. 아래 8-6절). PowerShell에서는 `python -m beot start` 대신 `beot.exe start`처럼 같은 파일을 명령으로 쓴다. 처음 실행하면 Windows가 "PC를 보호했습니다(알 수 없는 게시자)"라고 막을 수 있다. 출처가 확실하면 **추가 정보 → 실행**을 누른다. exe로 켜면 방 서버는 창 없이 백그라운드로 돈다. 끄기는 앱 트레이의 "방 끄기" 또는 앱의 [끄기]다. (M2 시험: 다른 PC 2대에서 설치 파일 1.1.2로 설치 · 실행했다)

## 2. 방 만들기
**방법 A — 입구 웹에서 만들기(추천):**
1. 브라우저로 `https://<서버장 주소>`(예: `https://example.com`)를 연다.
2. **방장** 탭을 연다. 처음이면 "처음이면 · 방장 열쇠로 들어가기"를 펼치고 닉네임, 비밀번호(8자 이상), 서버장에게 받은 방장 열쇠(`bh_…`)를 넣어 **계정을 한 번 만든다.** 다음부터는 닉네임과 비밀번호만 넣는다. 계정 없이 열쇠로 바로 들어갈 수도 있다(탭을 닫으면 지워진다). 비밀번호를 잃으면 서버장에게 "계정 풀기"를 요청한다.
3. **방 만들기**를 누른다. 방 코드와 실행할 명령이 나온다.
4. 방장 PC에서 그 명령을 실행한다. 이 PC가 그 방을 켠다.
```powershell
python -m beot start --code <방 코드>
```
- 앱(`beot.exe`) 홈 화면에서 내 방 목록(켜짐/꺼짐, 만료까지 남은 날), **방 화면 열기**, **코드 복사**, **닫기**를 쓸 수 있다.

**방법 B — 앱에서 만들기:** 앱(`beot.exe`) 홈에서 방을 만든다. 방 이름, 프로젝트 이름, git 방식(로컬 보관 또는 GitHub)을 고른다.
- 새 방은 처음부터 **계획서를 저장소에 두는 방**으로 켜진다(4-1절). GitHub 방식이면 상자 "계획서와 지시서가 공개 저장소에 들어가는 것을 확인한다"를 켠다. 상자를 끄면 옛 방으로 남고 경고가 나온다. 나중에 방 화면에서 옮길 수 있다.
- 방을 켜면 **방장 도우미 준비하고 켜기** 카드가 나온다. 누르면 방장 폴더를 만들고 도우미(claude)를 켠다. 방장 도우미는 일을 하지 않는다. 질문 답 · 1차 검토 · 배정 후보 제안만 한다.
- `python -m beot start`는 앱에서 만든 방을 켠다. 설정이 없는 방이면 "방 설정이 없다. 벗 앱에서 방을 만든다."를 내고 멈춘다.
- 토큰은 설정 파일에 저장하지 않고, 이 PC 사용자 환경 변수에만 저장한다.
- 프로그램이 하는 일: 저장소 점검과 규칙 설정, 방과 방장 만들기, **방과 터널 만들기(서버장 Worker)**, 방 서버 켜기, 잠자기 방지.
- 화면에 **로그인 토큰**(방 화면용, 다섯 단어 `xxxx-xxxx-…`)이 한 번 나온다. 안전한 곳에 둔다. 서버장에게 받은 방장 열쇠(`bh_…`)와는 다른 값이다.
- 화면에 **방 코드**(예: `amber-river-moss-123`)와 입구 주소가 나온다. 팀원에게 전달한다.
- 터미널의 `start`로 켜면 방 서버가 켜진 뒤 **브라우저가 방 화면을 자동으로 연다**(앱의 **만들고 켜기** · **켜기**는 `--no-browser`로 켜므로 자동으로 열지 않는다. 방 줄의 **방 화면 열기**를 누른다). 첫 실행이면 로그인도 자동이다. 다음부터는 로그인 토큰(다섯 단어)을 넣는다. 자동으로 열지 않으려면 `--no-browser`를 붙인다.
- 방 화면을 다시 열 때는 **`beot.exe` → 방 화면 열기**를 누른다. 방장으로 로그인된 채로 열린다(일회용 로그인 링크, 2분·한 번). 입구의 방장 탭에서 **방 화면 열기**를 눌러도 된다. 터미널에서는 `beot.exe start --room 방이름 --open-ui`다.
- 방 화면의 로그인 화면은 **방 계정**(닉네임·비밀번호)이다. 입구(서버장 주소)의 계정과 다르다. 방장 비밀번호를 잃으면 방 서버 PC에서 `beot.exe server set-password 방장닉네임`(방장 닉네임으로 바꿔 쓴다)을 실행한다.
- **한 PC에서 방을 여러 개 켤 수 있다**(최대 20개). 방마다 로컬 포트가 따로 있다(8780~8799). 새 방은 쓰지 않는 번호를 자동으로 받는다. `beot.exe`의 방 목록에서 방마다 켜고 끈다.
  - 두 번째 이후 방을 만들려면 **서버장이 앱의 [서버 업데이트]를 먼저 해야 한다**(입구 Worker 번호 3). 옛 Worker에서는 "서버장 Worker가 옛 버전"이라고 안내하고 만들지 않는다.
  - 서버장이 정한 "동시에 열 수 있는 방" 한도(기본 2개, 최대 20개)도 적용된다.
  - 이 버전 이전에 만든 방은 포트가 8780이다. 옛 방 둘을 함께 켜지는 못한다. 새로 만드는 방부터 다른 포트를 받는다.
- 콘솔에서 한글이 깨지면(PowerShell 5.1) 최신 `beot.exe`는 콘솔 출력을 UTF-8로 바꿔서 나온다. 그래도 깨지면 `chcp 65001`을 먼저 실행한다.
- **방은 백그라운드로 돈다.** `.exe`는 기본이고, 소스 실행은 `--background`를 붙인다. 설정이 끝나면 터미널 창을 닫아도 방은 켜져 있다.
- 끄거나 닫을 때는 앱의 방 목록에서 **끄기** · **닫기**를 누른다(방 화면의 버튼도 같다). 터미널에서는 `python -m beot start --stop`이다.
  - **방 끄기**: 방만 멈춘다. 방 코드와 터널은 그대로라서 다시 켜면 같은 방이다.
  - **방 닫기**: 방 코드와 방 주소가 사라진다. 팀원은 못 들어온다. 방 데이터는 이 PC에 남는다.
- **컴퓨터를 켜면 묻는다.** 방을 처음 켠 뒤 "컴퓨터를 켤 때마다 방을 켤지 물을까?"를 한 번 묻는다. 예를 고르면 Windows 로그인 때 "방을 켤까?"가 뜬다. 끄려면 `python -m beot start --no-ask-at-login`.
- 다음부터는 `python -m beot start` 한 줄로 켠다. 방 코드는 그대로다.
- `--dry-run`을 붙이면 켜지 않고 할 일만 보인다.
- 서버장 주소를 비우면 이 PC 안에서만 켠다(외부 접속 없음).
- 비공개가 필요하면 로컬 보관 방식이나 위의 "비공개가 필요하면"(구글 드라이브)을 쓴다.
- **git 없는 방**(예전 "비공개(git 없음)")은 더 켜지 않는다. 켜면 "git 없는 방은 더 켜지 않는다"가 나온다. 방 데이터는 그대로다. 방 폴더의 `beot.config.json`에서 `"git": "none"`을 `"local"`로 바꾸면 로컬 보관 방으로 켠다. 끄기 · 닫기 · 로그인 때 묻기 풀기는 그대로 된다.

**고정해 둘 것:** 방장 PC가 꺼지거나 잠자기에 들면 방은 닫힌 것처럼 보인다. 이 프로그램은 켜 있는 동안 잠자기를 막는다. 노트북은 덮개를 닫지 않는다(전원 설정에서 바꿀 수 있다).

## 3. 팀원 초대
1. 방장 화면의 "멤버" 구역에서 "팀원 추가"를 누른다.
2. 한 줄에 1명씩 쓴다: `닉네임[, 보기][, GitHub 이름]`. 여러 명을 한 번에 쓴다. GitHub 방식이면 팀원의 **GitHub 사용자 이름**도 넣는다.
3. **미리보기**에서 틀린 줄(이름 규칙 · 겹침)을 고친다. **연습 일**에서 "멤버마다 연습 일 1개"를 고르면 팀원마다 연습 일이 1개 생긴다(`연습/<이름>.md`를 만들어 제출하는 일).
4. 결과 창에서 멤버마다 **안내문 복사**를 누른다. 안내문은 멤버마다 따로 보낸다(단어 코드는 그 멤버의 일회용 비밀값이다). 창을 닫으면 단어 코드를 다시 볼 수 없다.
5. 안내문에는 서버 주소, 방 코드, 단어 코드와 순서가 있다. 순서는 벗 설치 → 앱에서 프로필(닉네임·비밀번호) 만들기 → [기존 서버 들어가기]의 안내문 칸에 안내문을 붙여 넣기(세 칸이 채워진다)다. 방의 닉네임과 비밀번호는 프로필 값으로 자동으로 정해진다. 안내문을 팀원에게 보낸다. `join.py` 파일은 보내지 않아도 된다.
6. 팀원에게 [안내서_팀원.md](안내서_팀원.md)를 준다.
- 단어 코드는 24시간 안에 한 번만 쓸 수 있다. 잃었거나 `join`이 실패하면 멤버 줄의 "코드 다시 받기"를 누른다.
- **팀원 지우기:** 내보낸 멤버는 목록에 남는다. 멤버 줄의 **지우기**를 누르면 목록에서 사라진다(방장만, 내보낸 멤버만). 진행 중이거나 검토를 기다리는 일이 있으면 거부한다. 배정만 된 일은 담당 없이 대기로 돌아간다. 승인된 일과 기록에는 이름이 남는다. 다시 들어오려면 새로 초대한다.
- 팀원이 비밀번호를 잃으면 멤버 줄의 **"비밀번호 재설정"**을 눌러 코드(24시간, 한 번)를 받아 전달한다. 방장 본인이 잃으면 방 서버 PC에서 `python -m beot server set-password <내 이름>`을 쓴다.
- 팀원은 처음 입장할 때 닉네임을 한 번 바꿀 수 있다(GitHub 방식, 로컬 보관 방식). 배정한 일의 담당은 바뀐 이름으로 따라온다.
- 내보내려면 멤버 줄의 "내보내기"를 누른다.
- 틀린 시도: 같은 주소에서 5번, 방 전체에서 20번 틀리면 10분 동안 입장이 닫힌다.
- 팀원은 초대 코드를 낼 때 비밀번호를 정한다. **입장은 사람이 직접 한다**(에이전트 · 스크립트는 입장하지 못한다).
- 팀원에게 **다른 서비스와 같은 비밀번호를 쓰지 않는다**고 알린다. 방장은 방 서버에서 팀원이 로그인할 때의 비밀번호 원문을 받을 수 있다.
- 앱은 프로필 비밀번호로 방 화면에 로그인한다. 예전의 로그인 티켓은 없어졌다.

## 4. 일 만들기와 승인
1. 화면의 "새 일"로 일을 만든다. 담당을 고를 수 있다.
2. 순서가 있으면 "먼저 승인돼야 하는 일의 번호"를 넣는다.
3. 팀원이 제출하면 "검토 대기"에 나온다.
4. 변경을 확인한다. 아래 "검토 도우미"를 쓰면 편하다.
5. "승인"을 누르면 PR이 합쳐진다. 반려는 사유가 필수다.
6. **보호 파일 경고**가 있으면 그 파일(`CLAUDE.md`, `.claude/` 등)의 내용을 직접 읽는다. 문제없으면 "확인했고 승인"을 누른다.

- **기준 문서(작업문서 · 지시서):** 방 화면에서는 읽기만 한다. 옮긴 방은 저장소의 `벗/작업문서.md` · `벗/지시서.md`가 원본이다. 고치려면 파일 탭에서 폴더 칸에 `벗`을 넣고 그 파일을 올린다(로컬 방식). GitHub 방식은 GitHub 화면에서 고치고 병합한다. 옮기지 않은 옛 방의 기준 문서는 고정이다.

### 검토 도우미 (`--review`)
방장 PC에서 실행한다. 제출된 가지를 검토용 작업 폴더로 열고 PR 링크와 변경 요약을 보여 준다.
```powershell
python join.py --review <일 번호>
```
- 방장의 작업 폴더(`C:\Users\<내 이름>\Beot\room`)가 기본이다. 다르면 `--dest <폴더>`를 붙인다.
- 승인과 반려는 화면에서 한다.
- 이 명령은 자동 시험으로만 확인했다. M2 실서버 시험의 검토는 방 화면으로 했다. 명령이 실패하면 화면에서 검토한다.

### 검토 권한 주기
팀원에게 검토를 맡길 수 있다. 검토 권한이 있는 팀원은 "검토" 화면에서 제출물을 승인하거나 반려한다.

**주의:** [보호 파일도 승인]을 켜면 그 팀원은 `CLAUDE.md`, `.claude/` 같은 에이전트 설정 파일을 바꾼 일도 승인한다. 병합되면 모든 팀원의 에이전트가 그 파일을 따른다. 믿는 팀원에게만 켠다.

1. 화면의 "멤버"를 연다.
2. 검토를 맡길 팀원의 [검토 권한]을 켠다.
3. 보호 파일 변경도 맡기려면 [보호 파일도 승인]을 켠다. [검토 권한]이 꺼져 있으면 켤 수 없다.
4. 권한을 거두려면 [검토 권한]을 끈다. [보호 파일도 승인]도 같이 꺼진다.

- 검토 권한자는 자기가 제출한 일을 승인하거나 반려할 수 없다. 방장이나 다른 검토자가 검토한다.
- 보호 파일을 바꾼 일은 [보호 파일도 승인] 권한이 없는 검토자가 반려만 할 수 있다.
- 권한은 방장만 줄 수 있다. 검토자는 다른 사람에게 권한을 줄 수 없다.
- 누가 승인했는지는 기록에 남는다. 팀원을 내보내면 권한도 사라진다.
- 검토 도우미(`--review`)는 지금 방장만 쓴다.

## 4-1. 계획서로 업무 만들기 (계획서는 저장소의 벗/계획서.md)
계획서 파일이 일 목록의 원본이다. 계획서가 바뀌면 방이 일 목록을 키(`[키]`)로 맞춘다. 새 키는 새 일, 바뀐 항목은 그 일의 갱신, 없어진 키는 "없어진 일" 표지다(일은 지우지 않는다).
1. **옮기기(옛 방만):** 방 화면 "전체 일"의 **계획서**를 누른다. 옮기지 않은 방이면 **옮기기** 창이 나온다. 먼저 방 화면 멤버 칸의 [백업]으로 백업한다. GitHub 방식이면 공개 확인 상자를 켠다. **옮기기**를 누른다. 지금 일 목록이 `벗/계획서.md`가 되고 일은 바뀌지 않는다. 새 방은 이 단계가 없다.
2. **계획서** 창에서 **계획서 만들기 프롬프트 복사**를 누른다.
3. 방장 폴더의 에이전트 창에 붙여 넣는다. 에이전트가 목표를 묻는다. 답한다. 에이전트가 `벗/계획서.md`를 쓴다. 담당은 지금 팀원 이름이다.
4. 로컬 방식: 파일 탭을 연다. 폴더 칸에 `벗`을 넣는다. 그 파일을 고르고 올린다. 방이 계획서를 검사한다. 오류(줄 번호)가 있으면 올리지 않고 이유를 보인다. 통과하면 바로 일이 생긴다.
5. GitHub 방식: GitHub 화면에서 `벗/계획서.md`를 올린다. 새 가지 이름을 `member/<내 닉네임>/plan-first`로 정해 PR을 만들고 병합한다(다른 가지 이름은 저장소 규칙이 막는다). 방이 1시간 안에(또는 방을 다시 켤 때) 일 목록을 맞춘다. 계획서에 오류가 있으면 일 목록을 바꾸지 않고 방 대화로 알린다.
- 형식: 업무는 `- [키] 제목 | 담당: 이름 | 선행: 키, 키` 목록. **모든 업무에 [키]**가 있어야 한다. 담당은 멤버 이름 또는 `없음`이다(`팀원1` 칸은 쓰지 않는다). 들여쓰기(2칸)는 "위 업무가 승인된 뒤에 시작"이다. 업무는 100개, 깊이는 6단계까지.
- **계획서의 일은 화면에서 고치지 않는다.** 제목 · 설명 · 마감 · 선행 · 지우기 · 계획 담당은 계획서를 고쳐서 바꾼다. 계획서 밖의 일(화면의 "새 일")은 화면에서 고친다.
- **계획 변경 제안:** 그 뒤의 계획 변경은 팀원 에이전트가 계획 파일만 고친 가지로 제안한다(`plan_propose`). 검토 대기에 "계획 변경 제안 · 새 일 · 바뀐 일 · 없어지는 일 · 담당 바뀜 · 담당 없는 일" 수가 나온다. **방장만** 승인한다. 승인하면 병합하고 일 목록이 바뀐다. 보통 일의 제출이 계획 파일을 바꾸면 방이 거부한다.
- **표지:** 진행 중인 일의 계획이 바뀌면 "계획 바뀜", 계획서에서 빠지면 "없어진 일" 표지가 일 목록과 검토 대기에 달린다. 담당 도우미가 깨어나 바뀐 내용을 읽는다. 표지는 다음 제출이 지운다.
- **검사 명령(선택):** 업무 줄에 `| 검사: python tools/run_tests.py`를 쓰면, 에이전트가 제출하기 전에 그 명령을 실행하고 결과를 함께 보낸다. 검토 화면의 "검사"에 **통과·실패·결과 없음**이 보인다. 실패나 결과 없음은 경고로만 표시하고 승인은 막지 않는다. 결과는 에이전트가 보고한 값이므로 증명이 아니다. 서버는 명령을 실행하지 않는다.
- **완료(선택):** `| 완료: tests/test_x.py 통과, README에 명령 1줄`처럼 사람이 그대로 확인할 수 있는 글(파일 · 명령 · 수)을 200자 이내로 쓴다. 1차 검토가 이 항목을 확인한다.
- **범위(선택):** `| 범위: beot/x.py, docs/`처럼 이 일이 고칠 경로를 10개 · 200자 이내로 쓴다. `/`로 끝나면 폴더다.
- 미리보기는 "확인 방법 없음(검사 · 완료 둘 다 없음) · 흐린 말(잘 · 적절히 등) · 범위 겹침" 수를 경고로 보인다. 막지는 않는다.
- 방장 폴더에는 앱 세션(`/벗 연결`)을 연결하지 않는다. 방장 폴더의 도우미가 1차 검토를 계속한다.
- 키를 바꾸면 "없어진 일 1 + 새 일 1"이 된다. 키는 고치지 않는다.
- 만든 일은 평소처럼 맡기·제출·승인한다. 선행 일이 승인되기 전에는 후행 일을 시작할 수 없다.

## 5. 평소 운영
| 하고 싶은 일 | 방법 |
|---|---|
| 켜기 | `python -m beot start` |
| 끄기 | 창에서 `Ctrl+C`. 방은 만료 기간 안에는 남아 있고 방장 PC가 꺼져 있는 동안 팀원은 들어올 수 없다 |
| **방 닫기(팀플 끝)** | `python -m beot start --close`. 서버장에서 방 주소와 터널이 지워지고 팀원은 더 들어오지 못한다. **방 데이터는 이 PC에 그대로 남는다.** 다시 `python -m beot start`를 하면 새 방 코드로 새 방이 열린다 |
| 방 만료 | 14일(서버장 설정) 동안 켜 있지 않으면 자동으로 닫힌다. 켜 있는 동안은 6시간마다 자동으로 알린다 |
| 백업 | 방장 화면 멤버 구역의 "백업" 버튼. zip에 비밀값이 있다. 다른 곳에 두고 쓴 뒤 지운다. 파일 탭 방은 원본도 들어간다(8-7절) |
| 긴급 공지 | 대화에서 "긴급"을 체크하고 보낸다 |
| 로그인 토큰 바꾸기 | 방 화면 멤버 목록의 내 줄에서 **내 토큰 받기**를 누른다. 이전 방장 토큰 · 에이전트 토큰은 끊긴다(8-6절) |

## 6. 문제가 생겼을 때
| 증상 | 확인할 것 |
|---|---|
| `서버장 Worker 오류 401` | 서버장에게 받은 방장 열쇠가 맞는지, 폐기되지 않았는지 서버장에게 묻는다 |
| `동시에 열 수 있는 방 수를 넘었다` | 쓰지 않는 방을 `python -m beot start --close`로 닫는다. 더 필요하면 서버장에게 한도를 요청한다 |
| 팀원이 방을 찾지 못한다 | 방 코드 철자, 방 서버가 켜져 있는지, 방이 만료·닫힘 되지 않았는지 |
| 팀원이 코드가 틀렸다고 한다 | 24시간 만료, 이미 사용 → "코드 다시 받기" |
| 승인에서 "가지가 바뀌었다" | 팀원이 다시 제출해야 한다 |
| 터널 토큰을 잃었다 | `python -m beot start`가 서버장에게서 자동으로 다시 받는다(방장 열쇠가 있어야 한다) |
| `방 ○○이(가) 이미 켜져 있다(포트 …)` | 같은 포트를 쓰는 방은 함께 켜지 못한다(옛 방 둘, 또는 같은 방을 두 번 켬). 켜진 방을 끈 뒤 켠다. 새로 만드는 방은 다른 포트를 받는다 |
| `서버장 Worker가 옛 버전이라 두 번째 이후 방…` | 서버장이 앱의 [서버 업데이트]를 한 뒤 다시 만든다 |
| `beot.exe`가 원격 데스크톱(AnyDesk 등)에서 멈추거나 창이 사라진다 | 원인을 확인하지 못했다(이슈 #1). `%LOCALAPPDATA%Beotlauncher.log`의 마지막 줄(패닉·창 오류)과 Windows 버전, 원격 프로그램 이름을 이슈에 알려 준다. 임시로 터미널에서 `beot.exe start --room 방이름`으로 켜고, 끌 때는 `beot.exe start --room 방이름 --stop`을 쓴다 |

## 8. 앱의 기능 (1.0.0부터)
> **표시:** 이 절의 화면 이름은 앱 화면의 글자를 코드에서 읽고 썼다. 실제 화면에서 다시 확인하지 않았다.

### 8-1. 저장 폴더 (방 데이터가 쌓이는 곳)
- 방 데이터(`room.db`)와 파일 탭 원본이 이 폴더에 쌓인다. 문서가 많으면 용량이 커진다. 큰 디스크에 두려고 정한다.
1. 앱 홈의 **새 방 만들기**를 연다.
2. **저장 폴더** 칸에 폴더 경로를 넣거나 **폴더 고르기**를 누른다. 비어 있는 폴더를 고른다. 비우면 기본 위치다.
3. **만들고 켜기**를 누른다.
- 방 줄 아래에 `저장 폴더: …`가 보인다. **용량 보기**로 쓴 크기를 본다.
- 방을 만든 뒤에 옮기려면 먼저 방을 **끈다**. 그 뒤 폴더를 직접 옮긴다. 앱에는 폴더 이동 기능이 없다.
- 저장 폴더는 `beot.exe`가 있는 폴더와 별개다. 앱을 다시 설치해도 저장 폴더는 지워지지 않는다.

### 8-2. 파일 탭 (원본 파일을 방장 PC에 두고 관리)
- 준비: 이 PC에 **git**을 설치한다. 새 방 만들기의 **자료 공유 방식**에서 **로컬 보관**을 고른다.
- 원본은 방장 PC의 로컬 git 저장소다. GitHub가 필요 없다. 이 방식은 비공개 작업에 쓴다(한계는 9절).
1. 방이 켜진 줄의 **파일** 버튼을 누른다(로컬 보관 방에만 보인다). 방 화면의 **파일** 탭이 같은 창에서 열린다. 방 화면에서 왼쪽 메뉴의 **파일**을 눌러도 된다.
2. 파일은 폴더 트리로 보인다. 폴더를 누르면 접고 펼친다. 파일을 누르면 오른쪽에 내용이 보인다(텍스트와 그림. 그 밖의 형식은 **내려받기**).
3. 올리려면 **파일 선택**으로 파일을 고르고, 폴더로 나누려면 **올릴 폴더**(예: `docs`)를 적고 **올리기**를 누른다. 파일 하나는 **50MB 이하**여야 한다. 큰 파일은 구글 드라이브로 나눈다.
4. 파일을 지우려면 파일을 눌러 **지우기**를 누른다. 팀원이 이미 받은 사본은 남는다.
5. 팀원이 [완료]를 제출하면 방 화면의 **검토** 탭(또는 앱의 **검토 대기**)에 나온다. **바뀐 파일 보기**로 바뀐 파일 목록을 읽는다.
6. 맞으면 **승인**을 누른다. 원본에 합쳐진다. 아니면 **반려 사유**를 적고 **반려**를 누른다(사유는 필수다).
- **보호 파일 경고:** 에이전트 설정 파일(`CLAUDE.md`, `.claude/` 등)이 바뀐 제출은 병합되면 다른 팀원의 에이전트가 따른다. 내용을 직접 읽는다. 괜찮으면 **확인했고 승인**을 누른다.
- 병합이 충돌하면 방이 자동으로 풀지 않는다. 팀원에게 새 원본에 맞춰 다시 제출하라고 알린다.
- 팀원은 파일 탭에서 목록을 보고 내려받을 수 있다. 팀원은 `문서함/<이름>/` 아래에는 승인 없이 올릴 수 있다(200MB까지, 에이전트 설정 파일은 불가). 방장은 파일 탭에서 지울 수 있다. 팀원은 원본의 `main`에 올릴 수 없다. 팀원은 `member/<이름>/…` 가지로만 제출한다. 폴더별 접근 범위는 없다. 팀원 전원이 전체 파일을 받을 수 있다.
- 방장 PC가 꺼지면 팀원은 사본을 받거나 제출할 수 없다.

### 8-3. [결정] 목록
- 팀원의 에이전트가 중요한 일을 물으면(`decide` 요청) 앱 홈 위에 **결정 요청 N건**이 나온다. 앱이 켜져 있어야 한다.
1. 요청 내용을 읽는다.
2. 선택지 버튼을 누르거나 **직접 답하기**에 적고 Enter를 누른다.
- 에이전트는 `decide`에 스스로 답하지 못한다. 사람의 답만 올라간다.
- 에이전트의 **자료 요청**(`ask`)에는 다른 에이전트가 답한다. 사람의 답이 필요 없다.
- M2 실서버 시험에서 팀원 에이전트의 `decide` 요청과 방장의 화면 답을 확인했다.

### 8-4. 방 삭제
- 꺼진 방의 **삭제**를 누른다. 방이 켜져 있으면 버튼이 없다. 먼저 **끄기**를 누른다.
- **경고:** 방 설정과 데이터를 지운다. 되돌릴 수 없다. 백업이 필요하면 먼저 백업한다.
1. **삭제**를 누른다.
2. 상자에 방 이름을 그대로 입력한다.
- 서버에 등록된 방이면 먼저 닫는다. 방 폴더와 저장 폴더의 벗 파일만 지운다.

### 8-5. 로그인 유지
- 로그인 화면의 **로그인 유지** 칸을 켜면 이 PC에서 비밀번호 없이 들어간다. 기본은 꺼짐이다.
- 비밀번호가 아니라 세션을 Windows 사용자 암호화로 저장한다. 같은 Windows 사용자 계정으로만 쓸 수 있다.
- **경고:** 공용 PC에서는 켜지 않는다. 이미 켰다면 홈 화면의 **로그아웃**을 누른다.

### 8-6. 앱 트레이 (창 X는 종료가 아니다)
- 창 오른쪽 위 X는 창만 닫는다. 앱과 켜진 방은 계속 돈다. 시계 옆 알림 영역에 아이콘 하나가 남는다.
- 아이콘을 두 번 누르면 앱 창이 다시 열린다. 아이콘을 우클릭하면 **앱 열기**, **방 끄기**, **종료**가 있다.
- **종료**를 누르면 켜진 방이 있을 때 "방도 끌까요?" 상자가 나온다. **예**는 방도 끄고 끝낸다. **아니요**는 방을 켜 둔 채 앱만 끝낸다. **취소**는 아무것도 하지 않는다.
- 앱을 작업 관리자에서 강제로 끝내면 방 터널(`cloudflared.exe`)이 남을 수 있다. 남으면 설치가 거부된다. 작업 관리자에서 `cloudflared.exe`를 끝낸다.
- 방 목록은 자동으로 갱신된다.

### 8-6b. 명령줄과 단축키
방 화면에서 쓴다. 글을 쓰는 중에는 단축키가 꺼진다.
- **Ctrl+K**(또는 `/`): 명령줄을 연다. 글자를 쓰면 화면 이동·동작이 걸러지고, 일(제목·본문)과 대화 글이 검색된다. ↑↓로 고르고 Enter로 연다. Esc로 닫는다.
- 비공개 1:1 대화(DM)는 그 두 사람만 검색된다. 방장도 남의 DM은 보이지 않는다.
- **`?`**: 단축키 도움말.
- **`j` / `k`**: 전체 일 목록에서 아래 / 위 일로 이동한다. **Enter**로 고른 일을 연다.
- **`v`**: 전체 일 보기를 바꾼다(목록 → 트리 → 칸반 → 타임라인).

### 8-6c. Notion 연동 (M3에서 지움)
방의 Notion 내보내기 · 일 동기화(벗 → Notion)는 M3에서 지웠다. 에이전트가 자기 Notion을 읽는 **Notion MCP** 연결(앱 설정)은 그대로다.
- 옛 설정이 남은 방도 그대로 켜진다. 남은 값은 읽지 않는다.
- 저장해 둔 Notion 통합 토큰은 Windows 사용자 환경 변수 `BEOT_NOTION_TOKEN_<방>`에 있다. 직접 지운다(설정 → 시스템 → 정보 → 고급 시스템 설정 → 환경 변수).

### 8-6d. 방장 에이전트 연결 (내 방에 Claude Code 등 연결)
방장도 에이전트를 내 방에 연결해 일 만들기·배정·진행 확인을 시킬 수 있다. 앱에 서버 계정으로 로그인한 방장만 쓴다.
1. 앱을 열고 **설정**(홈 위 **계정 … ›**)을 연다.
2. **내 방에 에이전트 연결 (방장)**에서 방이 켜져 있는지 본다. 꺼져 있으면 먼저 방을 켠다.
3. **에이전트 연결 만들기**를 누른다. 방장 에이전트 토큰을 만들고 작업 폴더(`C:\Users\<내 이름>\Beot\<방 이름>-owner`)에 `.mcp.json`, `CLAUDE.md`, `AGENTS.md`를 쓴다. 1.1.5부터 에이전트 토큰은 이 PC의 토큰 저장소에만 있고, `.mcp.json`에는 토큰 대리 주소와 대리 열쇠만 있다(팀원 안내서 "토큰 대리").
4. 아래 **에이전트 MCP 연결**에서 그 폴더(`<방 이름>-owner`)의 **연결 확인**, **설정 쓰기**, **열기**, **명령 복사**를 쓴다.
5. 연결되면 에이전트에 "작업 세션을 시작한다"라고 입력한다. 규칙 파일은 방장용이다. 승인·반려는 방장(사람)이 시킬 때만 한다.
- **주의:** 이 토큰은 방장 권한 전부를 가진다. 토큰은 작업 폴더의 `.mcp.json`과 `.git/beot/`에 있다. 폴더를 공유하거나 커밋하지 않는다.
- 토큰은 90일 뒤 만료된다. **토큰 새로 만들기**를 누르면 이전 토큰은 끊기고 폴더 파일이 새 토큰으로 바뀐다. **토큰 끊기**를 누르면 즉시 끊긴다.
- **다른 PC에서 방장 에이전트 쓰기:** 방 화면 멤버 목록의 내 줄에서 **내 토큰 받기**를 누르면 새 토큰의 연결 링크가 한 번 보인다(이전 방장 토큰·에이전트 토큰은 끊긴다). 다른 PC의 앱 **설정 → 토큰 등록**에 붙여 넣는다. 자세한 내용은 팀원 안내서 4절을 본다.
- 방장 로그인(닉네임·비밀번호)과 방장 열쇠는 바뀌지 않는다. 방 토큰을 재발급하거나 방장을 폐기하면 에이전트 토큰도 끊긴다.
- M2 실서버 시험에서 방장 에이전트(Claude Code · Codex)가 이 연결로 질문에 답하고 제출에 의견을 썼다.

### 8-7. 백업과 복원
- 백업 zip에는 `room.db` 등과 함께 **파일 탭 원본**(번들)이 들어간다. 백업 zip 안의 `README_복원.txt`가 복원 방법이다. 그 파일을 따른다.
- 요약: `git clone --mirror origin.bundle files/origin.git`을 실행하고 `files_state.json`을 원본 폴더 옆에 둔다.
- zip에 비밀값이 있다. 다른 곳에 두고 쓴 뒤 지운다.

## 9. 비공개와 한계
파일 탭은 원본을 방장 PC에만 둔다. 접근은 초대된 팀원의 토큰으로만 된다. 그래도 아래 일은 막지 못한다.
1. **에이전트:** 팀원의 AI 에이전트는 받은 사본을 읽는다. 읽은 내용은 그 AI 서비스로 전송된다. 비공개로 둘 파일은 팀원이 에이전트에게 열어 주지 않게 정한다.
2. **팀원 PC의 사본:** 팀원에게서 접근을 끊어도 이미 받은 사본은 지워지지 않는다. 팀플이 끝나면 팀원에게 사본 삭제를 요청한다.
3. **방장 PC가 꺼지면 멈춘다:** 사본 받기와 제출이 멈춘다. 방장 PC가 유출되면 원본도 같이 유출된다. 백업 zip도 비공개로 둔다.
4. **Cloudflare 터널:** 전송이 Cloudflare 터널을 지난다. 연결은 암호화돼 있다. 터널을 지난다는 사실은 알고 쓴다.
5. **전체 읽기:** 폴더별 접근 범위가 없다. 팀원 전원이 원본 전체를 받는다.
- Cloudflare 터널은 요청 본문을 약 100MB, 응답 시간을 약 100초로 제한한다(Cloudflare 안내). 이보다 큰 파일은 터널로 올리지 않는다.

## 10. 알려진 한계
- 방장 PC가 꺼지면 팀원은 들어올 수 없다. 닫지 않고 끄면 만료까지 방 주소와 터널이 남는다.
- GitHub 방식은 공개 저장소다. 팀원별 가지 제한이 안 된다(팀원이 다른 팀원의 가지를 바꿀 수 있다).
- 이 PC 밖의 다른 PC에서 에이전트까지 실행하는 전체 흐름은 이 PC 안에서만 확인했다.
- 휴대폰 화면과 Windows가 아닌 PC는 지원하지 않는다.
