# 터널로 밖에서 접속하기 (수동 절차, 도메인 필요)

> **이 문서의 위치:** 서버장 구조(`beot owner`와 `start.py`)를 쓰면 터널, 방 주소, 터널 토큰을 프로그램이 만든다. 이 문서의 수동 절차는 **서버장 없이 직접 터널을 만들 때만** 쓴다. 서버장 구조는 [안내서_서버장.md](안내서_서버장.md), [안내서_방장.md](안내서_방장.md)를 따른다.
> 서버장 구조에서는 아래 3절(Access)을 쓰지 않는다.

> **경고 1:** 이 절차를 시작하면 방 서버가 인터넷에서 보이는 주소를 가진다. 로그인 토큰이 방 전체 권한이다. 토큰은 채팅·파일·화면 공유에 남기지 않는다.
> **경고 2:** 터널 토큰도 비밀값이다. 파일에 적지 않는다. 사용자 환경 변수에만 저장한다.
> **경고 3:** 퀵 터널(계정·도메인 없이 `cloudflared tunnel --url`)로 확인한 것: 접속자 IP 헤더 `CF-Connecting-IP`가 실제로 오고, 서버가 그 값을 접속 주소로 쓴다. 공개 주소로 HSTS, MCP 접속, 틀린 토큰 5번 잠금이 동작한다. **(미확인)** 이름 있는 터널, Cloudflare 화면 이름과 단계, Access(이메일 인증)와 제외 경로는 계정과 도메인이 있어야 해서 시험하지 않았다. 화면 이름이 다르면 Cloudflare 안내를 따른다.
> 도메인 구매, Cloudflare 가입, 터널·Access 설정은 방장이 직접 한다.

## 0. 용어
- **터널:** 방장 PC에서 Cloudflare로 나가는 연결. 방화벽 설정과 포트포워딩이 필요 없다.
- **Access:** 방 서버에 닿기 전에 이메일 인증 코드로 한 번 더 확인하는 Cloudflare 기능(무료 50명까지).
- **터널 모드:** `ROOM_TUNNEL=1`. 방 서버가 접속자 IP를 터널이 붙인 헤더에서 읽는다.

## 1. 방 서버를 터널 모드로 켠다
1. 새 PowerShell 창에서 환경 변수를 정한다. 기존 변수(`ROOM_DB` 등)는 그대로 둔다.
```powershell
$env:ROOM_TUNNEL = "1"
$env:ROOM_PUBLIC_URL = "https://<방 이름>.beot.space"
```
2. **`ROOM_ALLOWED_HOSTS`에 공개 주소의 호스트 이름을 넣는다.** 넣지 않으면 에이전트(MCP) 접속이 `421 Invalid Host header`로 거부된다(퀵 터널에서 확인). 화면(`/ui`)은 영향이 없다.
```powershell
$env:ROOM_ALLOWED_HOSTS = "<방 이름>.beot.space,127.0.0.1:*,localhost:*"
```
3. `ROOM_BIND_IP`는 켜지 않는다. `ROOM_REQUIRE_TS`도 켜지 않는다. 함께 쓰면 서버가 시작을 거부한다.
4. 서버는 `127.0.0.1`에만 연다. 이 PC의 터널 프로그램만 서버에 닿는다.
```powershell
.\.venv\Scripts\python -m beot server serve --host 127.0.0.1 --port 8780
```
5. 시작 줄에 `터널 모드: True`가 나오는지 확인한다.

## 2. 터널을 만든다 (미확인)
1. Cloudflare에서 도메인을 연결한다.
2. Zero Trust 메뉴에서 터널을 만들고 `cloudflared` 설치 안내를 따른다.
3. 터널의 공개 호스트 이름을 `<방 이름>.beot.space`으로 정하고, 서비스를 `http://127.0.0.1:8780`으로 정한다.
4. 터널 토큰은 사용자 환경 변수로 저장한다. 파일에 적지 않는다.

## 3. Access를 붙인다 (미확인, 서버장 구조에서는 쓰지 않는다)
서버장 구조에서 Access를 쓰지 않는 이유: 팀원이 이메일 등록이나 추가 가입 없이 "방 코드와 비밀번호"만으로 들어와야 한다. 방어선은 방 토큰, 단어 코드, 틀린 횟수 잠금(같은 주소 5번, 방 전체 20번)이다. 직접 터널을 만들고 Access를 쓰려면 아래를 따른다.

**중요:** Access를 주소 전체에 붙이면 에이전트(MCP)와 `join`이 막힌다. 이들은 브라우저가 아니어서 이메일 인증을 할 수 없다. 두 경로는 Access에서 제외하고, 방 서버의 토큰과 횟수 제한이 지킨다.

| 경로 | Access | 이유 |
|---|---|---|
| `/mcp*` | 제외(Bypass) | 에이전트가 방 토큰으로 접속한다 |
| `/api/redeem` | 제외(Bypass) | `join`이 단어 코드를 교환한다. 틀린 시도는 방 서버가 제한한다 |
| 그 밖의 모든 경로(`/ui`, `/api/state`, `/api/call/*`) | 이메일 인증 필요 | 브라우저 접속은 한 번 더 확인한다 |

1. Access에서 자체 호스팅 애플리케이션을 만든다. 주소는 `<방 이름>.beot.space`이다.
2. 허용 정책에 방장과 팀원의 이메일을 넣는다.
3. `/mcp*`와 `/api/redeem`에 제외 정책을 만든다.

## 4. 터널 모드에서 달라지는 것
| 항목 | 내용 |
|---|---|
| IP 묶기 | 쓸 수 없다. 모든 접속이 터널을 거쳐 같은 주소로 보이기 때문이다. 방장 방어선은 로그인 토큰, 횟수 제한, Access다 |
| 틀린 토큰 횟수 제한 | 같은 접속자 IP에서 10분에 5번 틀리면 그 IP는 맞는 토큰도 10분 거부된다. 서버를 다시 켜면 풀린다 |
| 새 IP 기록 | 멤버가 처음 보이는 IP로 접속하면 방장 화면의 "접속 기록 > 최근 접속 IP"에 남는다. 처음 이후의 IP에는 "새 IP" 표시가 붙는다. 차단은 아니다 |
| 로그인 토큰 재발급 | 대화에 "alice의 방 토큰이 재발급됐다"가 남는다 |
| HTTPS | 터널이 HTTPS를 맡는다. 서버는 `Strict-Transport-Security`를 붙인다 |

## 5. 휴대폰으로 방장이 접속하기
1. 휴대폰 브라우저에서 `https://<방 이름>.beot.space/ui`를 연다.
2. Access의 이메일 인증을 한다.
3. 로그인 토큰을 입력한다. **"이 기기에서 기억하기"는 켜지 않는다.** 잠금이 없는 기기에서 휴대폰을 잃으면 방 전체 권한이 넘어간다.

## 6. 알아 둘 한계
- 같은 공유기(같은 공인 IP) 뒤의 사람이 틀린 토큰을 반복하면 그 IP 전체가 10분 잠긴다. 방장 휴대폰이 같은 Wi-Fi에 있어도 영향을 받을 수 있다.
- 틀린 방 토큰으로 계속 재시도하는 에이전트가 있으면 같은 IP의 정상 접속이 잠길 수 있다. 에이전트의 토큰이 맞는지 먼저 확인한다.
- 방장 PC가 꺼지거나 잠자기에 들면 이 방은 닫힌다.
- 방 서버의 잠금 횟수는 메모리에만 있다. 서버를 다시 켜면 풀린다.
