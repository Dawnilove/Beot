# 방장 준비: GitHub 방식 방 만들기

> **경고 1:** 이 방식의 저장소는 **공개**다. 누구나 코드를 볼 수 있다. 팀 모두가 동의해야 한다. 비밀번호, API 키, `.env` 파일은 저장소에 올리지 않는다.
> **경고 2:** 아래 3단계의 토큰은 이 저장소의 **관리자 권한**을 가진다. 새면 저장소를 남이 관리할 수 있다. 채팅, 파일, 화면 공유에 남기지 않는다. 환경 변수로만 둔다.
> **표시:** (미확인) = 화면 이름과 권한 이름은 GitHub 공식 문서를 기준으로 썼고 이 방 서버와 실제로 연결해 시험하지 않았다. 이름이 다르면 GitHub 화면을 따른다. 시험은 G5에서 한다.

## 0. 이 방식이 맞는가
| | GitHub 방식 | Gitea 방식 |
|---|---|---|
| 코드 | **공개** | 비공개 |
| "방장만 병합" 강제 | O (규칙 세트) | O |
| 팀원별 가지 제한 | **X** (팀원이 다른 팀원의 `member/…` 가지를 바꿀 수 있다) | O |
| 방장 PC 설치 | 없음 | Gitea 설치 |
| 팀원 준비 | **본인 GitHub 계정**, 초대 수락 | 없음 |
코드를 공개하기 어렵거나 팀원별 가지 제한이 필요하면 Gitea 방식을 쓴다.

## 1. 저장소 만들기 (GitHub 화면)
1. GitHub에서 새 저장소를 만든다.
2. 공개(Public)를 고른다. 비공개는 무료 계정에서 규칙 세트가 적용되지 않는다.
3. **README 파일을 추가한다.** 기본 가지(`main`)가 있어야 한다.
4. 저장소 이름을 적어 둔다. 형식은 `소유자/이름`이다.
5. 저장소 설정(Settings) > General > Pull Requests에서 **Allow merge commits**가 켜져 있는지 본다. 방이 병합 커밋 방식으로 병합한다.

## 2. 토큰 만들기 (GitHub 화면, 미확인)
1. GitHub의 Settings > Developer settings > Personal access tokens > **Fine-grained tokens**에서 새 토큰을 만든다.
2. **Repository access**: Only select repositories를 고르고 **1단계의 저장소 하나만** 고른다.
3. **Repository permissions**:
   - Administration: Read and write (협업자 초대·제거, 규칙 세트)
   - Contents: Read and write
   - Pull requests: Read and write
   - Metadata: Read-only (자동으로 켜진다)
4. **Expiration**: 90일 이하로 정한다. 만료되기 전에 새 토큰으로 바꾼다.
5. 만들어진 토큰은 한 번만 보인다. 다음 단계에서 환경 변수에 넣는다.

## 3. 방 서버를 GitHub 방식으로 켠다
새 PowerShell 창에서 환경 변수를 정한다. 토큰 값은 화면에 붙여 넣고 파일에 쓰지 않는다.
```powershell
$env:ROOM_GIT = "github"
$env:ROOM_GITHUB_REPO = "<소유자>/<이름>"
$env:ROOM_GITHUB_TOKEN = "<2단계의 토큰>"
$env:ROOM_DB = "$PWD\room.db"
$env:ROOM_PUBLIC_URL = "<팀원이 쓰는 방 주소>"
```
토큰을 새 창에서도 쓰려면 사용자 환경 변수로 저장한다. `[Environment]::SetEnvironmentVariable("ROOM_GITHUB_TOKEN", "<토큰>", "User")`

## 4. 저장소 점검과 규칙 세트 만들기
```powershell
.\.venv\Scripts\python -m beot server setup-git
```
이 명령은 다음을 한다.
1. 저장소가 공개인지, 토큰에 관리자 권한이 있는지, 기본 가지가 있는지, 병합 커밋이 허용인지, 규칙 세트를 읽을 수 있는지 점검한다.
2. 문제가 하나라도 있으면 이유를 출력하고 **아무것도 만들지 않는다.** 문제를 고치고 다시 실행한다.
3. 통과하면 규칙 세트 2개를 만든다(이미 있으면 갱신한다. 여러 번 실행해도 된다).
   - 기본 가지(`main`)는 PR로만 바뀐다. 강제 push와 삭제는 막는다.
   - `member/<이름>/…` 가지 밖의 가지는 만들기·바꾸기·삭제를 막는다.
   - 방장(저장소 관리자)은 PR 병합 때만 규칙을 우회한다.

## 5. 방 만들기와 팀원 초대
1. 방을 만든다: `.\.venv\Scripts\python -m beot server init --owner <방장 이름>`. 로그인 토큰이 한 번 출력된다.
2. 방 서버를 켠다(운영 한 장의 1장 9번).
3. 방장 화면에서 "팀원 추가"를 누른다. **이름**과 **팀원의 GitHub 사용자 이름**을 넣는다.
4. 나온 안내문(방 주소, 단어 코드, 단계)을 팀원에게 보낸다. 안내문 첫 단계가 GitHub 초대 수락이다.
5. 팀원이 GitHub에서 초대를 수락해야 push할 수 있다. 초대는 7일 뒤 만료된다. 만료되면 멤버 줄의 "코드 다시 받기"가 초대를 다시 보낸다.

## 6. 팀원 쪽 (안내문에 포함)
1. 받은 링크에서 GitHub 초대를 수락한다. 계정이 없으면 먼저 가입한다.
2. `join.py`를 실행한다. 공개 저장소를 로그인 없이 받는다.
3. 처음 push할 때 GitHub 로그인이 나온다(Windows는 자격 증명 관리자가 뜬다).
4. 50 MB 넘는 파일과 비밀 파일 이름은 push 전에 막힌다. 큰 파일은 구글 드라이브로 공유한다.

## 7. 문제가 생겼을 때
| 증상 | 확인할 것 |
|---|---|
| `setup-git`이 "비공개"라고 한다 | 저장소를 공개로 바꾼다 |
| "관리자 권한이 없다" | 토큰의 Administration 권한과 저장소 선택을 확인한다 |
| "기본 가지가 없다" | README를 넣어 `main`을 만든다 |
| "Allow merge commits" | 저장소 설정에서 켠다 |
| 팀원이 push에서 거부된다 | 초대를 수락했는지, 가지 이름이 `member/<방 이름>/…`인지 확인한다 |
| 승인이 "PR이 닫혀 있다"로 거부된다 | GitHub 화면에서 누가 PR을 닫았다. 팀원이 다시 제출한다 |
| "GitHub 속도 제한" | 잠시 뒤에 다시 시도한다 |
| 토큰이 만료됐다 | 새 토큰을 만들어 `ROOM_GITHUB_TOKEN`을 바꾸고 방 서버를 다시 켠다 |

## 8. 알려진 한계
- 팀원 A가 팀원 B의 `member/B/…` 가지를 바꾸거나 지울 수 있다(무료 개인 저장소는 사용자별 push 제한이 없다).
- 협업자 계정으로 실제 main push가 거부되는지는 방장 계정으로 대리 시험만 했다(G5에서 두 번째 계정으로 확인한다).
- 방 서버가 저장소 관리자 권한 토큰을 가진다. 방 서버 PC가 뚫리면 저장소가 넘어간다.
