# 벗 안내서: 팀원용

> **경고:** 단어 코드와 방 토큰은 채팅, 파일, 화면 공유에 남기지 않는다.
> **표시:** (미확인) = 이 PC 안에서만 시험했거나 시험하지 않은 부분이다.

## 0. 벗이 무엇인가
- 조마다 방장 PC 하나가 방(서버)이 된다.
- 팀원은 방에서 일을 맡고, 자기 가지에서 작업하고, 제출한다.
- 방장만 승인하고 합친다.

## 1. 준비물
1. Python 3와 git을 설치한다.
2. Claude 또는 Codex를 설치하고 로그인한다.
3. 방장에게서 네 가지를 받는다: **서버장 주소(도메인), 방 코드, 단어 코드, `join.py` 파일**.
4. GitHub 방식 방이면 본인 GitHub 계정이 필요하다. 방장에게 GitHub 사용자 이름을 알려 준다.

## 2. 처음 한 번: 방에 들어가기
1. PowerShell을 연다.
2. `join.py`가 있는 폴더로 이동한다.
3. 다음을 실행한다. `example.com`를 받은 서버장 주소로 바꾼다.
```powershell
python join.py --server example.com
```

벗 프로그램(`beot.exe`)을 받았다면 `join.py` 대신 같은 옵션으로 `beot join --server example.com`를 실행한다. 아래 `python join.py …` 명령도 모두 `beot join …`으로 바꿔 쓸 수 있다.

**Claude가 아닌 에이전트도 쓸 수 있다.** `--run 에이전트이름`을 붙이면 그 에이전트를 작업 폴더에서 연다(예: `--run codex`, `--run gemini`, `--run opencode`). 이름은 이 PC에 설치된 실행 파일 이름이다. Claude와 Codex가 아니면 시작 문장을 대신 넣지 않으므로, 열린 에이전트에 "작업 세션을 시작한다"라고 입력한다. 에이전트가 방 설정(`.mcp.json`, `AGENTS.md` 등)을 읽는지는 에이전트마다 다르다. 앱별 설정 파일은 `--apps`로 더 만든다.
4. **방 코드**를 먼저 묻는다. 입력한다(예: `amber-river-moss-123`). 방 코드는 비밀번호가 아니다.
5. 이어서 **초대 코드(단어 코드)**를 묻는다. 붙여 넣는다. 입력이 보이지 않는다. 24시간 안에 한 번만 쓸 수 있다.
6. **닉네임**을 묻는다. 엔터를 누르면 방장이 정한 이름을 쓴다. 다른 이름을 쓰려면 지금 입력한다(처음 한 번만 바꿀 수 있다).
7. **비밀번호**를 묻는다(8자 이상, 입력이 보이지 않는다). 엔터를 누르면 나중에 방 화면에서 정한다. 비밀번호는 방 서버에 암호화된 값으로만 남고 이 PC에는 저장하지 않는다.
8. 끝나면 작업 폴더가 생기고 **브라우저가 방 화면을 자동으로 연다(로그인도 자동).** 작업 폴더는 `C:\Users\<내 이름>\Beot\<프로젝트 이름>`이다(프로젝트 이름은 방장이 정한다. 마당에도 이 이름으로 보인다). 자동으로 열지 않으려면 `--no-browser`를 붙인다.
9. 방 화면을 다시 열 때는 브라우저로 `https://<서버장 주소>`를 열고 방 코드를 넣는다. 방 화면에서 **닉네임과 비밀번호**로 들어간다. 비밀번호가 없으면 PC에서 `python join.py --open`으로 연다(토큰 없이 들어간다). 화면 위의 배너에서 비밀번호를 정한다.
10. 비밀번호를 잃으면 방장에게 **재설정 코드**를 받는다. 로그인 화면의 "다른 방법으로 들어가기"에 닉네임, 코드, 새 비밀번호를 넣는다(코드는 24시간 안에 한 번만 쓴다).
- 비밀번호를 정하지 않으려면 `python join.py … --no-account`를 붙인다.
- 방 코드와 단어 코드를 미리 정해 두려면 환경 변수 `BEOT_ROOM_CODE`, `BEOT_INVITE`를 쓸 수 있다.
- 방장이 방 주소(`https://r-….도메인`)를 직접 알려 주면 `python join.py --room <방 주소>`도 된다.
- 한 번 들어온 PC는 기억한다. 다음부터 코드를 다시 받지 않는다.

GitHub 방식 방이면 먼저 GitHub 초대를 수락해야 한다. 방장의 안내문을 따른다. (`join`이 "초대를 수락한다"라고 안내해도 이미 수락했으면 무시한다.)

## 3. 일을 시작하기
1. 방 화면(방장이 알려 준 방 주소 뒤에 `/ui`)에서 내 일의 번호를 본다.
2. 다음을 실행한다. `<번호>`를 바꾼다.
```powershell
python join.py --start <번호>
```
3. 이 명령은 세 가지를 한다.
   - 규칙에 맞는 가지 이름을 만든다(`member/<내 이름>/…`).
   - 이 일 전용 작업 폴더를 만든다.
   - 방에서 이 일을 맡는다.
4. 출력된 **작업 폴더**로 이동한다.
5. 에이전트를 바로 열려면 `--run claude` 또는 `--run codex`를 붙인다.
```powershell
python join.py --start <번호> --run claude
```
6. 마당(Madang)이 켜져 있으면 마당 작업 폴더로 만든다. 꺼져 있으면 git으로 만든다.

## 4. 작업하고 제출하기
1. 작업 폴더에서 에이전트에게 일을 시킨다.
2. 에이전트가 파일을 고치고 push한다.
3. 에이전트가 `task_submit`으로 제출한다. 제출하면 PR이 생긴다.
4. 제출한 뒤 PR 링크를 받는다. Claude를 `--run`으로 열었으면 에이전트가 실행한다. 직접 하려면 다음을 실행한다.
```powershell
python join.py --link <번호>
```
5. 마당이 켜져 있으면 링크가 마당 작업 폴더에 붙는다.

## 5. 반려되면
1. 방 화면에서 반려 사유를 읽는다.
2. `python join.py --start <번호>`를 다시 실행한다. 같은 가지로 이어 간다.
3. 고치고 다시 제출한다.

## 5-1. 파일 탭 방 (사본 받기·완료 제출)
방장이 **로컬 보관** 방을 만들었으면 파일이 방장 PC의 원본에 있다. 같은 명령으로 사본을 받고 제출한다.
1. 일을 맡고 사본을 받는다. `<번호>`를 바꾼다.
```powershell
python join.py --start <번호>
```
2. 출력된 작업 폴더에서 파일을 고친다.
3. 끝나면 **완료**를 한다. `--summary`는 한 줄 설명이다.
```powershell
python join.py --finish <번호> --summary "무엇을 고쳤는지"
```
4. 방장이 검토한다. 승인되면 원본에 합쳐진다. 반려되면 사유를 읽고 `--start`를 다시 실행해 고친 뒤 다시 `--finish` 한다.
- 파일 하나는 50MB 이하여야 한다. 비밀 파일 이름(`.env`, 키 파일)은 올릴 때 경고한다.
- 올리는 곳은 `member/<내 이름>/…` 가지뿐이다. 원본 `main`에는 올릴 수 없다.
- **경고:** 사본은 이 PC에 남는다. 에이전트가 읽은 내용은 그 AI 서비스로 전송된다. 작업이 끝나면 사본 폴더를 지운다.
- 방장 PC가 꺼져 있으면 받기와 제출이 멈춘다.

### 검토자가 되면
방장이 [검토 권한]을 주면 화면에 "검토" 메뉴가 생긴다. 다른 사람의 제출물을 승인하거나 반려한다.
- 내가 제출한 일은 승인·반려할 수 없다. 방장이나 다른 검토자가 한다.
- 보호 파일(`CLAUDE.md`, `.claude/` 등)을 바꾼 일은 방장이 [보호 파일도 승인]을 줘야 승인한다. 없으면 반려만 한다.

## 6. 에이전트가 새 메시지를 받는 법
에이전트는 쉬고 있으면 새 메시지를 모른다. 아래 두 방법 중 하나를 쓴다. 둘 다 써도 된다.

> **경고**: 메시지에 비밀값(API 키, 비밀번호, 토큰)을 쓰지 않는다. 메시지는 방의 모든 사람이 볼 수 있다.

### 방법 1: 훅 (선택, 기본은 꺼져 있다)
훅은 에이전트가 세션을 시작하거나 질문을 받을 때마다 새 메시지를 모아 에이전트에게 알려 준다.

> **주의**: 훅은 에이전트가 실행하는 명령이다. 설치 전에 화면에 나온 내용을 읽는다. 모르는 명령이면 `n`을 입력한다.

1. 이미 `join`한 작업 폴더를 확인한다.
2. 다음을 실행한다. `<작업 폴더>`를 바꾼다.
```powershell
python join.py --hooks --dest <작업 폴더>
```
3. 화면에 나온 JSON을 읽는다.
4. 괜찮으면 `y`를 입력한다. 아니면 `n`을 입력한다. `n`이면 아무것도 바뀌지 않는다.
5. 에이전트를 새로 연다. 훅은 새 세션부터 적용된다.
6. 훅을 끄려면 다음을 실행한다. 벗이 넣은 훅만 지워진다.
```powershell
python join.py --remove-hooks --dest <작업 폴더>
```
- 훅은 Claude Code에서만 쓴다. 다른 앱(Codex, Gemini, Cursor, VS Code)에는 훅을 설치하지 않는다. 이 앱들은 방법 2를 쓴다.
- 훅은 `beot` 명령이 PATH에 있어야 한다. 없으면 설치 프로그램으로 먼저 깐다.
- 원래 설정 파일은 `.bak`로 남는다. 설정 파일: `.claude/settings.local.json`.

### 방법 2: `beot watch` 백그라운드 모니터
1. 작업 폴더에서 다음을 실행한다. 새 메시지가 오면 한 줄씩 출력한다.
```powershell
beot watch
```
2. 에이전트의 백그라운드 모니터 기능에 이 명령을 연결한다. 모니터가 출력을 읽고 쉬는 에이전트를 깨운다.
3. 한 번만 확인하려면 `beot watch --once`를 쓴다.

### 결정 요청 (`decide`)
- 에이전트는 `decide`에 스스로 답하지 않는다.
- 사람이 방 화면에서 선택지를 눌러 답한다.

## 7. 문제가 생겼을 때
| 증상 | 할 일 |
|---|---|
| "방을 찾지 못했다" | 방 코드 철자를 확인한다. 방장 PC가 꺼져 있거나 방이 닫혔을 수 있다. 방장에게 묻는다 |
| "서버장에 닿지 않는다" | 인터넷 연결과 서버장 주소(`https://`를 붙이지 않는다)를 확인한다 |
| "코드가 올바르지 않거나 만료됐다" | 단어 코드를 끝까지 입력했는지 본다. 24시간이 지났거나 이미 썼으면 방장에게 "코드 다시 받기"를 부탁한다 |
| "틀린 시도가 너무 많다", "입장이 잠시 닫혔다" | 10분 기다린다 |
| "방 서버에 닿지 않는다" | 방장 PC가 켜져 있는지 방장에게 묻는다 |
| push가 거부된다 | 가지 이름이 `member/<내 이름>/…`인지 본다. GitHub 방식이면 초대를 수락했는지 본다 |
| "먼저 승인돼야 하는 일이 있다" | 앞선 일이 승인될 때까지 기다린다 |
| 큰 파일이 안 올라간다 | 50 MB 넘는 파일은 막힌다. 구글 드라이브로 공유한다 |
| 작업 폴더가 이미 있다는 오류 | 그 폴더가 비어 있는지 본다. 내용이 있으면 방장에게 묻는다 |
| 403(오류 1010) | `join.py`가 최신인지 본다. 방장에게 새 `join.py`를 받는다 |
