# 운영 한 장 (서버 PC, 방장용)

> **경고 1:** `flow/`의 시험 스크립트는 `gitea/work`(저장소와 Gitea DB)를 지운다. 실제 프로젝트를 올린 PC에서는 실행하지 않는다. 스크립트는 `FLOW_WIPE_OK=1`을 직접 적지 않으면 중단된다(`flow/guard.sh`).
> **경고 2:** 토큰과 단어 코드는 채팅·파일·화면 공유에 남기지 않는다.
> **표시:** (확인) = 시험으로 확인한 형태. (미확인) = 형태는 맞지만 그대로 입력해 시험하지 않았다. 시험은 Git Bash 스크립트로 했고 아래 PowerShell 명령은 같은 환경 변수와 명령을 PowerShell 문법으로 옮긴 것이다.

> **GitHub 방식 방**(Gitea 대신 공개 GitHub 저장소를 쓰는 방)은 [방장_GitHub방식_준비.md](방장_GitHub방식_준비.md)를 따른다. 1장의 Gitea 단계(2~3, 5~6번)는 건너뛰고 그 문서의 3~4단계를 한다.

## 0. 용어
- **방 서버:** `server.py serve`. 일 목록, 규칙, 화면을 담당한다. 포트 8780.
- **Gitea:** 코드 저장소 서버. 포트 3000. 방 서버가 PR 생성·병합에 쓴다.
- **로그인 토큰:** 방장이 방 화면에 들어가는 값(서버장이 준 방장 열쇠 bh_…와 다르다). `xxxx-xxxx-xxxx-xxxx-xxxx` 꼴. 처음 한 번만 출력된다.
- **닉네임·비밀번호:** 방 화면 로그인의 기본 방법. 서버에는 해시만 있다. 잃으면 팀원은 방장의 재설정 코드, 방장은 `python server.py set-password <이름>`으로 바꾼다. 토큰은 비상용·에이전트용으로 그대로 쓴다.
- **봇 토큰:** 방 서버가 Gitea를 부를 때 쓰는 값. `setup-git`이 처음 한 번만 출력한다.

## 1. 처음 한 번 (방 만들기)
1. 설치한다 (README 1장). 폴더는 `Beot`이다.
2. Gitea의 LAN 주소를 정한다. `gitea\app.ini`에서 두 줄을 고친다. (확인)
   - `HTTP_ADDR = 0.0.0.0`
   - `ROOT_URL = http://<이 PC의 LAN 주소>:3000/`
3. Gitea를 켠다. 창을 닫지 않는다. (확인)
```powershell
.\gitea\gitea.exe web --config .\gitea\app.ini
```
4. 새 PowerShell 창을 연다. 환경 변수를 정한다. `<LAN 주소>`는 이 PC의 주소다. (확인: 같은 변수를 Git Bash에서 썼다)
```powershell
$env:ROOM_DB = "$PWD\room.db"
$env:ROOM_GITEA_URL = "http://127.0.0.1:3000"; $env:ROOM_GITEA_REPO = "roombot/project"
$env:ROOM_PUBLIC_URL = "http://<LAN 주소>:8780"; $env:ROOM_GIT_URL = "http://<LAN 주소>:3000"
$env:ROOM_BIND_IP = "1"
```
5. 봇 계정과 저장소를 만든다. **한 번만 실행한다.** 출력된 봇 토큰을 안전한 곳에 둔다. (확인)
```powershell
.\.venv\Scripts\python server.py setup-git
```
6. 봇 토큰을 사용자 환경 변수로 저장한다. 이후 새 창에서도 쓸 수 있다. (미확인)
```powershell
[Environment]::SetEnvironmentVariable("ROOM_GITEA_TOKEN", "<봇 토큰>", "User")
$env:ROOM_GITEA_TOKEN = "<봇 토큰>"
```
7. 방과 방장을 만든다. 출력된 로그인 토큰을 안전한 곳에 둔다. (확인)
```powershell
.\.venv\Scripts\python server.py init --owner alice
```
8. 방장의 접속 IP를 등록한다. 방장이 `127.0.0.1`과 LAN 주소를 둘 다 쓰기 때문이다. (확인)
```powershell
.\.venv\Scripts\python server.py set-ip alice 127.0.0.1,<LAN 주소>
```
9. 방 서버를 켠다. 창을 닫지 않는다. (확인)
```powershell
.\.venv\Scripts\python server.py serve --host 0.0.0.0 --port 8780
```
10. 브라우저에서 `http://<LAN 주소>:8780/ui`를 연다. 로그인 토큰으로 로그인한다. (확인)
11. 다른 PC가 접속하지 못하면 Windows 방화벽이 막은 것이다. 이 설정은 방장이 직접 한다. (미확인) README 3장의 `New-NetFirewallRule` 예시를 쓴다.

## 2. 평소에 켜기
1. Gitea를 켠다 (1장 3번).
2. 새 창에서 1장 4번의 환경 변수를 정한다. 봇 토큰은 1장 6번에서 저장했으면 이미 있다.
3. 방 서버를 켠다 (1장 9번). 데이터는 그대로 남는다. (확인: 서버만 다시 켜도 일·멤버가 유지됐다)

## 3. 끄기
1. 방 서버 창에서 `Ctrl+C`를 누른다.
2. Gitea 창에서 `Ctrl+C`를 누른다. 창이 없으면 다음을 실행한다. (미확인)
```powershell
Stop-Process -Name gitea
```

## 4. 팀원 초대
**화면에서 한다 (확인):** 방장 화면의 "멤버" 구역에서 "팀원 추가"를 누른다. 이름과 역할을 정하면 단어 코드와 안내문이 나온다.
- 코드 창을 닫으면 코드를 다시 볼 수 없다. 창에서 "안내문 복사"를 눌러 팀원에게 보낸다.
- 안내문에는 방 주소, 단어 코드, `join.py` 실행 방법이 있다. `join.py` 파일은 따로 전달한다.
- 코드를 잃었거나 `join`이 실패하면 멤버 줄의 "코드 다시 받기"를 누른다. 옛 방 토큰은 무효가 된다.
- 내보내려면 멤버 줄의 "내보내기"를 누른다. 내보낸 멤버는 "다시 초대"로 되돌린다.
- 보기 전용 멤버는 코드 대신 방 토큰을 받는다. 브라우저에서 방 토큰으로 들어온다.
- 화면에서 팀원을 추가하려면 서버에 `ROOM_PUBLIC_URL`과 `ROOM_GIT_URL`이 정해져 있어야 한다.
- DB와 백업에는 초대 정보가 암호문으로만 남는다(코드를 모르면 읽을 수 없다).

**명령줄로 한다:**
1. 팀원을 만들고 단어 코드를 받는다. (확인)
```powershell
.\.venv\Scripts\python server.py add-member bob --role member --word-only
```
2. 팀원에게 **단어 코드, 방 주소, `join.py` 파일** 세 가지를 전달한다. 코드는 24시간 안에 한 번만 쓸 수 있다.
3. 팀원이 `python join.py --room <방 주소> --run claude`를 실행한다 (README 2장).
4. 팀원이 접속하면 그 PC의 IP가 자동으로 묶인다. 화면의 멤버 목록에서 접속을 확인한다.

**코드를 잃었거나 `join`이 실패했을 때:** (확인)
```powershell
.\.venv\Scripts\python server.py reinvite bob
```
새 방 토큰과 새 단어 코드가 나온다. 옛 방 토큰은 무효가 된다.

**팀원의 PC가 바뀌었을 때(IP가 바뀜):** (확인: 규칙은 `test_room.py`, CLI 명령은 단독 시험하지 않았다)
```powershell
.\.venv\Scripts\python server.py set-ip bob ""      # 묶인 IP를 해제한다. 다음 접속 IP가 다시 묶인다
```

## 5. 일상 운영
| 하고 싶은 일 | 방법 |
|---|---|
| 일 만들기·배정 | 화면의 "새 일", 일의 "배정" |
| 일 순서 정하기 | 새 일의 "먼저 승인돼야 하는 일의 번호" |
| 승인·반려 | 화면의 "검토 대기". 반려는 사유가 필수다 |
| 보호 파일 경고 | 검토 항목에 주황색 경고("보호 대상 파일 변경")가 있으면 그 파일(`CLAUDE.md`, `.claude/` 등)의 내용을 Gitea에서 직접 읽는다. 문제없으면 "확인했고 승인"을 누른다. 확인 없이는 승인되지 않는다 |
| 긴급 공지 | 대화에서 "긴급" 체크 후 보내기 |
| 팀원 내보내기 | `server.py revoke bob`. 방 토큰이 즉시 무효가 되고 Gitea 쓰기 권한이 회수된다. 이미 clone된 사본은 회수되지 않는다 |
| 로그인 토큰 바꾸기 | `server.py rotate alice`. 새 토큰이 출력된다 |
| 백업 | `.\.venv\Scripts\python backup.py` (서버를 멈추지 않는다). zip에 비밀값이 있으므로 다른 곳에 두고 쓴 뒤 지운다 |

## 6. 문제가 생겼을 때
| 증상 | 확인할 것 |
|---|---|
| 팀원이 "방 서버에 닿지 않는다" | 같은 네트워크인지, 방 주소(`http://`로 시작), 방 서버가 켜져 있는지, 방화벽 |
| 팀원이 "코드가 올바르지 않거나 만료됐다" | 코드를 끝까지 입력했는지, 24시간이 지났는지, 이미 썼는지 → `reinvite` |
| 팀원이 "틀린 시도가 너무 많다" | 10분 기다린다. 같은 IP에서 5번 틀리면 막힌다 |
| 팀원이 화면에서 "토큰이 올바르지 않다" | 화면의 "접속 실패 기록"에서 사유를 본다. `ip_mismatch`는 다른 PC에서 접속한 것이다 → `set-ip`로 해제 |
| 방장 화면이 안 열린다 | 방장 IP 등록 여부(1장 8번). `127.0.0.1`과 LAN 주소 둘 다 등록한다 |
| 승인할 때 오류 | "제출 후 가지가 바뀌었다"면 팀원이 다시 제출해야 한다 |
| 반려했는데 PR 댓글이 없다 | 방장 에이전트에게 `events_since`로 `pr_comment_failed` 기록이 있는지 묻는다(화면에는 안 나온다). 반려 자체는 기록된다 |
| 서버가 이상하게 응답한다 | 포트 8780을 다른 프로그램이 쓰는지 본다 |

로그: 방 서버 창의 출력, Gitea 창의 출력(Gitea는 콘솔 모드라 로그 파일이 없다). 접속 실패는 화면의 "접속 실패 기록"에, 그 밖의 기록은 방장 에이전트의 `events_since`에서 본다.

## 7. 봇 토큰을 잃었을 때
`setup-git`은 두 번 실행할 수 없다(저장소가 이미 있어서 실패한다). 봇 토큰은 새로 만든다. (미확인: 명령 형태는 `setup-git`이 내부에서 쓰는 것과 같지만 단독으로는 시험하지 않았다)
```powershell
.\gitea\gitea.exe --config .\gitea\app.ini admin user generate-access-token --username roombot --token-name room-run-2 --scopes "write:repository,write:issue" --raw
```
출력된 값을 1장 6번처럼 `ROOM_GITEA_TOKEN`에 저장하고 방 서버를 다시 켠다.

## 7-2. 밖에서 접속하기(터널)
[터널_접속_설정.md](터널_접속_설정.md)를 따른다. 터널 모드(`ROOM_TUNNEL=1`)에서는 IP 묶기를 쓰지 않는다. **(미확인: 실제 터널로 시험하지 않았다)**

## 8. 알려진 한계
- 방과 Gitea는 이 PC가 켜져 있을 때만 쓸 수 있다.
- 이 PC의 LAN 주소가 바뀌면(DHCP) 방 주소가 바뀐다. 이미 `join`한 팀원의 설정(`.mcp.json`, git 원격 주소)이 모두 어긋난다. **고정 IP나 DHCP 예약을 먼저 정한다.** 주소가 바뀐 뒤의 복구 절차는 시험하지 않았다.
- LAN은 HTTP다. 신뢰하는 네트워크에서만 쓴다.
- 팀원 PC에 git-lfs가 없으면 큰 파일을 받지 못한다.
- 다른 PC에서 에이전트까지 실행하는 흐름은 이 PC 안에서만 확인했다.
