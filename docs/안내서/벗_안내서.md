# 벗 안내서

버전 1.2.2 · 2026-11-24

## 머리말

### 이 책은 누구를 위한 책인가
- 벗(Beot)을 설치하고 쓰는 모든 사람을 위한 책이다. 서버장, 리더, 팀원이 대상이다.
- 이 책 1권이 예전의 안내서 6개를 대체한다.

### 역할별 읽는 순서
| 내 역할 | 읽는 순서 |
|---|---|
| 서버장 | 1부 → 2부 → 5부 |
| 리더 | 1부 → 3부 → 5부. 서버장을 겸하면 2부도 읽는다 |
| 팀원 | 1부 → 4부 → 5부 |

- 앞의 부는 뒤의 부의 앞 지식이다. 역할을 모르면 1부 2장을 먼저 읽는다.
- 부록에 명령 표, 환경 변수 표, 용어 풀이가 있다.

### 표시 규칙
- 명령은 PowerShell에서 실행한다. 코드 블록 안의 글을 그대로 입력한다.
- `<…>`는 내 값으로 바꾼다. 예: `<프로젝트 코드>`.
- `example.com`은 예시 도메인이다. 내 도메인으로 바꾼다.
- **경고**와 **주의**는 해당 절차 앞에 있다. 먼저 읽는다.
- **(미확인)**은 형태는 맞지만 그대로 입력해 시험하지 않았다는 뜻이다.
- 화면 이름이 앱 화면과 다르면 앱 화면을 따른다.
- 토큰, 초대 코드, 비밀번호는 채팅, 파일, 화면 공유에 남기지 않는다. 이 책의 모든 부에 적용한다.

## 1부 공통

### 1장 벗이란 무엇인가

#### 1.1 한 줄 설명
- 조마다 리더 PC 하나가 프로젝트 서버가 된다. 프로젝트 서버는 일 목록, 규칙, 화면을 담당한다.
- 팀원은 프로젝트에서 일을 맡고, 자기 가지(`member/<이름>/…`)에서 작업하고, 제출한다.
- **리더만 승인하고 합친다.**
- 외부 접속은 **서버장**이 준비한 도메인을 쓴다. 이 도메인의 웹 화면이 **입구**(서버장의 접속 창구)다.

#### 1.2 구조
1. 서버장: 도메인과 Cloudflare 계정을 가진다. 입구(Worker)를 한 번 설치한다. 서버 PC는 없다.
2. 리더: 서버장에게 받은 리더 토큰으로 프로젝트를 만든다. 프로젝트 서버는 리더 PC에서 돈다.
3. 팀원: 서버장의 도메인에서 프로젝트 코드를 넣어 리더 PC의 프로젝트로 들어온다.

### 2장 세 역할과 준비물

#### 2.1 서버장
- 도메인과 Cloudflare 계정을 가진 사람이다. **서버 PC는 없다.**
- 한 번 설치하고, 리더에게 **리더 토큰**(`bh_…`)를 준다.
- 서버장마다 Cloudflare 계정이 따로다. 서버장 1의 리더 토큰은 서버장 2의 도메인에서 쓸 수 없다.
- **서버장은 신뢰 기준이다.** 서버장은 프로젝트 코드와 프로젝트 주소 목록을 볼 수 있다. 비밀번호(초대 코드)는 보지 못한다. 팀원은 아는 서버장의 도메인만 쓴다.

#### 2.2 리더
- 서버장에게 받은 리더 토큰으로 프로젝트를 만든다. 팀원을 초대하고, 일을 만들고, 승인한다.
- 리더는 Cloudflare를 다루지 않는다(서버장을 겸할 때만 다룬다).

#### 2.3 팀원
- 리더에게 안내문을 받아 프로젝트에 들어온다. 일을 맡고, 작업하고, 제출한다.

#### 2.4 서버장을 정하는 두 경로
- **첫 경로(추천):** 팀 밖의 1명(강사, 동아리 담당 등)이 서버장을 한 번 맡는다. 그 사람이 여러 팀의 리더에게 리더 토큰을 준다. 리더는 토큰만 받는다.
- **둘째 경로:** 리더가 서버장을 겸한다. 2부의 설치를 한 뒤 자기에게 리더 토큰을 만든다([7.1](#71-리더-초대)).

#### 2.5 역할별 준비물
| 역할 | 준비물 |
|---|---|
| 서버장 | 도메인 1개(Cloudflare에 추가, 상태 **Active**), Cloudflare 계정, Python 3와 벗 프로그램(벗 폴더), Cloudflare API 토큰(6장에서 만든다), `workers.dev` 주소(없으면 설치 명령에 `--workers-subdomain 이름`을 붙인다. Cron에 필요하다) |
| 리더 | Python 3, git, 벗 프로그램(벗 폴더), 입구 주소(도메인), 리더 토큰(`bh_…`). GitHub 방식이면 공개 저장소(README 파일 있음)와 그 저장소 하나에 쓰는 GitHub 토큰([11장](#11장-github-방식-준비)) |
| 팀원 | git. Claude 또는 Codex를 설치하고 로그인한 상태. 리더에게 받은 안내문(입구 주소, 프로젝트 코드, 초대 코드). GitHub 방식 프로젝트면 본인 GitHub 계정 |

- 벗 앱(`beot.exe`)만 쓰면 Python은 필요 없다. `join.py`나 `python -m beot …`을 쓸 때만 Python 3가 필요하다.
- 리더가 비공개로 둘 자료가 있으면 [9.3](#93-비공개가-필요하면)을 읽는다.

### 3장 앱 설치와 업데이트

#### 3.1 설치
1. **설치 파일**(`beot-setup-1.2.2.exe`)을 실행한다. 관리자 권한이 필요 없다. `내 폴더\AppData\Local\Programs\Beot`에 설치된다.
2. 설치 없이 쓰려면 압축 파일(`beot-1.2.2-windows.zip`)을 **폴더째** 푼다.
3. 설치 폴더나 압축 폴더에는 `beot.exe` 하나와 `app` 폴더가 있다. `beot.exe`만 따로 옮기지 않는다.
4. `beot.exe`를 더블클릭하면 앱 창이 열린다.
- 처음 실행하면 Windows가 "PC를 보호했습니다(알 수 없는 게시자)"라고 막을 수 있다. 코드 서명이 없기 때문이다. 출처가 확실하면 **추가 정보 → 실행**을 누른다.
- 릴리스에는 `join.py`(팀원용 한 파일, Python 3와 git 필요, exe를 쓰면 필요 없다)와 `SHA256SUMS.txt`(파일 확인값)도 있다.
- PowerShell에서는 `python -m beot start` 대신 `beot.exe start`처럼 같은 파일을 명령으로 쓴다.
- 콘솔에서 한글이 깨지면(PowerShell 5.1) 최신 `beot.exe`는 콘솔 출력을 UTF-8로 바꿔서 낸다. 그래도 깨지면 `chcp 65001`을 먼저 실행한다.

#### 3.2 프로필과 로그인
1. 앱을 처음 열면 **프로필**(닉네임, 비밀번호 8자 이상)을 만든다.
2. 다음부터는 앱을 켤 때 비밀번호만 넣는다. 프로필 파일에는 닉네임과 확인값만 남는다.
- 로그인 화면의 **로그인 유지**는 기본이 꺼짐이다. 켜면 이 PC에서 비밀번호 없이 들어간다. 비밀번호가 아니라 세션을 Windows 사용자 암호화로 저장한다. 같은 Windows 사용자 계정으로만 쓸 수 있다.
- **경고:** 공용 PC에서는 **로그인 유지**를 켜지 않는다. 이미 켰다면 홈 화면의 **로그아웃**을 누른다.

#### 3.3 앱 창 닫기와 종료
- 창 오른쪽 위 X는 창만 닫는다. 앱과 켜진 프로젝트는 계속 돈다. 시계 옆 알림 영역에 아이콘 하나가 남는다.
- 아이콘을 두 번 누르면 앱 창이 다시 열린다. 창을 닫아도 트레이가 Windows 알림을 보낸다([16.10](#1610-트레이-알림)).
- 아이콘을 우클릭하면 **앱 열기**, **프로젝트 끄기**, **종료**가 있다.
- **종료**를 누르면 켜진 프로젝트가 있을 때 "프로젝트도 끌까?" 상자가 나온다. **예**는 프로젝트도 끄고 끝낸다. **아니요**는 프로젝트를 켜 둔 채 앱만 끝낸다. **취소**는 아무것도 하지 않는다.
- 앱을 작업 관리자에서 강제로 끝내면 프로젝트 터널(`cloudflared.exe`)이 남을 수 있다. 남으면 설치가 거부된다. 작업 관리자에서 `cloudflared.exe`를 끝낸다.

#### 3.4 업데이트
**주의:** 1.1.7 앱이 1.1.8로 올릴 때는 한 번, 프로젝트와 무인 도우미(`beot agent`)가 다시 켜지지 않는다. 업데이트 뒤 손으로 다시 켠다. 1.1.8부터는 저절로 다시 켜진다.

1. 같은 곳에 설치 파일을 덮어 설치한다. 벗이 켜져 있어도 된다(1.1.8). 설치기가 이 설치 폴더의 벗만 끄고 설치한다.
2. 업데이트 전에 켜져 있던 프로젝트, 토큰 중계, 무인 도우미는 설치 뒤 다시 켜진다. 꺼져 있던 것은 켜지 않는다.
- 포터블 벗과 다른 폴더의 벗은 건드리지 않는다.

**1.2.2로 올리는 순서** (1.1.8 이후)
**주의:** 새 규칙(비밀번호 다시 넣기, 검토 관문)은 프로젝트 서버가 지킨다. 리더 PC를 먼저 올린다.

1. **리더 PC를 먼저 올린다.** 프로젝트 서버를 켠 PC다.
2. 올린 뒤 프로젝트 서버와 리더 에이전트를 다시 켠다.
3. 열려 있던 프로젝트 화면은 **새로 고침**한다. 옛 화면은 비밀번호 칸이 없어서 승인 · 반려가 거부된다.
4. **팀원 PC도 올린다.** 바뀐 연결 안내 글(Codex 앱 · CLI)을 팀원 PC의 앱이 작업 폴더에 쓴다. 트레이 알림도 팀원 PC를 올려야 받는다. 앱을 켜면 손대지 않은 옛 글이 새 글로 바뀐다. 1.1.16부터는 벗이 켜질 때 작업 폴더의 옛 지시문(`CLAUDE.md` 등)과 `/벗` 명령 파일을 새 문구로 바꾼다. 옛 버전의 지시문과 글자가 정확히 같은 파일만 바꾸고, 사용자가 고친 파일은 그대로 둔다. 무인 도우미를 쓰는 팀원 PC도 올려야 한도 알림 글이 채팅에 올라가지 않는다(1.1.15).
5. 서버장이 꼭 할 일은 없다. 입구의 로그인 실패 글("로그인 실패가 너무 많다. 10분 뒤에 다시 시도한다")은 서버장이 입구를 다시 배포해야 바뀐다([7.4](#74-입구-업데이트와-새-버전-알리기)).
6. 이전 버전에서 안내봇(안내 창)을 켜 둔 PC는 그 창을 닫는다. `%LOCALAPPDATA%\Beot\guide` 폴더는 지워도 된다(1.1.15).
7. 1.2.0의 **봇 TF는 기본 꺼짐**이다. 켜기 전에는 기존 동작이 바뀌지 않는다. 1.1.16에서 `chain_max=100`으로 한도를 우회한 프로젝트는 1.2.0에서도 그 값이 남는다. 기본값만 0(해제)으로 바뀐다.
8. **무인 도우미를 쓰는 PC는 1.2.2로 올린 뒤 도우미를 다시 켠다.** 1.2.0 이하에서는 도우미가 쓰는 Claude의 쓰기가 작업 폴더 밖에도 닿을 수 있었다. 새 쓰기 범위(작업 폴더 안)는 다시 켠 도우미부터 적용된다.
- 포터블 벗은 트레이 **[완전 종료]**를 누른 뒤 새 zip을 덮어 푼다. `data` 폴더는 지우지 않는다.

**앱 자동 업데이트**
- 앱은 켠 뒤 2분, 그 뒤 30분마다 GitHub의 새 릴리스를 확인한다.
- 새 버전이 있으면 설치 파일을 받고 확인값을 확인한 뒤 **묻지 않고** 설치한다. 설정에서 끌 수 있다. 앱 위의 **지금 업데이트**로 바로 올릴 수도 있다.
- 같은 버전의 설치가 실패하면 자동으로 다시 하지 않는다.
- 1.1.13부터 설치 도우미는 설치를 끝낸 뒤 멈추지 않는다. 설치 파일만 기다리고, 10분 넘게 멈추면 그만두고 앱을 다시 연다.
- 포터블 벗은 자동 업데이트를 하지 않는다. 새 버전 알림과 릴리스 페이지 링크만 보인다.
- 한계: 확인값은 같은 릴리스의 `SHA256SUMS.txt`와 비교한다. 코드 서명은 없다.
- 팀원은 각자 PC의 앱에서 업데이트한다.
- 자동 업데이트는 입구(Worker)를 바꾸지 않는다. 서버장이 [입구 업데이트](#74-입구-업데이트와-새-버전-알리기)를 따로 한다.

**1.1.5 이하를 쓰는 팀이 1.1.6으로 올리는 순서**
1. **리더 PC를 먼저 올린다.** 올리기 전에 `beot backup`으로 프로젝트를 백업한다.
2. 그다음 팀원 PC를 올린다. 설치 파일이 켜 둔 무인 도우미를 먼저 끈다.
3. 올린 뒤 무인 도우미(`beot agent`)를 다시 켠다.
4. **자동 분배가 켜진다.** 끄지 않은 기존 프로젝트도 켜진다. 원하지 않으면 프로젝트 화면의 스위치로 끈다.
5. `beot start`의 옛 `--project`(팀원 폴더 이름)는 `--folder-name`으로 바뀌었다. 새 `--project`는 `--room`과 같은 뜻(프로젝트 고르기)이다. `beot start --project …`를 쓰던 사람은 `--folder-name`으로 바꾼다.
6. 1.1.4 이하에서 올리면 토큰 중계도 적용된다. 처음 켤 때 작업 폴더의 에이전트 연결 파일이 저절로 옮겨진다([19.2](#192-토큰-중계-115)).

#### 3.5 바뀐 것
- 1.1.9 ~ 1.2.2의 바뀐 점은 아래에 있다. 버전마다 릴리스 노트(`릴리스노트_<버전>.md`)가 있다. 새 버전이 위에 있다.

**1.2.2에서 바뀐 것** (1.2.0 이후)
- **보안 수정:** 무인 도우미가 쓰는 Claude의 쓰기(Edit · Write)를 작업 폴더 안으로 한정했다. 작업 폴더 안이어도 `.git` · `.claude` · `.codex` · `.agents` · `.mcp.json`은 쓰지 못한다. 1.2.0 이하에서는 도우미가 작업 폴더 밖에도 쓸 수 있었다. 무인 도우미를 쓰는 PC는 이 버전으로 올린 뒤 도우미를 다시 켠다.
- **API 키 모드(Claude 무인 도우미):** 설정에 "에이전트 API 키 (이 PC)" 카드가 생겼다. 키는 이 PC의 Windows 사용자만 풀 수 있는 방식(DPAPI)으로 저장하고 프로젝트 서버로 보내지 않는다. 월 예산 · 실행 1번 상한 · 청구일을 정한다. 예산에 닿으면 무인 도우미가 멈추고 구독으로 자동 전환하지 않는다. 금액은 이 PC에서 벗이 센 추정값이다. 환경 변수로 키를 주는 방법도 그대로 된다. Claude만 된다([23.3](#233-무인-도우미)).
- **봇 TF(기본 꺼짐):** 봇 도구 목록을 읽는 방식을 고쳤다. 연결할 때 "옛 도구가 남았을 수 있다" 경고가 더는 뜨지 않는다. 봇 TF 문제 알림이 생겼다([16.9](#169-orca-봇-연결-1115)).
- **프로젝트 삭제:** Windows에서 프로젝트 삭제가 실패하던 결함을 고쳤다. 읽기 전용 git 파일 때문에 `PermissionError`가 났다.

**1.2.0에서 바뀐 것** (1.1.16 이후)
- **봇 TF(기본 꺼짐):** Orca 봇이 리더 일을 TF(임무 묶음) 단위로 한다. 리더 TF는 3개다: 학습 PC · 접수(조율) · 검토 의견 모드. 앱에서 켤 때 확인 상자가 뜬다([16.9](#169-orca-봇-연결-1115)).
- **접수 TF의 사전 검사:** 새 결정 요청 · 질문 · 제출이 없으면 모델을 부르지 않는다.
- **검토 의견 모드:** 서버 설정 `review_mode`는 리더 에이전트가 Orca일 때만 적용된다.
- **허용 규칙 문서(`doc_read`):** 읽을 수 있는 경로를 늘릴 수 있다.
- **`orca_connect` 고침:** 같은 이름의 다른 폴더 도구를 덮어쓰던 결함을 고쳤다.
- **글 한도:** 연쇄 한도(`chain_max`)는 기본 해제(0)다. 리더가 2~100으로 다시 켤 수 있고 앱 화면에 편집칸이 있다. 리더 에이전트의 글은 연쇄 한도와 24시간 한도를 받지 않는다. 폭주 정지는 그대로다.
- **Discord 알림 제거:** 알림 코드와 웹훅 설정을 지웠다. `ROOM_WEBHOOK_URL`은 경고만 하고 무시한다.
- **화면:** 앱 화면의 체크박스가 커지던 것을 15px로 고쳤다.
- **안내서:** 팀원편에 "구독 크레딧으로 무인 도우미 쓰기" 절을 더했다([23.3](#233-무인-도우미)).
- **빌드:** 런처 exe가 런처 소스 · 잠금 파일 · 아이콘보다 오래되면 빌드를 거부한다.

**1.1.16에서 바뀐 것** (1.1.15 이후)
- **외부 연결(`beot.view/1`):** 리더가 이 PC의 외부 프로그램을 연결로 등록하면, 프로젝트의 모든 멤버가 레일의 **외부 연결**에서 그 프로그램의 상태를 본다. 보기만 한다. 등록은 `beot start --room <프로젝트> --connect <연결 이름>`이다([16.11](#1611-외부-연결-1116)).
- **용어 정리:** 화면, 프로젝트 서버의 글, 명령줄 도움말, 안내서의 낱말을 한 용어표로 맞췄다. 주요 변경은 판 → 버전, 열쇠 · 키 → 토큰, 토큰 대리 → 토큰 중계, 대리 열쇠 → 중계 토큰, 단어 코드 → 초대 코드, 서버(서버장의 접속 창구) → 입구, 리더 PC에서 도는 서버 → 프로젝트 서버, 리더 도우미 → 리더 에이전트, 팀원 PC의 단독 "도우미" → 무인 도우미, 사건 → 기록 · 새 소식, "틀린 시도" → 로그인 실패 등 상황별 문구, 업무 대시보드 → 프로젝트 대시보드다. 리더 토큰을 만드는 화면 단추의 이름은 **리더 토큰 만들기**다. 문체는 평서형("~한다")으로 맞췄다.
- **초대 안내문은 옛 형식도 받는다:** 안내문을 붙여 넣을 때 새 형식(`입구 주소:` · `초대 코드:`)과 옛 형식(`서버 주소:` · `서버장 주소:` · `단어 코드:`)을 모두 읽는다. 1.1.15 이전에 받은 안내문도 그대로 쓴다([12.1](#121-팀원-초대)).
- **지시문 자동 갱신:** 팀원 PC의 벗이 켜질 때 작업 폴더의 옛 지시문(`CLAUDE.md` 등)과 `/벗` 명령 파일을 새 문구로 바꾼다. 옛 버전의 지시문과 글자가 정확히 같은 파일만 바꾸고, 사용자가 고친 파일은 그대로 둔다.
- **채널 이름은 20자까지:** 채널 만들기와 Orca 봇의 학습 PC 배정(채널 입력)이 같은 규칙을 쓴다. 한글 · 영문 · 숫자 · `-` · `_`로 1~20자다. 이전에는 학습 PC 배정만 24자까지 받았다.
- **무인 도우미 글의 머리:** 무인 도우미가 쓴 글의 머리 `[무인 도우미]`는 배지로 보인다.
- **입구의 로그인 실패 글:** "로그인 실패가 너무 많다. 10분 뒤에 다시 시도한다"로 바뀌었다. 서버장이 입구를 다시 배포해야 바뀐다([7.4](#74-입구-업데이트와-새-버전-알리기)).
- **안내서 이름:** 별도 안내서 파일 `안내서_방장.md`는 `안내서_리더.md`로, `방장_GitHub방식_준비.md`는 `리더_GitHub방식_준비.md`로 이름이 바뀌었다. 옛 이름으로 건 링크는 새 이름으로 고친다.

**1.1.15에서 바뀐 것** (1.1.14 이후)
- **Orca 봇 연결:** 설정에서 **Orca 봇 연결**을 누르면 고른 Orca 봇이 프로젝트의 일 · 채팅 도구를 쓴다. 들어온 프로젝트와 리더 에이전트 둘 다 된다. 봇에는 프로젝트 토큰이 아니라 중계 토큰(토큰 중계가 내주는 이 PC 전용 토큰)만 넘긴다. **봇 역할 고르기**와 **봇 지시문 복사**가 있다. Node.js(npx)가 필요하다([16.9](#169-orca-봇-연결-1115)).
- **리더 에이전트는 무인 도우미와 Orca 봇 중 하나만:** 프로젝트 설정에서 고른다. 서버가 고르지 않은 쪽의 검토를 거부한다. Orca 봇 모드에서는 봇이 1차 통과와 에이전트 최종 검토도 한다. 모델 · 노력을 확인할 수 없어서 "약한 검토"로 표시된다. 최종 검토는 사람의 [에이전트 최종 검토]와 비밀번호 허가가 그대로 필요하다([13.5](#135-에이전트-최종-검토)).
- **안내 창(안내봇) 제거:** 프로젝트 화면의 안내 창, 설정의 안내봇 카드, `beot guide` 명령, 안내봇 질문의 하루 한도 설정이 없어졌다.
- **무인 도우미 한도 알림:** 무인 도우미가 하루 실행 한도에 도달해도 프로젝트 채팅에 글을 올리지 않는다. 무인 도우미 카드의 "한도" 상태와 기록(로그)에만 남는다([23.3](#233-무인-도우미)).
- **그 밖:** 전체 일의 흐름 · 칸반 · 타임라인 보기가 화면 폭을 다 쓴다. 무인 도우미가 `claude` · `git`을 띄울 때 콘솔 창이 뜨지 않는다.

**1.1.14에서 바뀐 것** (1.1.13 이후)
- **원격 저장소(`origin`)가 없는 리더 폴더:** 1.1.13에서는 이런 폴더에서 리더 에이전트가 1차 통과를 주지 못했다. 이제 프로젝트 서버가 리더 에이전트에게만 제출 가지를 받을 곳을 알려 준다(로컬 방식은 같은 PC의 원본 저장소, GitHub 방식은 저장소 주소). 리더 에이전트는 리더 폴더를 건드리지 않고 임시 저장소에 제출 커밋만 받아 1차 검토와 에이전트 최종 검토를 한다. 끝나면 임시 저장소를 지운다. 1차 · 최종 검토는 제한 실행만 한다([13.5](#135-에이전트-최종-검토)).
- 한계: GitHub 비공개 저장소를 쓰는 프로젝트에서 리더 폴더에 원격 저장소가 없으면 제출을 받지 못해 사람이 검토한다.

**1.1.13에서 바뀐 것** (1.1.12 이후)

- **한계(1.1.7 → 1.1.8 한 번):** 1.1.7 앱이 1.1.8로 올릴 때는 옛 앱 코드가 묻고 프로젝트를 끈다. 그 한 번은 프로젝트와 무인 도우미가 다시 켜지지 않는다. 올린 뒤 프로젝트를 켜고 무인 도우미를 다시 켠다.
- **안내봇 ③:** 팀원의 질문마다 `claude -p`로 답하는 흐름(`beot guide serve --accept-terms`)이다. 하루 질문 한도 200개, 질문당 예산 상한이 있다. 연결은 아직 막혀 있다. (1.1.15에서 제거)
- **전체 일 "흐름" 보기:** 트리 탭이 흐름 보기로 바뀌었다. 일을 단계 열에 놓고, 고른 일의 앞뒤 사슬에만 화살표를 그린다. **[선 모두 보기]**로 전체 선을 본다.
- **병목 일 임시 재배정:** 담당 무인 도우미가 3시간 넘게 멈췄고 뒤에 기다리는 일이 있으면 병목으로 알린다. 리더가 일 상세의 **[임시 담당]**으로 다른 팀원에게 빌려주고 **[돌려주기]**로 되돌린다. 원래 담당의 무인 도우미가 돌아오면 시작 전 일은 저절로 돌아온다.
- **검토 관문:** 1차 검토 모델 · 노력 수준을 고정한다(기본 Sonnet 5.5 medium). Codex 리더도 1차 검토를 하지만 "모델 고정 안 됨"으로 표시한다. 검사가 실패한 제출은 1차 통과를 받지 못하고, 승인하려면 사유를 적는다. 리더 에이전트는 리더 본인 제출 · 계획 변경 제안 · 보호 경로 제출도 1차 검토한다(1.1.13부터). 1차 통과는 사람의 승인을 대신하지 않는다. 보호 경로 제출은 승인하는 사람이 내용을 직접 확인하고, 계획 변경은 리더가 승인한다. 승인자 · 시각 · 1차 검토 · 검사 결과를 일 상세에 보여 준다.
- **Codex 리더 1차 검토:** Codex 리더 에이전트 프로젝트도 1차 검토를 한다. 모델 · 노력을 고정하지 못해 승인 줄에 "Codex · 모델 고정 안 됨"으로 표시한다(약한 검토).
- **안내봇 기록 파일:** 질문별 기록 파일(`<번호>.log`)은 `serve`를 켤 때 5MB가 넘으면 돌린다. (안내봇은 1.1.15에서 제거)
- **첫 화면 대시보드:** 지표 5칸(진척률 · 완료 · 진행 중 · 승인 대기 · 지연), 팀원별 카드, 지금 볼 일, 최근 완료를 한 화면에 모았다. [주간] · [일간]으로 기간을 바꾼다.
- **태블릿에서 보기:** 폭 1100px 이하와 손가락 기기에서 단추를 터치 크기로 키운다. PC 화면의 **[태블릿으로 열기]** QR(주소만, 로그인 정보 없음)로 연다. 이 PC 안에서만 열린 프로젝트는 공개 터널 주소로 켜야 QR이 나온다. 로그인 화면에 "비밀번호를 아직 정하지 않았으면 PC 앱 설정에서 정한다" 안내가 있다.

**1.1.7에서 바뀐 것** (1.1.6 이후)
- **안내 챗봇:** 안내 봇이 프로젝트 화면에서 묻는 말에 답한다. 연결 기능(`beot guide link`)은 **리더가 연결하고 `beot guide serve` 창을 켜 둬야** 쓸 수 있다. 봇은 리더 작업 폴더를 읽기만 하고, 비밀 경로는 읽지 않는다. (1.1.15에서 제거)
- **전체 일 트리:** 일 사이의 연결선을 그린다. 가지를 접고 펼 수 있다. 후행 일의 진행률을 보여 준다. 선행이 끝나기를 기다리는 일에 대기 배지를 붙인다.
- **리더 비밀번호 창:** 프로젝트를 지웠다가 같은 이름으로 다시 만들면 로그인이 `pw_unset`으로 막히던 결함을 고쳤다. 프로젝트를 지우면 리더 비밀번호 확인 기억과 리더 세션도 잊는다.
- **업데이트 확인:** 확인 주기를 6시간에서 30분으로 줄였다. 공개 직후 새 버전을 몰랐다.
- **리더 에이전트 연결 단추:** 설정을 연 뒤 켜면 눌러도 답이 없던 결함을 고쳤다. 꺼짐 상태가 단추를 막지 않는다.
- **토큰 거부(401):** 토큰이 거부되면 "프로젝트 서버에 연결하지 못했다" 대신 토큰 문제임을 알리는 문구를 보여 준다.

**1.1.6에서 바뀐 것** (1.1.5 이후)
- **이름 바꾸기:** 옛 이름 방 → 프로젝트, 옛 이름 방장 → 리더, 옛 이름 방 코드 → 프로젝트 코드. 명령에 `--project` 옵션을 넣었다. `--room`도 계속 받는다.
- **도움말 모드:** 설정·프로젝트 화면의 **[도움말]**을 누르면 켜진다(46항목). 항목을 누르면 기능, 쓰는 때, 명령어, 안내서 절을 보여 준다([16.8](#168-도움말-모드)).
- **파일 탭:** 같은 이름의 파일은 경로를 같이 보여 준다. 폴더를 지울 수 있다. 지운 뒤 다시 읽기에 실패하면 이유를 보여 준다.
- **그 밖:** 자동 분배를 기본으로 켠다. `beot take --help`를 넣었다. 리더 비밀번호 복구 명령에 `ROOM_DB` 경로를 붙였다([10.4](#104-프로젝트-화면-열기와-로그인)).

**1.1.5에서 바뀐 것** (1.1.4 이후)
- **토큰 중계:** 에이전트 설정 파일에 프로젝트 토큰을 두지 않는다. 토큰은 이 PC의 토큰 저장소(Windows 사용자 암호화)에만 있다.
- **파일 탭:** 삭제 결함을 고쳤다. 계획 문서에 반영된 이유를 보여 준다. 문서함, 업로드·다운로드 진행 표시, 드래그 앤 드롭을 넣었다.
- **리더 에이전트와 여러 PC:** 리더 에이전트가 계획서 초안을 쓰고 사람이 1번 승인한다. 담당이 없는 일을 자동으로 나눈다. 멤버 목록에 접속 표시가 있다. `room_brief`와 에이전트끼리 묻고 답하기를 넣었다. 1차 검토를 통과한 일만 사람이 승인한다. 여러 PC에서는 기기별 토큰, 일마다 PC 1대, 다른 PC로 넘기기를 쓴다.
- **첫 화면:** 내 차례 막대, 주간·일간 프로젝트 대시보드, 기록 화면.
- **앱 세션 연결:** `/벗`, `watch --app`. 구독 한도와 절전 안내, 계획 완료 기준 경고, 제출 보고 4칸. Antigravity 무인 실행.
- **안정화:** 설치 전에 무인 도우미를 끈다. 설치 실패를 기록한다. cloudflared 확인값을 확인한다. 터널 로그를 회전한다. `app.log`, 기록 열기, 화면 오류의 이유 표시.

### 이 부의 요약
- 벗은 조마다 리더 PC 하나가 프로젝트 서버가 되고, 리더만 승인하고 합치는 협업 도구다.
- 역할은 서버장(도메인과 Cloudflare, 서버 PC 없음), 리더(프로젝트 서버 PC), 팀원이다.
- 서버장은 팀 밖의 1명이 맡는 경로를 추천한다. 리더가 겸할 수도 있다.
- 설치 파일을 실행하고, 앱에서 프로필(닉네임, 비밀번호 8자 이상)을 만든다.
- 창 X는 앱을 끝내지 않는다. 트레이 아이콘의 **종료**로 끝낸다.
- 업데이트는 덮어 설치하거나 앱의 **지금 업데이트**를 쓴다. 리더 PC를 먼저 올린다.
- 공용 PC에서는 **로그인 유지**를 켜지 않는다.

## 2부 서버장

> **경고 1:** Cloudflare API 토큰과 서버장 관리 토큰은 채팅, 파일, 화면 공유에 남기지 않는다.
>
> **경고 2:** 서버장은 신뢰 기준이다. 팀원은 아는 서버장의 도메인만 쓴다.
>
> 이 부의 명령은 `example.com`으로 시험했다.

### 4장 서버장이 하는 일

#### 4.1 역할
1. 도메인과 Cloudflare 계정을 준비한다.
2. 입구(Worker)를 한 번 설치한다. 설치는 앱 창([5장](#5장-앱-창에서-입구-설치)) 또는 명령([6장](#6장-명령으로-입구-설치))으로 한다.
3. 리더에게 **리더 토큰**를 준다([7.1](#71-리더-초대)).
4. 프로젝트 서버는 각 리더의 PC에서 돈다. 서버장은 서버 PC를 두지 않는다.

#### 4.2 서버장이 직접 하는 일
앱 창으로 설치하면 서버장이 직접 하는 일은 3가지뿐이다.
1. Cloudflare 계정과 도메인(상태 Active)을 준비한다.
2. Cloudflare에서 토큰을 복사한다.
3. Bot Fight Mode를 끈다([6.2](#62-cloudflare-화면-설정)).

나머지는 앱 창에서 끝난다.

### 5장 앱 창에서 입구 설치

권장 방법이다. 앱(`beot.exe`)은 [3장](#3장-앱-설치와-업데이트)에서 설치한다.

#### 5.1 설치 절차
1. 앱에서 프로필(닉네임, 비밀번호 8자 이상)을 만든다([3.2](#32-프로필과-로그인)).
2. 선택 화면에서 **입구 열기** 카드의 **입구 열기**를 누른다. 입구(서버장의 접속 창구)는 리더와 팀원이 `https://도메인`으로 들어오는 곳이다.
3. **토큰 만들기**를 누른다. Cloudflare가 열린다. 권한이 미리 골라져 있다. 계속 → 토큰 만들기 → 값을 복사한다.
4. 앱의 토큰 칸에 붙여 넣고 **확인**을 누른다. 토큰은 파일에 저장하지 않는다.
5. 도메인 목록에서 도메인을 고른다. 권한 4개를 자동으로 검사한다. 없는 권한이 있으면 ✗로 보인다. 그 권한을 더한 새 토큰으로 3번부터 다시 한다.
6. workers.dev 이름 칸이 나오면 이름을 넣는다.
7. **설치**를 누른다. 단계별로 진행이 보인다. 실패하면 이유가 보인다. 고친 뒤 다시 눌러도 안전하다.
8. 서버장 계정(닉네임, 비밀번호)을 만든다. 닉네임에 프로필 닉네임이 미리 들어 있다. 비밀번호 칸을 비우면 프로필 비밀번호를 쓴다(계정과 같은 비밀번호가 된다). 만들면 바로 로그인된다.
9. 서버장 계정은 리더 권한도 가진다. 프로젝트도 직접 만든다.

#### 5.2 리더에게 토큰 전달
1. 홈 화면의 **리더 관리**를 연다.
2. 리더 이름과 프로젝트 수를 넣고 **리더 토큰 만들기**를 누른다. 리더 토큰이 한 번만 보인다.
3. **복사**해서 리더에게 전달한다. 입구 주소(도메인)도 같이 알려 준다.
4. 리더는 앱의 **기존 입구로 들어가기** 카드에서 입구 주소를 넣고 **입구 주소로 계정 로그인**을 누른다.
5. 이어서 **처음이면 · 계정 만들기**에 이 토큰을 넣는다. 비밀번호 칸을 비우면 프로필 비밀번호를 쓴다.

#### 5.3 서버장 비밀번호를 잃었을 때
- 로그인 화면의 **서버장 비밀번호를 잃었다**를 쓴다(서버장 PC에서만 된다).
- 또는 이 PC에서 `python beot_main.py owner reset-admin-password`를 실행하고 새 비밀번호를 두 번 넣는다.

### 6장 명령으로 입구 설치

앱 창 대신 명령으로 설치할 때 쓴다. 명령은 벗 폴더에서 실행한다.

#### 6.1 Cloudflare API 토큰 만들기
1. Cloudflare 대시보드 > My Profile > API Tokens > Create Token > Custom token을 연다.
2. 권한은 아래를 기준으로 한다. 화면 이름이 다르면 화면을 따른다.

| 줄 | 항목 | 수준 |
|---|---|---|
| Account | Workers Scripts | Edit |
| Account | Cloudflare Tunnel | Edit |
| Zone | DNS | Edit |
| Zone | Workers Routes | Edit |

3. Account Resources는 내 계정으로 정한다. Zone Resources는 **Specific zone > 내 도메인**으로 정한다.
4. 만료일을 짧게 정한다(예: 7일). 설치가 끝나면 삭제해도 된다.
   - **경고:** 토큰은 Worker 비밀값으로 올라가서 프로젝트 만들기에 계속 쓰인다. **삭제하면 새 프로젝트를 만들 수 없다.**
   - 오래 쓰려면 만료 전에 새 토큰으로 `setup`을 다시 실행한다.
5. 토큰 값을 환경 변수에 저장한다. 입력은 화면에 보이지 않는다.
```powershell
$t = Read-Host "Cloudflare API 토큰" -AsSecureString; [Environment]::SetEnvironmentVariable("CLOUDFLARE_API_TOKEN", [Runtime.InteropServices.Marshal]::PtrToStringAuto([Runtime.InteropServices.Marshal]::SecureStringToBSTR($t)), "User")
```
- 환경 변수가 없으면 설치 명령이 숨김 입력으로 묻는다. 이 프로그램은 토큰을 파일에 저장하지 않는다.

#### 6.2 Cloudflare 화면 설정
- **Bot Fight Mode: 끈다**(추천). 벗의 접속자는 브라우저가 아니라 프로그램(`join`, 에이전트)이라 도전 과제를 풀 수 없다. 켜 두면 막힐 수 있다.
- **공격 모드(Under Attack Mode): 켜지 않는다.** 모든 접속자에게 도전 과제를 내서 `join`과 에이전트가 막힌다.
- Access(이메일 인증)는 쓰지 않는다. 팀원이 이메일 등록 없이 코드만으로 들어와야 하기 때문이다.

#### 6.3 설치 명령
```powershell
python beot_main.py owner --domain example.com setup
```
- `workers.dev` 주소가 없다는 안내가 나오면 `--workers-subdomain 이름`을 붙여 다시 실행한다.
- 이 명령이 하는 일:
  1. 토큰을 검증한다.
  2. 도메인이 Active인지 확인한다.
  3. **서버장 관리 토큰**을 만든다(이 PC 사용자 환경 변수 `BEOT_ADMIN_TOKEN_<도메인>`).
  4. Worker를 올린다.
  5. 매일 03:17(UTC)에 만료를 점검하는 Cron을 설정한다.
  6. 입구 주소와 경로를 만든다.
  7. 입구 응답을 확인한다.
- 끝나면 `https://<도메인>/`에 "프로젝트 코드를 입력한다" 화면이 나온다.
- 다시 실행하면 갱신한다. 프로젝트 만료 기간을 바꾸려면 `--expire-days 7`처럼 붙인다(기본 14일).
- 새 주소가 퍼지는 데 몇 분이 걸릴 수 있다. 응답이 없다고 나오면 잠시 뒤 다시 확인한다.
- Cron은 설정 뒤 첫 실행까지 약 8분이 걸렸다.

### 7장 입구 운영

#### 7.1 리더 초대
```powershell
python beot_main.py owner invite kim --max 2
```
- 리더 이름은 영문자, 숫자, `-`, `_` 32자까지다.
- `--max`는 그 리더가 **동시에** 열 수 있는 프로젝트 수다(기본 2, 최대 20).
- 화면에 **리더 토큰**(`bh_…`)가 한 번만 나온다. 리더에게 안전하게 전달한다. 다시 볼 수 없다.
- 리더에게 입구 주소(도메인)도 알려 준다. 리더는 `https://<도메인>`의 **리더** 탭에서 프로젝트를 만든다. 리더는 [3부](#3부-리더)를 따른다.

#### 7.2 운영 명령
| 하고 싶은 일 | 명령 |
|---|---|
| 리더 목록과 프로젝트 수 | `python beot_main.py owner hosts` |
| 만료 점검 상태 | `python beot_main.py owner status` (Cron 마지막 실행, 닫은 프로젝트 수, 오류) |
| 리더 계정 초기화 | `python beot_main.py owner unbind kim` (리더가 비밀번호를 잃었을 때. 리더는 같은 리더 토큰으로 입구에서 계정을 다시 만든다) |
| 리더 폐기 | `python beot_main.py owner revoke kim` (새 프로젝트를 못 만든다. **폐기된 리더는 자기 프로젝트를 닫지 못한다.** 열린 프로젝트가 남아 있으면 명령이 알려 준다. `close-rooms`로 서버장이 닫는다) |
| 리더의 열린 프로젝트 닫기 | `python beot_main.py owner close-rooms kim` (터널과 주소를 지운다. **폐기된 리더의 프로젝트도 닫는다.** 리더 PC의 프로젝트 데이터는 남는다) |
| 리더 지우기 | 서버장 화면의 **지우기**(폐기된 리더만) 또는 `python beot_main.py owner remove kim`. 열린 프로젝트가 있으면 안 된다. 계정과 세션도 같이 지운다. 되돌릴 수 없다 |
| 만료 기간 변경 | `python beot_main.py owner setup --expire-days 7` |
| 도메인이 여러 개일 때 | 명령 앞에 `--domain 도메인`을 붙인다 |

- 리더를 정리하는 순서: `revoke` → `close-rooms` → `remove`.
- **프로젝트 만료:** 리더 PC가 6시간마다 "살아 있음"을 알린다. 알림이 없는 날이 만료 기간(기본 14일)을 넘으면 Cron이 프로젝트의 터널과 주소를 지운다. 리더 PC의 저장물은 지우지 않는다.
- 서버장 관리 토큰을 잃으면 같은 PC에서 `setup`을 다시 실행해 새로 만든다. 이전 리더 토큰은 계속 유효하다.

#### 7.3 서버장 화면
명령 대신 앱의 **리더 관리**로 리더 초대, 목록, 폐기, 계정 초기화를 한다.
1. 앱(`beot.exe`)의 **입구 열기** 또는 **기존 입구로 들어가기**로 들어간다. 서버장 계정은 앱에서 만든다(관리 토큰을 붙여 넣지 않는다).
2. 홈 화면의 **리더 관리**에서 리더 목록(프로젝트 수, 계정 여부), **새 리더 초대**(리더 토큰은 한 번만 보인다), **폐기**, **계정 초기화**를 쓴다.
3. 서버장 계정은 리더 권한도 가진다. 프로젝트도 직접 만든다.
- 관리 토큰을 클립보드에 넣으려면 아래를 쓴다. 이름의 도메인 부분은 영문자와 숫자가 아닌 글자를 `_`로 바꾸고 대문자로 쓴 값이다(예: `example.com` → `BEOT_ADMIN_TOKEN_EXAMPLE_COM`). 사용한 뒤에는 클립보드를 다른 글자로 덮어쓴다.
```powershell
[Environment]::GetEnvironmentVariable("BEOT_ADMIN_TOKEN_<도메인>","User") | Set-Clipboard
```

#### 7.4 입구 업데이트와 새 버전 알리기
- 앱 자동 업데이트는 입구 Worker를 바꾸지 않는다. **Worker 수정이 있는 버전은 서버장이 직접 반영한다.**
  - 앱 홈 화면 **리더 관리**의 **입구 업데이트**를 누른다(토큰 필요).
  - 또는 `python beot_main.py owner --domain 도메인 setup`을 실행한다.
  - 계정과 프로젝트 데이터는 지워지지 않는다.
- 두 번째 이후 프로젝트를 만들려는 리더가 있으면 입구 업데이트가 먼저 필요하다([24.2](#242-리더-문제)).
- **새 버전 알리기:** 벗을 새로 받은 서버장 PC에서 `VERSION` 파일을 올리고 `python beot_main.py owner setup`을 다시 실행한다. Worker가 그 버전을 "최신"으로 알린다. 이보다 낮은 버전으로 도는 프로젝트의 리더 화면에 새 버전 알림이 뜬다(닫으면 그 버전은 다시 안 뜬다).

#### 7.5 철거
**경고:** 열려 있는 모든 프로젝트가 닫힌다. 되돌릴 수 없다.
```powershell
python beot_main.py owner teardown --yes
```
- 경로, 입구 주소, 열려 있는 모든 프로젝트의 터널과 주소, Worker(저장된 프로젝트 목록 포함)를 지운다.
- 리더 PC의 프로젝트 데이터는 지우지 않는다. 이 PC의 관리 토큰 환경 변수는 남는다.

### 8장 터널 수동 설정

**이 장의 위치:** 서버장 구조(`beot owner`와 `start.py`)를 쓰면 터널, 프로젝트 주소, 터널 토큰을 프로그램이 만든다. 이 장의 수동 절차는 **서버장 없이 직접 터널을 만들 때만** 쓴다. 서버장 구조에서는 이 장의 Access(8.3)를 쓰지 않는다.

> **경고 1:** 이 절차를 시작하면 프로젝트 서버가 인터넷에서 보이는 주소를 가진다. 로그인 토큰이 프로젝트 전체 권한이다. 토큰은 채팅, 파일, 화면 공유에 남기지 않는다.
>
> **경고 2:** 터널 토큰도 비밀값이다. 파일에 적지 않는다. 사용자 환경 변수에만 저장한다.
>
> **확인한 것(퀵 터널로 시험):** 접속자 IP 헤더 `CF-Connecting-IP`가 실제로 오고 서버가 그 값을 접속 주소로 쓴다. 공개 주소로 HSTS, MCP 접속, 틀린 토큰 5번 잠금이 동작한다. 퀵 터널은 계정과 도메인 없이 `cloudflared tunnel --url`로 만든다.
>
> **(미확인):** 이름 있는 터널, Cloudflare 화면 이름과 단계, Access(이메일 인증)와 제외 경로는 계정과 도메인이 있어야 해서 시험하지 않았다. 화면 이름이 다르면 Cloudflare 안내를 따른다.
>
> 도메인 구매, Cloudflare 가입, 터널과 Access 설정은 리더가 직접 한다.

#### 8.1 용어
- **터널:** 리더 PC에서 Cloudflare로 나가는 연결. 방화벽 설정과 포트포워딩이 필요 없다.
- **Access:** 프로젝트 서버로 가기 전에 이메일 인증 코드로 한 번 더 확인하는 Cloudflare 기능(무료 50명까지).
- **터널 모드:** `ROOM_TUNNEL=1`. 프로젝트 서버가 접속자 IP를 터널이 붙인 헤더에서 읽는다.

#### 8.2 프로젝트 서버를 터널 모드로 켜기
1. 새 PowerShell 창에서 환경 변수를 정한다. 기존 변수(`ROOM_DB` 등)는 그대로 둔다.
```powershell
$env:ROOM_GIT = "local"   # GitHub 방식 프로젝트면 "github". 정하지 않으면 프로젝트 서버가 켜지지 않는다
$env:ROOM_TUNNEL = "1"
$env:ROOM_PUBLIC_URL = "https://<프로젝트 이름>.example.com"
```
2. **`ROOM_ALLOWED_HOSTS`에 공개 주소의 호스트 이름을 넣는다.** 넣지 않으면 에이전트(MCP) 접속이 `421 Invalid Host header`로 거부된다(퀵 터널에서 확인). 화면(`/ui`)은 영향이 없다.
```powershell
$env:ROOM_ALLOWED_HOSTS = "<프로젝트 이름>.example.com,127.0.0.1:*,localhost:*"
```
3. 서버는 `127.0.0.1`에만 연다. 이 PC의 터널 프로그램만 서버에 연결할 수 있다.
```powershell
.\.venv\Scripts\python -m beot server serve --host 127.0.0.1 --port 8780
```
4. 시작 줄에 `터널 모드: True`가 나오는지 확인한다.

#### 8.3 터널 만들기와 Access
**터널 만들기 (미확인)**
1. Cloudflare에서 도메인을 연결한다.
2. Zero Trust 메뉴에서 터널을 만들고 `cloudflared` 설치 안내를 따른다.
3. 터널의 공개 호스트 이름을 `<프로젝트 이름>.example.com`으로 정하고, 서비스를 `http://127.0.0.1:8780`으로 정한다.
4. 터널 토큰은 사용자 환경 변수로 저장한다. 파일에 적지 않는다.

**Access 붙이기 (미확인, 서버장 구조에서는 쓰지 않는다)**
- 서버장 구조에서 Access를 쓰지 않는 이유: 팀원이 이메일 등록이나 추가 가입 없이 "프로젝트 코드와 비밀번호"만으로 들어와야 하기 때문이다. 방어선은 프로젝트 토큰, 초대 코드, 로그인 실패 횟수 잠금(같은 주소 5번, 프로젝트 전체 20번)이다.
- **중요:** Access를 주소 전체에 붙이면 에이전트(MCP)와 `join`이 막힌다. 이들은 브라우저가 아니어서 이메일 인증을 할 수 없다. 두 경로는 Access에서 제외하고, 프로젝트 서버의 토큰과 횟수 제한이 지킨다.

| 경로 | Access | 이유 |
|---|---|---|
| `/mcp*` | 제외(Bypass) | 에이전트가 프로젝트 토큰으로 접속한다 |
| `/api/redeem` | 제외(Bypass) | `join`이 초대 코드를 교환한다. 코드 입력 실패는 프로젝트 서버가 제한한다 |
| 그 밖의 모든 경로(`/ui`, `/api/state`, `/api/call/*`) | 이메일 인증 필요 | 브라우저 접속은 한 번 더 확인한다 |

1. Access에서 자체 호스팅 애플리케이션을 만든다. 주소는 `<프로젝트 이름>.example.com`이다.
2. 허용 정책에 리더와 팀원의 이메일을 넣는다.
3. `/mcp*`와 `/api/redeem`에 제외 정책을 만든다.

#### 8.4 터널 모드에서 달라지는 것
| 항목 | 내용 |
|---|---|
| 틀린 토큰 횟수 제한 | 같은 접속자 IP에서 10분에 5번 틀리면 그 IP는 맞는 토큰도 10분 거부된다. 서버를 다시 켜면 풀린다 |
| 새 IP 기록 | 멤버가 처음 보이는 IP로 접속하면 리더 화면의 "접속 기록 > 최근 접속 IP"에 남는다. 처음 이후의 IP에는 "새 IP" 표시가 붙는다. 차단은 아니다 |
| 로그인 토큰 재발급 | 대화에 "alice의 프로젝트 토큰이 재발급됐다"가 남는다 |
| HTTPS | 터널이 HTTPS를 맡는다. 서버는 `Strict-Transport-Security`를 붙인다 |

리더의 방어선은 로그인 토큰, 횟수 제한, Access다.

#### 8.5 휴대폰으로 리더가 접속하기
1. 휴대폰 브라우저에서 `https://<프로젝트 이름>.example.com/ui`를 연다.
2. Access의 이메일 인증을 한다.
3. 로그인 토큰을 입력한다. **"이 PC에서 기억하기"는 켜지 않는다.** 잠금이 없는 기기에서 휴대폰을 잃으면 프로젝트 전체 권한이 넘어간다.

#### 8.6 알아 둘 한계
- 같은 공유기(같은 공인 IP) 뒤의 사람이 틀린 토큰을 반복하면 그 IP 전체가 10분 잠긴다. 리더 휴대폰이 같은 Wi-Fi에 있어도 영향을 받을 수 있다.
- 틀린 프로젝트 토큰으로 계속 재시도하는 에이전트가 있으면 같은 IP의 정상 접속이 잠길 수 있다. 에이전트의 토큰이 맞는지 먼저 확인한다.
- 리더 PC가 꺼지거나 잠자기에 들면 이 프로젝트는 닫힌다.
- 프로젝트 서버의 잠금 횟수는 메모리에만 있다. 서버를 다시 켜면 풀린다.

### 이 부의 요약
- 서버장은 도메인과 Cloudflare 계정을 가지고 입구(Worker)를 한 번 설치한다. 서버 PC는 없다.
- 설치는 앱 창이 가장 쉽다. 서버장이 직접 할 일은 계정과 도메인 준비, 토큰 복사, Bot Fight Mode 끄기다.
- 명령 설치는 `python beot_main.py owner --domain example.com setup`이다. Cloudflare API 토큰 권한은 4개다.
- 리더 토큰(`bh_…`)은 한 번만 보인다. `owner invite 이름 --max 프로젝트수`로 만든다.
- 리더를 정리하는 순서는 `revoke` → `close-rooms` → `remove`다.
- Worker 수정이 있는 버전은 서버장이 **입구 업데이트**를 눌러야 반영된다.
- 터널 수동 설정은 서버장 없이 직접 터널을 만들 때만 쓴다.

## 3부 리더

> **경고:** 토큰과 초대 코드는 채팅, 파일, 화면 공유에 남기지 않는다.

### 9장 리더 시작 전에

#### 9.1 준비물
1. Python 3, git, 벗 프로그램(벗 폴더). 앱(`beot.exe`)만 쓰면 Python은 필요 없다.
2. **입구 주소**(도메인)와 **리더 토큰**(`bh_…`). 서버장에게 받는다. 서버장을 겸하면 [2부](#2부-서버장)의 설치를 먼저 하고 자기에게 리더 토큰을 만든다.
3. GitHub 방식이면 **공개 저장소**(README 파일이 있어야 한다)와 그 저장소 하나에 쓰는 GitHub 토큰. 만드는 법은 [11장](#11장-github-방식-준비)이다.

#### 9.2 소스로 실행할 때의 주의
**주의:** 이 부의 `python` 명령은 벗 폴더의 가상환경 Python이어야 한다. 시스템 `python`으로 실행하면 `No module named 'uvicorn'` 오류가 난다. 가상환경을 먼저 켠다. `beot.exe`를 쓰면 필요 없다.
```powershell
.\.venv\Scripts\Activate.ps1
```

#### 9.3 비공개가 필요하면
- 벗의 GitHub 방식은 공개 저장소다. 공개하면 안 되는 자료(기획 문서, 토큰, 데이터 등)는 저장소에 올리지 않고 **구글 드라이브**로 공유한다. 저장소에는 공개해도 되는 코드만 둔다.
- 비공개가 필요하면 로컬 보관 방식을 쓴다([16.2](#162-파일-탭), [25장](#25장-알려진-한계)).

#### 9.4 리더가 알아 둘 구조
- 프로젝트 서버는 일 목록, 규칙, 화면을 담당한다. 팀원은 자기 가지에 제출한다. **리더만 승인하고 합친다.**
- 외부 접속은 서버장이 준비한 도메인을 쓴다.

### 10장 프로젝트 만들기와 켜기

#### 10.1 방법 A: 입구 웹에서 만들기 (추천)
1. 브라우저로 `https://<입구 주소>`(예: `https://example.com`)를 연다.
2. **리더** 탭을 연다.
3. 처음이면 "처음이면 · 리더 토큰으로 들어가기"를 펼친다. 닉네임, 비밀번호(8자 이상), 서버장에게 받은 리더 토큰(`bh_…`)을 넣어 **계정을 한 번 만든다.** 다음부터는 닉네임과 비밀번호만 넣는다.
   - 계정 없이 토큰으로 바로 들어갈 수도 있다(탭을 닫으면 지워진다).
   - 비밀번호를 잃으면 서버장에게 "계정 초기화"를 요청한다.
4. **프로젝트 만들기**를 누른다. 프로젝트 코드와 실행할 명령이 나온다.
5. 리더 PC에서 그 명령을 실행한다. 이 PC가 그 프로젝트를 켠다.
```powershell
python -m beot start --code <프로젝트 코드>
```
- 앱(`beot.exe`) 홈 화면에서 내 프로젝트 목록(켜짐/꺼짐, 만료까지 남은 날), **프로젝트 화면 열기**, **코드 복사**, **닫기**를 쓸 수 있다.

#### 10.2 방법 B: 앱에서 만들기
1. 앱(`beot.exe`) 홈에서 프로젝트를 만든다. 프로젝트 이름, 팀원 폴더 이름, git 방식(로컬 보관 또는 GitHub)을 고른다.
2. 새 프로젝트는 처음부터 **계획서를 저장소에 두는 프로젝트**로 켜진다([14장](#14장-계획서로-일-만들기)). GitHub 방식이면 상자 "계획서와 지시서가 공개 저장소에 들어가는 것을 확인한다"를 켠다. 상자를 끄면 옛 프로젝트로 남고 경고가 나온다. 나중에 프로젝트 화면에서 옮길 수 있다.
3. 프로젝트를 켜면 **리더 에이전트 준비하고 켜기** 카드가 나온다. 누르면 리더 폴더를 만들고 리더 에이전트(claude)를 켠다. 리더 에이전트는 일을 하지 않는다. 질문 답, 1차 검토, 배정 후보 제안만 한다.
- `python -m beot start`는 앱에서 만든 프로젝트를 켠다. 설정이 없는 프로젝트면 "프로젝트 설정이 없다. 벗 앱에서 프로젝트를 만든다."를 내고 멈춘다.

#### 10.3 프로젝트가 켜질 때 프로그램이 하는 일
- 저장소 점검과 규칙 설정, 프로젝트와 리더 만들기, **프로젝트와 터널 만들기(입구에 요청)**, 프로젝트 서버 켜기, 잠자기 방지.
- 리더 토큰, 터널 토큰, GitHub 토큰은 설정 파일에 저장하지 않고, 이 PC 사용자 환경 변수(`BEOT_HOST_TOKEN_<프로젝트>` 등)에만 저장한다.
- 화면에 **로그인 토큰**(프로젝트 화면용, 다섯 단어 `xxxx-xxxx-…`)이 한 번 나온다. 안전한 곳에 둔다. 서버장에게 받은 리더 토큰(`bh_…`)과는 다른 값이다.
- 화면에 **프로젝트 코드**(예: `amber-river-moss-123`)와 입구 주소가 나온다. 팀원에게 전달한다.
- `--dry-run`을 붙이면 켜지 않고 할 일만 보인다.
- 입구 주소를 비우면 이 PC 안에서만 켠다(외부 접속 없음).
- 다음부터는 `python -m beot start` 한 줄로 켠다. 프로젝트 코드는 그대로다.

#### 10.4 프로젝트 화면 열기와 로그인
- 터미널의 `start`로 켜면 프로젝트 서버가 켜진 뒤 **브라우저가 프로젝트 화면을 자동으로 연다.** 첫 실행이면 로그인도 자동이다. 다음부터는 로그인 토큰(다섯 단어)을 넣는다. 자동으로 열지 않으려면 `--no-browser`를 붙인다.
- 앱의 **만들고 켜기**와 **켜기**는 `--no-browser`로 켜므로 자동으로 열지 않는다. 프로젝트 줄의 **프로젝트 화면 열기**를 누른다.
- 프로젝트 화면을 다시 열 때는 `beot.exe` → **프로젝트 화면 열기**를 누른다. 리더로 로그인된 채로 열린다(일회용 로그인 링크, 2분, 한 번). 입구의 리더 탭에서 **프로젝트 화면 열기**를 눌러도 된다. 터미널에서는 `beot.exe start --room 프로젝트이름 --open-ui`다.
- 프로젝트 화면의 로그인 화면은 **프로젝트 계정**(닉네임, 비밀번호)이다. 입구의 계정과 다르다.
- 리더 비밀번호를 잃으면 프로젝트 서버 PC에서 `beot.exe server set-password 리더닉네임`(리더 닉네임으로 바꿔 쓴다)을 실행한다. 앱이 보여 주는 복구 명령에는 앞에 `$env:ROOM_DB = "<room.db 경로>";`가 붙어 있다. 그대로 실행하면 다른 폴더에서도 맞는 프로젝트 파일을 연다.

#### 10.5 한 PC에서 프로젝트 여러 개 켜기
- 한 PC에서 프로젝트를 최대 20개 켤 수 있다. 프로젝트마다 로컬 포트가 따로 있다(8780~8799). 새 프로젝트는 쓰지 않는 번호를 자동으로 받는다.
- `beot.exe`의 프로젝트 목록에서 프로젝트마다 켜고 끈다.
- 두 번째 이후 프로젝트를 만들려면 **서버장이 앱의 [입구 업데이트]를 먼저 해야 한다.** 옛 버전의 입구에서는 "입구가 옛 버전"이라고 안내하고 만들지 않는다.
- 서버장이 정한 "동시에 열 수 있는 프로젝트" 한도(기본 2개, 최대 20개)도 적용된다.
- 1.1.5 이전에 만든 프로젝트는 포트가 8780이다. 옛 프로젝트 둘을 함께 켜지는 못한다. 새로 만드는 프로젝트부터 다른 포트를 받는다.

#### 10.6 끄기와 닫기
- **프로젝트는 백그라운드로 돈다.** `.exe`는 기본이고, 소스 실행은 `--background`를 붙인다. 설정이 끝나면 터미널 창을 닫아도 프로젝트는 켜져 있다.
- 끄거나 닫을 때는 앱의 프로젝트 목록에서 **끄기** 또는 **닫기**를 누른다(프로젝트 화면의 단추도 같다). 터미널에서는 `python -m beot start --stop`이다.
  - **프로젝트 끄기:** 프로젝트만 멈춘다. 프로젝트 코드와 터널은 그대로라서 다시 켜면 같은 프로젝트다.
  - **프로젝트 닫기:** 프로젝트 코드와 프로젝트 주소가 사라진다. 팀원은 못 들어온다. 프로젝트 데이터는 이 PC에 남는다.
- **PC를 켜면 묻는다.** 프로젝트를 처음 켠 뒤 "PC를 켤 때마다 프로젝트를 켤지 물을까?"를 한 번 묻는다. 예를 고르면 Windows 로그인 때 "프로젝트를 켤까?"가 뜬다. 끄려면 `python -m beot start --no-ask-at-login`.

#### 10.7 고정해 둘 것
리더 PC가 꺼지거나 잠자기에 들면 프로젝트는 닫힌 것처럼 보인다. 이 프로그램은 켜 있는 동안 잠자기를 막는다. 노트북은 덮개를 닫지 않는다(전원 설정에서 바꿀 수 있다).

#### 10.8 git 없는 프로젝트
- 예전의 "비공개(git 없음)" 프로젝트는 더 켜지 않는다. 켜면 "git 없는 프로젝트는 더 켜지 않는다"가 나온다. 프로젝트 데이터는 그대로다.
- 프로젝트 폴더의 `beot.config.json`에서 `"git": "none"`을 `"local"`로 바꾸면 로컬 보관 프로젝트로 켠다.
- 끄기, 닫기, 로그인 때 묻기 풀기는 그대로 된다.

### 11장 GitHub 방식 준비

> **경고 1:** 이 방식의 저장소는 **공개**다. 누구나 코드를 볼 수 있다. 팀 모두가 동의해야 한다. 비밀번호, API 키, `.env` 파일은 저장소에 올리지 않는다.
>
> **경고 2:** 11.3의 토큰은 이 저장소의 **관리자 권한**을 가진다. 새면 저장소를 남이 관리할 수 있다. 채팅, 파일, 화면 공유에 남기지 않는다. 환경 변수로만 둔다.
>
> 이 절차로 공개 저장소와 토큰을 만들고 GitHub 방식 프로젝트를 켜 확인했다(규칙 세트 2개 생성). 화면 이름이 다르면 GitHub 화면을 따른다.

#### 11.1 이 방식이 맞는가
| | GitHub 방식 |
|---|---|
| 코드 | **공개** |
| "리더만 병합" 강제 | O (규칙 세트) |
| 팀원별 가지 제한 | **X** (팀원이 다른 팀원의 `member/…` 가지를 바꿀 수 있다) |
| 리더 PC 설치 | 없음 |
| 팀원 준비 | **본인 GitHub 계정**, 초대 수락 |

코드를 공개하기 어렵거나 팀원별 가지 제한이 필요하면 GitHub 방식을 쓰지 않는다. 로컬 보관 방식(`ROOM_GIT=local`)을 쓴다.

#### 11.2 저장소 만들기 (GitHub 화면)
1. GitHub에서 새 저장소를 만든다.
2. 공개(Public)를 고른다. 비공개는 무료 계정에서 규칙 세트가 적용되지 않는다.
3. **README 파일을 추가한다.** 기본 가지(`main`)가 있어야 한다.
4. 저장소 이름을 적어 둔다. 형식은 `소유자/이름`이다.
5. 저장소 설정(Settings) > General > Pull Requests에서 **Allow merge commits**가 켜져 있는지 본다. 프로젝트가 병합 커밋 방식으로 병합한다.

#### 11.3 토큰 만들기 (GitHub 화면)
1. GitHub의 Settings > Developer settings > Personal access tokens > **Fine-grained tokens**에서 새 토큰을 만든다.
2. **Repository access**: Only select repositories를 고르고 **11.2의 저장소 하나만** 고른다.
3. **Repository permissions**:
   - Administration: Read and write (협업자 초대와 제거, 규칙 세트)
   - Contents: Read and write
   - Pull requests: Read and write
   - Metadata: Read-only (자동으로 켜진다)
4. **Expiration**: 90일 이하로 정한다. 만료되기 전에 새 토큰으로 바꾼다.
5. 만들어진 토큰은 한 번만 보인다. 다음 단계에서 환경 변수에 넣는다.

#### 11.4 프로젝트 서버를 GitHub 방식으로 켜기
새 PowerShell 창에서 환경 변수를 정한다. 토큰 값은 화면에 붙여 넣고 파일에 쓰지 않는다.
```powershell
$env:ROOM_GIT = "github"
$env:ROOM_GITHUB_REPO = "<소유자>/<이름>"
$env:ROOM_GITHUB_TOKEN = "<11.3의 토큰>"
$env:ROOM_DB = "$PWD\room.db"
$env:ROOM_PUBLIC_URL = "<팀원이 쓰는 프로젝트 주소>"
```
토큰을 새 창에서도 쓰려면 사용자 환경 변수로 저장한다.
```powershell
[Environment]::SetEnvironmentVariable("ROOM_GITHUB_TOKEN", "<토큰>", "User")
```

#### 11.5 저장소 점검과 규칙 세트 만들기
```powershell
.\.venv\Scripts\python -m beot server setup-git
```
이 명령은 다음을 한다.
1. 저장소가 공개인지, 토큰에 관리자 권한이 있는지, 기본 가지가 있는지, 병합 커밋이 허용인지, 규칙 세트를 읽을 수 있는지 점검한다.
2. 문제가 하나라도 있으면 이유를 출력하고 **아무것도 만들지 않는다.** 문제를 고치고 다시 실행한다.
3. 통과하면 규칙 세트 2개를 만든다(이미 있으면 갱신한다. 여러 번 실행해도 된다).
   - 기본 가지(`main`)는 PR로만 바뀐다. 강제 push와 삭제는 막는다.
   - `member/<이름>/…` 가지 밖의 가지는 만들기, 바꾸기, 삭제를 막는다.
   - 리더(저장소 관리자)는 PR 병합 때만 규칙을 우회한다.

**확인한다(무인 도우미를 켜기 전에 1번):** GitHub 저장소의 **Settings → Rules → Rulesets**에서 규칙 세트 2개가 **Active**인지 본다. Disabled이거나 없으면 `main` 보호가 비어 있다. 서버 쪽 push 거부는 GitHub 규칙 세트만 한다(로컬 보관 방식은 프로젝트 서버의 훅이 한다).

#### 11.6 프로젝트 만들기와 팀원 초대
1. 프로젝트를 만든다: `.\.venv\Scripts\python -m beot server init --owner <리더 이름>`. 로그인 토큰이 한 번 출력된다.
2. 프로젝트 서버를 켠다([17.1](#171-처음-한-번-프로젝트-만들기)의 5번).
3. 리더 화면에서 "팀원 추가"를 누른다. **이름**과 **팀원의 GitHub 사용자 이름**을 넣는다.
4. 나온 안내문(프로젝트 주소, 초대 코드, 단계)을 팀원에게 보낸다. 안내문 첫 단계가 GitHub 초대 수락이다.
5. 팀원이 GitHub에서 초대를 수락해야 push할 수 있다. 초대는 7일 뒤 만료된다. 만료되면 멤버 줄의 "코드 다시 받기"가 초대를 다시 보낸다.

팀원 쪽 절차(안내문에 포함):
1. 받은 링크에서 GitHub 초대를 수락한다. 계정이 없으면 먼저 가입한다.
2. `join.py`를 실행한다. 공개 저장소를 로그인 없이 받는다.
3. 처음 push할 때 GitHub 로그인이 나온다(Windows는 자격 증명 관리자가 뜬다).
4. 50MB 넘는 파일과 비밀 파일 이름은 push 전에 막힌다. 큰 파일은 구글 드라이브로 공유한다.

### 12장 팀원 초대와 관리

#### 12.1 팀원 초대
1. 리더 화면의 "멤버" 구역에서 "팀원 추가"를 누른다.
2. 한 줄에 1명씩 쓴다: `닉네임[, 보기][, GitHub 이름]`. 여러 명을 한 번에 쓴다. GitHub 방식이면 팀원의 **GitHub 사용자 이름**도 넣는다.
3. **미리보기**에서 틀린 줄(이름 규칙, 겹침)을 고친다. **연습 일**에서 "멤버마다 연습 일 1개"를 고르면 팀원마다 연습 일이 1개 생긴다(`연습/<이름>.md`를 만들어 제출하는 일).
4. 결과 창에서 멤버마다 **안내문 복사**를 누른다. 안내문은 멤버마다 따로 보낸다(초대 코드는 그 멤버의 일회용 비밀값이다). **창을 닫으면 초대 코드를 다시 볼 수 없다.**
5. 안내문에는 입구 주소, 프로젝트 코드, 초대 코드와 순서가 있다. 순서는 다음과 같다. 안내문을 팀원에게 보낸다. `join.py` 파일은 보내지 않아도 된다.
   1. 벗을 설치한다.
   2. 앱에서 프로필(닉네임, 비밀번호)을 만든다.
   3. **기존 입구로 들어가기**의 안내문 칸에 안내문을 붙여 넣는다(세 칸이 채워진다).
   - 프로젝트의 닉네임과 비밀번호는 프로필 값으로 자동으로 정해진다.
6. 팀원에게 [4부](#4부-팀원)를 읽게 한다.

- 초대 코드는 24시간 안에 한 번만 쓸 수 있다. 잃었거나 `join`이 실패하면 멤버 줄의 "코드 다시 받기"를 누른다.
- 팀원이 안내문을 붙여 넣으면 앱이 새 형식(`입구 주소:` · `초대 코드:`)과 옛 형식(`서버 주소:` · `서버장 주소:` · `단어 코드:`)을 모두 읽는다(1.1.16). 1.1.15 이전에 받은 안내문도 그대로 쓴다.
- 팀원은 초대 코드를 낼 때 비밀번호를 정한다. **입장은 사람이 직접 한다**(에이전트, 스크립트는 입장하지 못한다).
- 팀원에게 **다른 서비스와 같은 비밀번호를 쓰지 않는다**고 알린다. 리더는 프로젝트 서버에서 팀원이 로그인할 때의 비밀번호 원문을 받을 수 있다.
- 앱은 프로필 비밀번호로 프로젝트 화면에 로그인한다. 예전의 로그인 티켓은 없어졌다.
- 로그인 실패: 같은 주소에서 5번, 프로젝트 전체에서 20번 실패하면 10분 동안 입장이 닫힌다.

#### 12.2 멤버 관리
- **비밀번호 재설정:** 팀원이 비밀번호를 잃으면 멤버 줄의 **"비밀번호 재설정"**을 눌러 코드(24시간, 한 번)를 받아 전달한다. 리더 본인이 잃으면 프로젝트 서버 PC에서 `python -m beot server set-password <내 이름>`을 쓴다.
- **닉네임:** 팀원은 처음 입장할 때 닉네임을 한 번 바꿀 수 있다(GitHub 방식, 로컬 보관 방식). 배정한 일의 담당은 바뀐 이름으로 따라온다.
- **내보내기:** 멤버 줄의 "내보내기"를 누른다. 내보낸 멤버의 권한도 사라진다.
- **팀원 지우기:** 내보낸 멤버는 목록에 남는다. 멤버 줄의 **지우기**를 누르면 목록에서 사라진다(리더만, 내보낸 멤버만).
  - 진행 중이거나 검토를 기다리는 일이 있으면 거부한다. 배정만 된 일은 담당 없이 대기로 돌아간다.
  - 승인된 일과 기록에는 이름이 남는다. 다시 들어오려면 새로 초대한다.
- **로그인 토큰 바꾸기:** 프로젝트 화면 멤버 목록의 내 줄에서 **내 토큰 받기**를 누른다. 이전 리더 토큰과 에이전트 토큰은 끊긴다.

### 13장 일 만들기와 승인

#### 13.1 일 만들기와 승인
1. 화면의 "새 일"로 일을 만든다. 담당을 고를 수 있다.
2. 순서가 있으면 "먼저 승인돼야 하는 일의 번호"를 넣는다. 선행 일이 승인되기 전에는 후행 일을 시작할 수 없다.
3. 팀원이 제출하면 "검토 대기"에 나온다.
4. 변경을 확인한다. [13.3](#133-검토-도우미)을 쓰면 편하다.
5. "승인"을 누르면 PR이 합쳐진다. 반려는 사유가 필수다. **승인 · 반려 · 1차 없이 승인 창에는 "내 비밀번호" 칸이 있다. 로그인한 상태여도 결정할 때마다 넣는다**(1.1.12).
6. **보호 파일 경고**가 있으면(`CLAUDE.md`, `.claude/` 등) 그 파일의 내용을 직접 읽는다. GitHub 방식은 GitHub에서, 로컬 보관 방식은 원본에서 읽는다. 문제없으면 "확인했고 승인"을 누른다. 확인 없이는 승인되지 않는다.
- 비밀번호가 없거나 틀리면 프로젝트 서버가 결정하지 않는다. 이 실패는 로그인 실패로 세어, 여러 번 실패하면 10분 동안 잠긴다. 앱의 **[프로젝트 화면 열기]**로 들어온 화면은 이 비밀번호 한 번으로 로그인과 결정을 함께 한다. 앱의 검토 화면에서 승인 · 반려를 누르면 Windows 확인 창이 뜬다. **[예]**를 눌러야 보낸다.
- 이유: 로그인된 화면을 에이전트가 조작해 최종 반려를 한 사례가 있었다. 최종 승인 · 반려는 사람만 한다. **에이전트에게 비밀번호를 알려 주지 않는다.**
- 프로젝트 밖(GitHub 화면)에서 병합된 제출은 프로젝트 서버가 1시간마다 찾아 승인으로 맞춘다.
- GitHub 방식 프로젝트는 검토 화면에 PR 링크가 보인다.
- 전체 일의 흐름 보기는 확대 · 축소한다(`+` / `−` / `100%` / 화면에 맞춤, Ctrl+휠, 두 손가락). 일 수를 셀 때 "진행 중"은 실제로 맡아 하는 일만 센다. 배정됨 · 반려됨은 "대기"다.
- 일 만들기와 배정은 화면의 "새 일"과 일의 "배정"으로 한다.
- 승인에서 "가지가 바뀌었다"가 나오면 팀원이 다시 제출해야 한다.
- 반려했는데 PR 댓글이 없으면 리더 에이전트에게 `events_since`로 `pr_comment_failed` 기록이 있는지 묻는다(화면에는 안 나온다). 반려 자체는 기록된다.

#### 13.2 기준 문서
- 작업문서와 지시서는 프로젝트 화면에서 읽기만 한다. 옮긴 프로젝트는 저장소의 `벗/작업문서.md`와 `벗/지시서.md`가 원본이다.
- 고치려면 파일 탭에서 폴더 칸에 `벗`을 넣고 그 파일을 올린다(로컬 방식). GitHub 방식은 GitHub 화면에서 고치고 병합한다.
- 옮기지 않은 옛 프로젝트의 기준 문서는 고정이다.

#### 13.3 검토 도우미
리더 PC에서 실행한다. 제출된 가지를 검토용 작업 폴더로 열고 PR 링크와 변경 요약을 보여 준다.
```powershell
python join.py --review <일 번호>
```
- 리더의 작업 폴더(`C:\Users\<내 이름>\Beot\room`)가 기본이다. 다르면 `--dest <폴더>`를 붙인다.
- 승인과 반려는 화면에서 한다.
- 이 명령은 자동 시험으로만 확인했다. 실서버에서는 프로젝트 화면으로 검토했다. 명령이 실패하면 화면에서 검토한다.
- 검토 도우미(`--review`)는 지금 리더만 쓴다.

#### 13.4 검토 권한 주기
팀원에게 검토를 맡길 수 있다. 검토 권한이 있는 팀원은 "검토" 화면에서 제출물을 승인하거나 반려한다.

**주의:** [보호 파일도 승인]을 켜면 그 팀원은 `CLAUDE.md`, `.claude/` 같은 에이전트 설정 파일을 바꾼 일도 승인한다. 병합되면 모든 팀원의 에이전트가 그 파일을 따른다. 믿는 팀원에게만 켠다.

1. 화면의 "멤버"를 연다.
2. 검토를 맡길 팀원의 [검토 권한]을 켠다.
3. 보호 파일 변경도 맡기려면 [보호 파일도 승인]을 켠다. [검토 권한]이 꺼져 있으면 켤 수 없다.
4. 권한을 거두려면 [검토 권한]을 끈다. [보호 파일도 승인]도 같이 꺼진다.

- 검토 권한자는 자기가 제출한 일을 승인하거나 반려할 수 없다. 리더나 다른 검토자가 검토한다.
- 보호 파일을 바꾼 일은 [보호 파일도 승인] 권한이 없는 검토자가 반려만 할 수 있다.
- 권한은 리더만 줄 수 있다. 검토자는 다른 사람에게 권한을 줄 수 없다.
- 누가 승인했는지는 기록에 남는다. 팀원을 내보내면 권한도 사라진다.

#### 13.5 에이전트 최종 검토
리더가 명령한 제출 1건만 리더 에이전트가 다시 검토한다. 사람의 최종 승인을 대신하지 않는다. 리더가 명령할 때만 쓴다.

**주의:** 이 검토는 리더 PC의 Claude 구독 한도를 쓴다.

1. 프로젝트 화면의 검토 화면에서 제출을 연다.
2. **[에이전트 최종 검토]**를 누르고 비밀번호를 1번 넣는다.
3. 리더 에이전트가 그 제출을 Opus 5.5 · xhigh로 검토하고 승인 · 반려 · 사람에게 돌리기 중 하나로 판정한다.
4. 승인 기록에 "에이전트 최종 판정 · 모델 · 노력 · 명령한 사람"이 남는다.
- 허가는 그 제출의 지금 커밋에만, 30분 동안 1번 쓰인다. 에이전트는 비밀번호를 받지 않는다.
- **맡기지 않는 제출:** 보호 경로 · 계획 변경 · 1차 통과 없음 · 검사가 통과가 아님 · 바뀐 줄이 잘림. 이런 제출은 사람이 승인한다.
- **1차 검토 범위(1.1.13):** 리더 에이전트는 리더 본인 제출, 계획 변경 제안(PR 있는 것), 보호 경로 제출도 1차 검토한다. 보호 경로 제출의 최종 승인은 사람이 내용을 직접 확인한다.
- **`origin`이 없는 리더 폴더(1.1.14):** 프로젝트 서버가 리더 에이전트에게 제출 가지를 받을 곳을 알려 준다. 리더 폴더는 건드리지 않는다. 임시 저장소에 제출 커밋만 받아 검토하고, 끝나면 지운다.
- **리더 에이전트가 Orca 봇일 때(1.1.15):** 프로젝트 설정에서 리더 에이전트를 *Orca 봇*으로 고르면 리더 에이전트는 검토하지 않고 봇이 1차 통과와 에이전트 최종 검토를 한다([16.9](#169-orca-봇-연결-1115)). 모델 · 노력을 확인할 수 없어서 "약한 검토"로 표시된다. 위의 사람 허가(비밀번호 1번, 그 제출 · 그 커밋 · 30분 · 1번)와 "맡기지 않는 제출" 규칙은 그대로다. 리더 에이전트를 바꾸면 이전에 낸 허가는 무효가 된다.

### 14장 계획서로 일 만들기

계획서는 저장소의 `벗/계획서.md`다. 이 파일이 일 목록의 원본이다. 계획서가 바뀌면 프로젝트가 일 목록을 키(`[키]`)로 맞춘다. 새 키는 새 일, 바뀐 항목은 그 일의 갱신, 없어진 키는 "없어진 일" 표지다(일은 지우지 않는다).

#### 14.1 계획서 만들기 절차
1. **옮기기(옛 프로젝트만):** 프로젝트 화면 "전체 일"의 **계획서**를 누른다. 옮기지 않은 프로젝트면 **옮기기** 창이 나온다.
   1. 먼저 프로젝트 화면 멤버 칸의 [백업]으로 백업한다.
   2. GitHub 방식이면 공개 확인 상자를 켠다.
   3. **옮기기**를 누른다. 지금 일 목록이 `벗/계획서.md`가 되고 일은 바뀌지 않는다.
   - 새 프로젝트는 이 단계가 없다.
2. **계획서** 창에서 **계획서 만들기 프롬프트 복사**를 누른다.
3. 리더 폴더의 에이전트 창에 붙여 넣는다. 에이전트가 목표를 묻는다. 답한다. 에이전트가 `벗/계획서.md`를 쓴다. 담당은 지금 팀원 이름이다.
4. **로컬 방식:** 파일 탭을 연다. 폴더 칸에 `벗`을 넣는다. 그 파일을 고르고 올린다. 프로젝트가 계획서를 검사한다. 오류(줄 번호)가 있으면 올리지 않고 이유를 보여 준다. 통과하면 바로 일이 생긴다.
5. **GitHub 방식:** GitHub 화면에서 `벗/계획서.md`를 올린다. 새 가지 이름을 `member/<내 닉네임>/plan-first`로 정해 PR을 만들고 병합한다(다른 가지 이름은 저장소 규칙이 막는다). 프로젝트가 1시간 안에(또는 프로젝트를 다시 켤 때) 일 목록을 맞춘다. 계획서에 오류가 있으면 일 목록을 바꾸지 않고 프로젝트 대화로 알린다.

#### 14.2 계획서 형식
- 일은 `- [키] 제목 | 담당: 이름 | 선행: 키, 키` 목록이다. **모든 일에 [키]**가 있어야 한다.
- 담당은 멤버 이름 또는 `없음`이다(`팀원1` 칸은 쓰지 않는다).
- 들여쓰기(2칸)는 "위 일이 승인된 뒤에 시작"이다.
- 일은 100개, 깊이는 6단계까지다.
- 키를 바꾸면 "없어진 일 1 + 새 일 1"이 된다. 키는 고치지 않는다.

선택 항목:
- **검사:** 일 줄에 `| 검사: python tools/run_tests.py`를 쓰면, 에이전트가 제출하기 전에 그 명령을 실행하고 결과를 함께 보낸다. 검토 화면의 "검사"에 **통과, 실패, 결과 없음**이 보인다. 실패나 결과 없음은 경고로만 표시하고 승인은 막지 않는다. 결과는 에이전트가 보고한 값이므로 증명이 아니다. 서버는 명령을 실행하지 않는다.
- **완료:** `| 완료: tests/test_x.py 통과, README에 명령 1줄`처럼 사람이 그대로 확인할 수 있는 글(파일, 명령, 수)을 200자 이내로 쓴다. 1차 검토가 이 항목을 확인한다.
- **범위:** `| 범위: beot/x.py, docs/`처럼 이 일이 고칠 경로를 10개, 200자 이내로 쓴다. `/`로 끝나면 폴더다.
- 미리보기는 "확인 방법 없음(검사와 완료 둘 다 없음), 흐린 말(잘, 적절히 등), 범위 겹침" 수를 경고로 보여 준다. 막지는 않는다.

#### 14.3 계획이 바뀔 때
- **계획서의 일은 화면에서 고치지 않는다.** 제목, 설명, 마감, 선행, 지우기, 계획 담당은 계획서를 고쳐서 바꾼다. 계획서 밖의 일(화면의 "새 일")은 화면에서 고친다.
- **계획 변경 제안:** 계획 변경은 팀원 에이전트가 계획 파일만 고친 가지로 제안한다(`plan_propose`). 검토 대기에 "계획 변경 제안 · 새 일 · 바뀐 일 · 없어지는 일 · 담당 바뀜 · 담당 없는 일" 수가 나온다. **리더만** 승인한다. 승인하면 병합하고 일 목록이 바뀐다. 보통 일의 제출이 계획 파일을 바꾸면 프로젝트가 거부한다.
- **표지:** 진행 중인 일의 계획이 바뀌면 "계획 바뀜", 계획서에서 빠지면 "없어진 일" 표지가 일 목록과 검토 대기에 달린다. 담당 무인 도우미가 깨어나 바뀐 내용을 읽는다. 표지는 다음 제출이 지운다.
- 만든 일은 평소처럼 맡기고 제출하고 승인한다.
- 리더 폴더에는 앱 세션(`/벗 연결`)을 연결하지 않는다. 리더 폴더의 리더 에이전트가 1차 검토를 계속한다.

### 15장 평소 운영

#### 15.1 운영 표
| 하고 싶은 일 | 방법 |
|---|---|
| 켜기 | 앱의 프로젝트 목록 **켜기** 또는 `python -m beot start` |
| 끄기 | 앱의 프로젝트 목록 **끄기** 또는 `python -m beot start --stop`. 프로젝트는 만료 기간 안에는 남아 있다. 리더 PC가 꺼져 있는 동안 팀원은 들어올 수 없다 |
| **프로젝트 닫기(팀플 끝)** | `python -m beot start --close`. 입구에서 프로젝트 주소와 터널이 지워지고 팀원은 더 들어오지 못한다. **프로젝트 데이터는 이 PC에 그대로 남는다.** 다시 `python -m beot start`를 하면 새 프로젝트 코드로 새 프로젝트가 열린다 |
| 프로젝트 만료 | 14일(서버장 설정) 동안 켜 있지 않으면 자동으로 닫힌다. 켜 있는 동안은 6시간마다 자동으로 알린다 |
| 일 만들기와 배정 | 화면의 "새 일", 일의 "배정" |
| 승인과 반려 | 화면의 "검토 대기". 반려는 사유가 필수다 |
| 긴급 공지 | 대화에서 "긴급"을 체크하고 보낸다 |
| 로그인 토큰 바꾸기 | 프로젝트 화면 멤버 목록의 내 줄에서 **내 토큰 받기**. 이전 리더 토큰과 에이전트 토큰은 끊긴다 |
| 백업 | 리더 화면 멤버 구역의 "백업" 단추. 파일 탭 프로젝트는 원본도 들어간다([16.7](#167-백업과-복원)) |

**경고:** 백업 zip에 비밀값이 있다. 다른 곳에 두고 쓴 뒤 지운다.

#### 15.2 프로젝트 서버 수동 실행 때의 운영 명령
수동 실행([17장](#17장-프로젝트-서버-수동-실행))은 아래 명령을 쓴다.
| 하고 싶은 일 | 명령 |
|---|---|
| 팀원 내보내기 | `python -m beot server revoke bob`. 프로젝트 토큰이 즉시 무효가 되고 git 쓰기 권한이 회수된다. 이미 clone된 사본은 회수되지 않는다 |
| 로그인 토큰 바꾸기 | `python -m beot server rotate alice`. 새 토큰이 출력된다 |
| 백업 | `.\.venv\Scripts\python -m beot backup`. 서버를 멈추지 않는다 |

### 16장 앱의 기능

> **표시:** 이 장의 화면 이름은 앱 화면의 글자를 코드에서 읽고 썼다. 실제 화면에서 다시 확인하지 않았다.

#### 16.1 저장 폴더
프로젝트 데이터(`room.db`)와 파일 탭 원본이 이 폴더에 쌓인다. 문서가 많으면 용량이 커진다. 큰 디스크에 두려고 정한다.
1. 앱 홈의 **새 프로젝트 만들기**를 연다.
2. **저장 폴더** 칸에 폴더 경로를 넣거나 **폴더 고르기**를 누른다. 비어 있는 폴더를 고른다. 비우면 기본 위치다.
3. **만들고 켜기**를 누른다.
- 프로젝트 줄 아래에 `저장 폴더: …`가 보인다. **용량 보기**로 쓴 크기를 본다.
- 프로젝트를 만든 뒤에 옮기려면 먼저 프로젝트를 **끈다.** 그 뒤 폴더를 직접 옮긴다. 앱에는 폴더 이동 기능이 없다.
- 저장 폴더는 `beot.exe`가 있는 폴더와 별개다. 앱을 다시 설치해도 저장 폴더는 지워지지 않는다.

#### 16.2 파일 탭
원본 파일을 리더 PC에 두고 관리한다.
- 준비: 이 PC에 **git**을 설치한다. 새 프로젝트 만들기의 **자료 공유 방식**에서 **로컬 보관**을 고른다.
- 원본은 리더 PC의 로컬 git 저장소다. GitHub가 필요 없다. 이 방식은 비공개 작업에 쓴다(한계는 [25.3](#253-파일-탭의-비공개와-한계)).

절차:
1. 프로젝트가 켜진 줄의 **파일** 단추를 누른다(로컬 보관 프로젝트에만 보인다). 프로젝트 화면의 **파일** 탭이 같은 창에서 열린다. 프로젝트 화면에서 왼쪽 메뉴의 **파일**을 눌러도 된다.
2. 파일은 폴더 트리로 보인다. 폴더를 누르면 접고 펼친다. 파일을 누르면 오른쪽에 내용이 보인다(텍스트와 그림. 그 밖의 형식은 **내려받기**).
3. 올리려면 **파일 선택**으로 파일을 고르고, 폴더로 나누려면 **올릴 폴더**(예: `docs`)를 적고 **올리기**를 누른다. 파일 하나는 **50MB 이하**여야 한다. 큰 파일은 구글 드라이브로 나눈다.
4. 파일을 지우려면 파일을 눌러 **지우기**를 누른다. 팀원이 이미 받은 사본은 남는다.
5. 팀원이 [완료]를 제출하면 프로젝트 화면의 **검토** 탭(또는 앱의 **검토 대기**)에 나온다. **바뀐 파일 보기**로 바뀐 파일 목록을 읽는다.
6. 맞으면 **승인**을 누른다. 원본에 합쳐진다. 아니면 **반려 사유**를 적고 **반려**를 누른다(사유는 필수다).

- **보호 파일 경고:** 에이전트 설정 파일(`CLAUDE.md`, `.claude/` 등)이 바뀐 제출은 병합되면 다른 팀원의 에이전트가 따른다. 내용을 직접 읽는다. 괜찮으면 **확인했고 승인**을 누른다.
- 병합이 충돌하면 프로젝트가 자동으로 풀지 않는다. 팀원에게 새 원본에 맞춰 다시 제출하라고 알린다.
- 팀원은 파일 탭에서 목록을 보고 내려받을 수 있다. 팀원은 `문서함/<이름>/` 아래에는 승인 없이 올릴 수 있다(200MB까지, 에이전트 설정 파일은 불가). 리더는 파일 탭에서 지울 수 있다.
- 팀원은 원본의 `main`에 올릴 수 없다. `member/<이름>/…` 가지로만 제출한다.
- 폴더별 접근 범위는 없다. 팀원 전원이 전체 파일을 받을 수 있다.
- 리더 PC가 꺼지면 팀원은 사본을 받거나 제출할 수 없다.

#### 16.3 결정 목록
- 팀원의 에이전트가 중요한 일을 물으면(`decide` 요청) 앱 홈 위에 **결정 요청 N건**이 나온다. 앱이 켜져 있어야 한다.
1. 요청 내용을 읽는다.
2. 선택지 단추를 누르거나 **직접 답하기**에 적고 Enter를 누른다.
- 에이전트는 `decide`에 스스로 답하지 못한다. 사람의 답만 올라간다.
- 에이전트의 **자료 요청**(`ask`)에는 다른 에이전트가 답한다. 사람의 답이 필요 없다.
- 실서버 시험에서 팀원 에이전트의 `decide` 요청과 리더의 화면 답을 확인했다.

#### 16.4 프로젝트 삭제
**경고:** 프로젝트 설정과 데이터를 지운다. 되돌릴 수 없다. 백업이 필요하면 먼저 백업한다.
- 꺼진 프로젝트의 **삭제**를 누른다. 프로젝트가 켜져 있으면 단추가 없다. 먼저 **끄기**를 누른다.
1. **삭제**를 누른다.
2. 상자에 프로젝트 이름을 그대로 입력한다.
- 입구에 등록된 프로젝트면 먼저 닫는다. 프로젝트 폴더와 저장 폴더의 벗 파일만 지운다.

#### 16.5 명령줄과 단축키
프로젝트 화면에서 쓴다. 글을 쓰는 중에는 단축키가 꺼진다.
- **Ctrl+K**(또는 `/`): 명령줄을 연다. 글자를 쓰면 화면 이동과 동작이 걸러지고, 일(제목, 본문)과 대화 글이 검색된다. ↑↓로 고르고 Enter로 연다. Esc로 닫는다.
- 비공개 1:1 대화(DM)는 그 두 사람만 검색된다. 리더도 남의 DM은 보이지 않는다.
- **`?`**: 단축키 도움말.
- **`j` / `k`**: 전체 일 목록에서 아래 / 위 일로 이동한다. **Enter**로 고른 일을 연다.
- **`v`**: 전체 일 보기를 바꾼다(목록 → 트리 → 칸반 → 타임라인).

#### 16.6 리더 에이전트 연결
리더도 에이전트(Claude Code 등)를 내 프로젝트에 연결해 일 만들기, 배정, 진행 확인을 시킬 수 있다. 앱에 계정으로 로그인한 리더만 쓴다.

**주의:** 이 토큰은 리더 권한 전부를 가진다. 토큰은 이 PC의 토큰 저장소에 있다. 작업 폴더의 `.mcp.json`에는 중계 주소와 중계 토큰만 있다. 폴더를 공유하거나 커밋하지 않는다.

1. 앱을 열고 **설정**(홈 위 **계정 … ›**)을 연다.
2. **내 프로젝트에 에이전트 연결 (리더)**에서 프로젝트가 켜져 있는지 본다. 꺼져 있으면 먼저 프로젝트를 켠다.
3. **에이전트 연결 만들기**를 누른다. 리더 에이전트 토큰을 만들고 작업 폴더(`C:\Users\<내 이름>\Beot\<프로젝트 이름>-owner`)에 `.mcp.json`, `CLAUDE.md`, `AGENTS.md`를 쓴다. 에이전트 토큰은 이 PC의 토큰 저장소에만 있다([19.2](#192-토큰-중계-115)).
4. 아래 **에이전트 MCP 연결**에서 그 폴더(`<프로젝트 이름>-owner`)의 **연결 확인**, **설정 쓰기**, **열기**, **명령 복사**를 쓴다.
5. 연결되면 에이전트에 "작업 세션을 시작한다"라고 입력한다. 규칙 파일은 리더용이다. 승인과 반려는 리더(사람)가 시킬 때만 한다.

- 토큰은 90일 뒤 만료된다. **토큰 새로 만들기**를 누르면 이전 토큰은 끊기고 폴더 파일이 새 토큰으로 바뀐다. **토큰 끊기**를 누르면 즉시 끊긴다.
- **다른 PC에서 리더 에이전트 쓰기:** 프로젝트 화면 멤버 목록의 내 줄에서 **내 토큰 받기**를 누르면 새 토큰의 연결 링크가 한 번 보인다(이전 리더 토큰과 에이전트 토큰은 끊긴다). 다른 PC의 앱 **설정 → 토큰 등록**에 붙여 넣는다. 자세한 내용은 [19.1](#191-다른-pc에서-같은-프로젝트-쓰기)을 본다.
- 리더 로그인(닉네임, 비밀번호)과 리더 토큰은 바뀌지 않는다. 프로젝트 토큰을 재발급하거나 리더를 폐기하면 에이전트 토큰도 끊긴다.
- 실서버 시험에서 리더 에이전트(Claude Code, Codex)가 이 연결로 질문에 답하고 제출에 의견을 썼다.

#### 16.7 백업과 복원
- 백업 zip에는 `room.db` 등과 함께 **파일 탭 원본**(묶음)이 들어간다.
- 백업 zip 안의 `README_복원.txt`가 복원 방법이다. 그 파일을 따른다.
- 요약: `git clone --mirror origin.bundle files/origin.git`을 실행하고 `files_state.json`을 원본 폴더 옆에 둔다.
- zip에 비밀값이 있다. 다른 곳에 두고 쓴 뒤 지운다.

#### 16.8 도움말 모드
앱 화면과 프로젝트 화면의 단추가 무엇을 하는지 모를 때 쓴다.
1. 설정 화면이나 프로젝트 화면의 **[도움말]**을 누른다. 도움말 모드가 켜진다.
2. 알고 싶은 단추나 칸을 누른다. 원래 동작은 하지 않고 설명 칸이 열린다.
3. 설명 칸에서 기능, 쓰는 때, 명령어, 이 책의 해당 절을 읽는다.
4. **닫기**(또는 Esc)로 설명 칸을 닫는다.
5. **도움말 끄기**를 눌러 원래대로 돌아간다.
- 설명이 있는 항목은 46개다. 키보드로는 Tab으로 항목을 고르고 Enter로 연다.

#### 16.9 Orca 봇 연결 (1.1.15)
이 PC에 Orca가 있으면 Orca 봇이 프로젝트의 일 · 채팅 도구를 쓴다. 들어온 프로젝트와, 내가 연 프로젝트의 리더 에이전트 둘 다 된다.

**준비:** Node.js(npx)가 필요하다. 봇은 Orca에서 먼저 만든다.
1. 앱 **설정**을 연다.
2. 리더 프로젝트는 **에이전트 연결 만들기**를 먼저 누른다([16.6](#166-리더-에이전트-연결)). 그 프로젝트 줄 아래에 **Orca 봇** 줄이 생긴다. 들어온 프로젝트는 같은 프로젝트 칸의 **더 보기**에 있다.
3. 봇을 고르고 **Orca 봇 연결**을 누른다.
4. **봇 역할 고르기**에서 역할을 고른다.
5. **봇 지시문 복사**를 누르고, 봇 채팅에 붙여 넣는다.

| 봇 역할 | 하는 일 |
|---|---|
| 일 처리 · 질문 답변 | 일을 맡고 처리한다. 채팅에서 `@`로 부른 질문에 답한다(DM은 읽지 않는다) |
| 검토 (일 + 프로젝트 전체) | 제출 검토와 프로젝트 전체 검토. 리더용이다 |
| 진행 관리 | 독촉, 주간 요약, 계획서 초안. 리더용이다 |
| 학습 PC 배정 | 채널 이름(한글 · 영문 · 숫자 · `-` · `_`, 1~20자)과 규칙 문서 경로를 입력한다. 규칙이 없거나 모호하면 배정하지 않고 사람에게 묻는다 |

**리더 에이전트: 무인 도우미와 Orca 봇 중 하나만**
- 리더 프로젝트의 **Orca 봇** 줄에서 **리더 에이전트**를 고른다. 기본은 무인 도우미다. 서버가 고르지 않은 쪽의 검토를 거부한다.
- **무인 도우미 모드:** 봇은 의견과 1차 반려까지만 한다.
- **Orca 봇 모드:** 봇이 1차 통과와 에이전트 최종 검토도 한다. 모델 · 노력을 서버가 확인할 수 없어서 "약한 검토"로 표시된다. 최종 검토는 사람이 [에이전트 최종 검토]와 비밀번호로 일 1건(30분, 1번)을 허가해야 한다([13.5](#135-에이전트-최종-검토)).
- 리더 에이전트를 바꾸면 이전에 낸 허가는 무효가 된다. 봇은 사람 전용 결정(승인 · 반려 등)을 하지 못한다.

**봇 TF (1.2.0, 기본 꺼짐)**
- Orca 봇이 리더 일을 TF(임무 묶음) 단위로 한다. 리더 TF는 3개다: 학습 PC · 접수(조율) · 검토 의견 모드. 켜기 전에는 기존 동작이 바뀌지 않는다.
- 앱에서 TF를 켤 때 확인 상자가 뜬다.
- **접수 TF**는 사전 검사를 먼저 한다. 새 결정 요청 · 질문 · 제출이 없으면 모델을 부르지 않는다.
- **검토 의견 모드**(서버 설정 `review_mode`)는 리더 에이전트가 Orca일 때만 적용된다.
- 허용 규칙 문서(`doc_read`)의 경로를 늘릴 수 있다.
- 봇 TF가 멈추거나 오류가 나면 트레이에 "TF 문제" 알림이 온다. 비용은 Orca가 알려 주지 않아 오늘 모델 실행 횟수만 보인다.
- 한계: 봇 TF의 도구 제한은 지시문 수준이다. 서버가 강제하지 않는다. 실제 Orca에서의 주기 깨우기 · 사전 검사 결과 전달 · 결과 카드 위치는 사람 시험 전이다 (미확인).

- 봇에는 프로젝트 토큰이 아니라 중계 토큰만 넘긴다. 이 토큰은 이 PC에서만 쓸모 있다. 프로젝트의 **토큰 끊기**로 무효로 할 수 있다.
- 벗 앱이 켜져 있어야 봇이 프로젝트에 연결할 수 있다.
- 봇은 일이 배정된 즉시가 아니라 정해 둔 주기나 채팅으로 깨어난다.
- 리더 봇의 행동은 리더 이름으로 기록된다. 같은 폴더의 무인 도우미와 봇을 함께 켜지 않는다.
- 한계: 일 제출, 주기 실행으로 스스로 깨어나기, 허가 직후 봇 깨우기는 확인하지 못했다 (미확인). Orca 봇 모드에서는 같은 봇이 1차 통과와 최종 검토를 한다. 서로 다른 모델이라는 보장이 없다. 마지막 방어선은 사람의 허가(비밀번호)다.

#### 16.10 트레이 알림
창을 닫아도 트레이가 Windows 알림을 보낸다(1.1.13).
- **알림 종류:** 결정 요청, 검토 대기, 1차 통과, 마감, 프로젝트 밖 변경, 1차 결과 없음, 프로젝트 서버 꺼짐, 다시 켜짐.
- 1분에 10건을 넘으면 묶어서 1건으로 보낸다.
- 프로필에 로그인하기 전이면 트레이 아이콘에 "로그인 필요"가 보인다.
- 팀원 PC는 작업 폴더의 프로젝트에서 내게 온 알림을 로그인 없이 받는다. 팀원 PC도 올려야 한다.
- 알림을 눌러도 앱 창이 열리지 않을 수 있다. 벗 아이콘을 눌러 연다.

#### 16.11 외부 연결 (1.1.16)
리더가 이 PC의 외부 프로그램(예: 학습 관제 화면)을 연결로 등록한다. 그러면 프로젝트의 모든 멤버가 레일의 **외부 연결**에서 그 프로그램의 상태를 본다. 보기만 한다. 쓰는 단추는 없다. 연결된 프로그램은 연결 규약 `beot.view/1`(설계 V)의 페이지를 주어야 한다.

**주의:** 연결 토큰에는 그 프로그램의 **보기용 토큰**만 넣는다. 모든 API를 쓰는 토큰을 넣지 않는다. 토큰 값을 채팅 · 파일에 쓰지 않는다.

**켜는 순서 (같은 PC)**
1. 보기용 토큰을 만든다: `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
2. 1번의 값을 그 프로그램의 보기용 토큰 환경 변수(Windows 사용자 환경 변수)에 넣는다. 예: 아우라지는 `AURAJI_WEB_VIEW_TOKEN`이다.
3. 새 PowerShell 창을 연다. 이유: 이미 열린 창은 새 환경 변수를 읽지 않는다.
4. 3번의 창에서 연결할 프로그램을 켠다. 예: `auraji web`.
5. 다른 PowerShell 창에서 연결을 등록한다: `beot start --room <프로젝트> --connect <연결 이름>`. 연결 이름은 영문 소문자 · 숫자 16자까지다. 프로젝트가 켜져 있어도 된다.
6. 접속 주소를 넣는다(예: 아우라지는 `http://127.0.0.1:8765/api`). `127.0.0.1` 또는 Tailscale 주소(`100.64.0.0/10`)와 포트만 받는다.
7. 시작 경로를 넣는다(예: `loops`).
8. 제목을 넣는다. 빈 값이면 연결 이름을 쓴다.
9. 숨김 입력에 1번의 값을 넣는다.
10. 프로젝트를 끈다: `beot start --room <프로젝트> --stop`.
11. 프로젝트를 켠다: `beot start --room <프로젝트>`. 벗은 연결 토큰을 Windows 사용자 환경 변수에서 바로 읽으므로 새 창이 필요 없다.
12. 역할이 `viewer`인 멤버의 계정으로 프로젝트에 들어간다.
13. 레일의 **외부 연결** 단추를 누른다.
14. 연결 탭에 첫 페이지가 보이는지 본다.
15. 쓰는 요청의 단추가 없는지 본다.
16. 프로젝트 서버 로그(`server.log`)에 "연결 토큰 · 범위 · 접속 주소 중 하나가 맞지 않는다"나 "전체 토큰일 수 있다"가 없는지 본다.

**끄는 순서**
1. `beot start --room <프로젝트> --connect-off <연결 이름>`을 실행한다. 이 명령은 연결 토큰도 빈 값으로 저장한다.
2. 프로젝트를 끈다: `beot start --room <프로젝트> --stop`. 이유: 켜진 프로젝트 서버는 연결을 메모리에 쥐고 있다.
3. 프로젝트를 켠다: `beot start --room <프로젝트>`.
4. 연결한 프로그램의 보기용 토큰 환경 변수를 지운다.
5. 연결한 프로그램을 끈다. 이유: 켜진 프로그램은 보기용 토큰을 메모리에 쥐고 있다.
6. 새 PowerShell 창을 연다.
7. 6번의 창에서 그 프로그램을 다시 켠다.

- 다른 PC의 프로그램을 잇는 순서는 아직 적지 않는다.
- 외부 연결 화면의 그리기는 자동 시험이 없다. 아래의 수동 확인으로 본다.

**수동 확인 (가짜 연결 서버, 개발자용)**
1. `tests\fixtures\beot_view_1` 폴더를 복사한다. 복사본의 `loop.json`에서 "반복" 표 한 칸에 `img` 태그와 `onerror` 속성으로 경고 창을 띄우는 글(`img src=x onerror=alert(1)`을 꺾쇠 괄호로 감싼 것)을 넣는다.
2. 복사본의 `now`를 확인하는 날의 앞 시각으로 고친다. 목적: 화면의 경과 시간 글(`ago`)이 `now`가 아니라 받은 시각에서 재는지 본다.
3. 가짜 연결 서버를 켠다: `python tools\fake_connect.py --port 8766 --token <16자 이상 임의 값> --dir <복사본>`.
4. 연결을 등록한다: `beot start --room <프로젝트> --connect fake`. 접속 주소 `http://127.0.0.1:8766`, 시작 경로 `loops`, 3번의 토큰을 넣는다.
5. 프로젝트를 끈다: `beot start --room <프로젝트> --stop`.
6. 프로젝트를 켠다: `beot start --room <프로젝트>`.
7. 벗 화면에서 외부 연결을 연다.
8. 루프 목록이 보이는지 본다.
9. `L1` 행을 누른다.
10. 고친 칸이 글자 그대로 보이는지 본다.
11. 경고 창이 뜨지 않는지 본다.
12. 곡선과 기준선이 보이는지 본다.
13. 받은 시각이 지금 시각이고 자료 시각과 다른지 본다. 경과 시간 글은 24번에서 본다.
14. "처음으로"를 누른다.
15. 루프 목록이 보이는지 본다.
16. 복사본의 `loop.json`에 `"partial": true`를 넣는다.
17. 5초 기다린다.
18. "일부 자료를 읽지 못했다"가 보이는지 본다.
19. 복사본의 `loop.json`에 `"type": "chart"`인 블록을 더한다.
20. 5초 기다린다.
21. "그리지 못한 블록"이 보이고 다른 블록은 그려지는지 본다.
22. 가짜 연결 서버를 끈다.
23. 1분 넘게 기다린다.
24. "1분 전 자료, 지금은 받지 못했다"가 보이는지 본다. "1일 전"이 보이면 받은 시각이 아니라 자료 시각에서 잰 것이다.
25. `beot start --room <프로젝트> --connect-off fake`를 실행하고 프로젝트를 끄고 켠다.

### 17장 프로젝트 서버 수동 실행

앱이나 `start` 대신 프로젝트 서버를 직접 켤 때(예: 같은 네트워크(LAN)에서 시험할 때) 쓴다. 서버장 구조에서 밖으로 접속하는 프로젝트는 [10장](#10장-프로젝트-만들기와-켜기)을 쓴다. 외부 접속은 [8장](#8장-터널-수동-설정)을 본다. GitHub 방식 프로젝트는 [11장](#11장-github-방식-준비)을 따른다. 그 경우 아래 17.1의 2~3번 대신 11.4~11.5를 한다.

> **표시:** (확인) = 시험으로 확인한 형태. (미확인) = 형태는 맞지만 그대로 입력해 시험하지 않았다. 아래 PowerShell 명령은 예전에 Git Bash로 시험한 환경 변수와 명령을 PowerShell 문법으로 옮긴 것이다.

#### 17.0 용어
- **프로젝트 서버:** `python -m beot server serve`. 일 목록, 규칙, 화면을 담당한다. 포트 8780.
- **git 원본:** 로컬 보관 방식(`ROOM_GIT=local`)에서는 이 PC의 bare git(`origin.git`)이다. 프로젝트 서버가 프로젝트 주소의 `/git`으로 중계한다(포트는 프로젝트 서버 하나). GitHub 방식에서는 GitHub 저장소다.
- **로그인 토큰:** 리더가 프로젝트 화면에 들어가는 값(서버장이 준 리더 토큰 `bh_…`와 다르다). `xxxx-xxxx-xxxx-xxxx-xxxx` 꼴. 처음 한 번만 출력된다.
- **닉네임·비밀번호:** 프로젝트 화면 로그인의 기본 방법. 프로젝트 서버에는 확인값만 있다. 잃으면 팀원은 리더의 재설정 코드, 리더는 `python -m beot server set-password <이름>`으로 바꾼다. 토큰은 비상용과 에이전트용으로 그대로 쓴다.

#### 17.1 처음 한 번 (프로젝트 만들기)
1. 벗 소스 폴더(`Beot`)에서 Python 가상 환경을 만들고 패키지를 설치한다. 아래 명령은 모두 이 폴더에서 실행한다.
```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install "mcp<2" cryptography
```
2. 새 PowerShell 창을 연다. 환경 변수를 정한다. `<LAN 주소>`는 이 PC의 주소다. git이 설치돼 있어야 한다. (미확인: 로컬 보관 방식의 이 입력 형태)
```powershell
$env:ROOM_DB = "$PWD\room.db"
$env:ROOM_GIT = "local"
$env:ROOM_PUBLIC_URL = "http://<LAN 주소>:8780"
```
3. git 원본 저장소를 만든다. 여러 번 실행해도 된다. (미확인)
```powershell
.\.venv\Scripts\python -m beot server setup-git
```
4. 프로젝트와 리더를 만든다. 출력된 로그인 토큰을 안전한 곳에 둔다. (확인)
```powershell
.\.venv\Scripts\python -m beot server init --owner alice
```
5. 프로젝트 서버를 켠다. 창을 닫지 않는다. (확인)
```powershell
.\.venv\Scripts\python -m beot server serve --host 0.0.0.0 --port 8780
```
6. 브라우저에서 `http://<LAN 주소>:8780/ui`를 연다. 로그인 토큰으로 로그인한다. (확인)
7. 다른 PC가 접속하지 못하면 Windows 방화벽이 막은 것이다. 이 설정은 리더가 직접 한다. (미확인) 관리자 PowerShell에서 같은 서브넷만 허용하는 규칙을 만든다.
```powershell
New-NetFirewallRule -DisplayName "Beot" -Direction Inbound -Protocol TCP -LocalPort 8780 -Action Allow -RemoteAddress LocalSubnet
```

[11.6](#116-프로젝트-만들기와-팀원-초대)의 "프로젝트 서버를 켠다"는 이 절의 5번이다.

#### 17.2 평소에 켜기와 끄기
1. 새 창에서 17.1의 2번 환경 변수를 정한다.
2. 프로젝트 서버를 켠다(17.1의 5번). 데이터는 그대로 남는다. (확인: 서버만 다시 켜도 일과 멤버가 유지됐다)
3. 끄려면 프로젝트 서버 창에서 `Ctrl+C`를 누른다.

#### 17.3 명령줄로 팀원 초대
화면에서 하는 방법은 [12.1](#121-팀원-초대)이다. 화면에서 팀원을 추가하려면 프로젝트 서버에 `ROOM_PUBLIC_URL`과 `ROOM_GIT_URL`이 정해져 있어야 한다. 화면의 "팀원 추가"는 이름과 역할을 정하면 초대 코드와 안내문이 나온다. (확인)

명령줄:
1. 팀원을 만들고 초대 코드를 받는다. (확인)
```powershell
.\.venv\Scripts\python -m beot server add-member bob --role member
```
2. 팀원에게 **초대 코드, 프로젝트 주소, `join.py` 파일** 세 가지를 전달한다. 코드는 24시간 안에 한 번만 쓸 수 있다.
3. 팀원이 `python join.py --room <프로젝트 주소> --run claude`를 실행한다.
4. 화면의 멤버 목록에서 접속을 확인한다.

코드를 잃었거나 `join`이 실패했을 때: (확인)
```powershell
.\.venv\Scripts\python -m beot server reinvite bob
```
- 새 프로젝트 토큰과 새 초대 코드가 나온다. 옛 프로젝트 토큰은 무효가 된다.
- 화면의 "코드 다시 받기"도 같다. 코드 창을 닫으면 코드를 다시 볼 수 없다. 창에서 "안내문 복사"를 눌러 팀원에게 보낸다.
- 내보내려면 멤버 줄의 "내보내기"를 누른다. 내보낸 멤버는 "다시 초대"로 되돌린다.
- 보기 전용 멤버는 코드 대신 프로젝트 토큰을 받는다. 브라우저에서 프로젝트 토큰으로 들어온다.
- DB와 백업에는 초대 정보가 암호문으로만 남는다(코드를 모르면 읽을 수 없다).
- 운영 명령(`revoke`, `rotate`, `backup`)은 [15.2](#152-프로젝트-서버-수동-실행-때의-운영-명령)에 있다.

### 이 부의 요약
- 리더는 서버장에게 받은 리더 토큰으로 입구 웹(프로젝트 만들기)이나 앱에서 프로젝트를 만들고, `python -m beot start`로 켠다.
- 프로젝트는 백그라운드로 돈다. 끄기는 프로젝트 코드가 남고, 닫기는 프로젝트 코드와 주소가 사라진다(데이터는 PC에 남는다).
- 팀원 초대는 멤버 구역의 "팀원 추가"로 한다. 안내문은 멤버마다 따로 보낸다. 초대 코드는 24시간 안에 한 번만 쓴다.
- 승인은 리더만 한다. 보호 파일 경고가 있으면 파일 내용을 직접 읽는다.
- GitHub 방식은 공개 저장소다. 규칙 세트 2개가 Active인지 확인한다. 비공개가 필요하면 로컬 보관 방식을 쓴다.
- 계획서(`벗/계획서.md`)가 일 목록의 원본이다. 모든 일에 [키]가 있어야 한다.
- 외부 연결(1.1.16)은 `beot start --room <프로젝트> --connect <연결 이름>`으로 등록한다. 멤버는 레일의 **외부 연결**에서 보기만 한다([16.11](#1611-외부-연결-1116)).
- 백업 zip에는 비밀값이 있다. 쓴 뒤 지운다.

## 4부 팀원

> **경고:** 초대 코드와 프로젝트 토큰은 채팅, 파일, 화면 공유에 남기지 않는다.

### 18장 프로젝트에 들어가기

팀원은 프로젝트에서 일을 맡고, 자기 가지에서 작업하고, 제출한다. 리더만 승인하고 합친다.

#### 18.1 준비
1. git을 설치한다. `join.py`를 쓸 때는 Python 3도 설치한다. 벗 프로그램 `beot.exe`만 쓰면 Python은 필요 없다.
2. Claude 또는 Codex를 설치하고 로그인한다.
3. 리더에게서 안내문(**입구 주소, 프로젝트 코드, 초대 코드**)을 받는다. 명령으로 들어가려면 `join.py` 파일도 받는다(리더 또는 릴리스에서 받는다). `beot.exe`를 쓰면 `join.py`는 필요 없다.
4. GitHub 방식 프로젝트면 본인 GitHub 계정이 필요하다. 리더에게 GitHub 사용자 이름을 알려 준다.

#### 18.2 앱으로 들어가기 (추천)
1. `beot.exe`를 열고 프로필(닉네임, 비밀번호 8자 이상)을 만든다([3.2](#32-프로필과-로그인)).
2. **기존 입구로 들어가기**를 연다.
3. **리더에게 받은 안내문 붙여 넣기** 칸에 안내문 전체를 붙여 넣는다. 입구 주소, 프로젝트 코드, 초대 코드 칸이 채워진다. 새 형식과 옛 형식의 안내문을 모두 읽는다. 안내문은 어디에도 보내지 않는다. 칸에 직접 넣어도 된다.
4. **들어가기**를 누른다. 몇 분 걸릴 수 있다.
5. 프로젝트의 닉네임과 프로젝트 비밀번호는 프로필 값으로 자동으로 정해진다. 프로젝트에 같은 닉네임이 있으면 리더가 정한 이름을 쓴다.
6. **들어온 프로젝트 → 프로젝트 화면 열기**가 프로젝트 화면을 **앱 창에서** 연다(주소가 `https://r-…`인 프로젝트). 화면 위의 **설정**에서 에이전트 MCP 연결을 한다([21장](#21장-에이전트에-프로젝트-연결하기)). 로그인 없이 열린다.
7. 들어온 뒤 **새로 들어온 프로젝트의 무인 도우미 켜기** 카드가 나온다. 누르면 무인 도우미가 내 일을 처리한다([23.3](#233-무인-도우미)). 켜지 않아도 된다.

- git이 없으면 앱이 알린다. PowerShell에서 `winget install --id Git.Git -e`로 설치하고 앱을 다시 켠다.
- 앱의 프로젝트 화면은 프로필 비밀번호로 로그인한다. 예전의 로그인 티켓은 없어졌다.
- **주의:** 프로필 비밀번호는 계정과 프로젝트 비밀번호에 같은 값으로 쓰인다. 한쪽이 새면 다른 쪽도 위험하다. 따로 쓰려면 앱 입력 칸에 다른 비밀번호를 직접 넣고, 프로젝트 화면에서 프로젝트 비밀번호를 바꾼다.
- **GitHub 방식 프로젝트면** 먼저 GitHub 초대를 수락해야 한다. 리더의 안내문을 따른다. `join`이 "초대를 수락한다"라고 안내해도 이미 수락했으면 무시한다.

#### 18.3 명령으로 들어가기
1. PowerShell을 연다.
2. `join.py`가 있는 폴더로 이동한다.
3. 다음을 실행한다. `example.com`을 받은 입구 주소로 바꾼다.
```powershell
python join.py --server example.com
```
4. **프로젝트 코드**를 묻는다. 입력한다(예: `amber-river-moss-123`). 프로젝트 코드는 비밀번호가 아니다.
5. **초대 코드**를 묻는다. 붙여 넣는다. 입력이 보이지 않는다. 24시간 안에 한 번만 쓸 수 있다.
6. **비밀번호**를 정한다(8자 이상, 두 번 입력한다, 입력이 보이지 않는다). 초대 코드와 함께 프로젝트 서버에 낸다. 비워 둘 수 없다. 비밀번호는 프로젝트 서버에 암호화된 값으로만 남고 이 PC에는 저장하지 않는다.
7. **닉네임**을 묻는다. 엔터를 누르면 리더가 정한 이름을 쓴다. 다른 이름을 쓰려면 지금 입력한다(처음 한 번만 바꿀 수 있다).
8. 끝나면 작업 폴더가 생기고 **브라우저가 프로젝트 화면을 자동으로 연다(로그인도 자동).** 작업 폴더는 `C:\Users\<내 이름>\Beot\<프로젝트 이름>`이다(프로젝트 이름은 리더가 정한다). 자동으로 열지 않으려면 `--no-browser`를 붙인다.

- 벗 프로그램(`beot.exe`)을 받았다면 `join.py` 대신 같은 옵션으로 `beot join --server example.com`을 실행한다. 이 장과 20장의 `python join.py …` 명령은 모두 `beot join …`으로 바꿔 쓸 수 있다.
- **입장은 사람이 직접 한다.** 터미널이 아닌 실행(스크립트, 에이전트)은 입장하지 못한다.
- **다른 서비스와 같은 비밀번호를 쓰지 않는다.** 리더는 프로젝트 서버에서 내가 로그인할 때의 비밀번호 원문을 받을 수 있다.
- 프로젝트 코드와 초대 코드를 미리 정해 두려면 환경 변수 `BEOT_ROOM_CODE`, `BEOT_INVITE`를 쓸 수 있다.
- 리더가 프로젝트 주소(`https://r-….도메인`)를 직접 알려 주면 `python join.py --room <프로젝트 주소>`도 된다.
- 한 번 들어온 PC는 기억한다. 다음부터 코드를 다시 받지 않는다.
- **Claude가 아닌 에이전트도 쓸 수 있다.** `--run 에이전트이름`을 붙이면 그 에이전트를 작업 폴더에서 연다(예: `--run codex`, `--run gemini`, `--run opencode`). 이름은 이 PC에 설치된 실행 파일 이름이다. Claude와 Codex가 아니면 시작 문장을 대신 넣지 않으므로, 열린 에이전트에 "작업 세션을 시작한다"라고 입력한다. 에이전트가 프로젝트 설정(`.mcp.json`, `AGENTS.md` 등)을 읽는지는 에이전트마다 다르다. 앱별 설정 파일은 `--apps`로 더 만든다.

#### 18.4 프로젝트 화면 다시 열기와 비밀번호
- 브라우저로 `https://<입구 주소>`를 열고 프로젝트 코드를 넣는다. 프로젝트 화면에서 **닉네임과 비밀번호**로 들어간다.
- 비밀번호가 없으면 PC에서 `python join.py --open`으로 연다(이 PC에 저장된 프로젝트 토큰으로 들어간다. 사람만 하는 동작은 이 화면에서 비밀번호를 묻는다). 화면 위의 배너에서 비밀번호를 정한다.
- 비밀번호를 잃으면 리더에게 **재설정 코드**를 받는다. 로그인 화면의 "다른 방법으로 들어가기"에 닉네임, 코드, 새 비밀번호를 넣는다(코드는 24시간 안에 한 번만 쓴다).
- 터미널의 `join`은 프로젝트 화면을 브라우저로 연다. 열지 않으려면 `--no-browser`를 붙인다.

### 19장 다른 PC 사용과 토큰 중계

#### 19.1 다른 PC에서 같은 프로젝트 쓰기
토큰 등록 절차다.
1. 처음 쓴 PC의 프로젝트 화면에서 멤버 목록의 내 줄에 있는 **내 토큰 받기**를 누른다. 확인하면 새 토큰의 **연결 링크**가 한 번만 보인다. **이전 토큰과 다른 PC의 로그인은 모두 끊긴다.**
2. 링크를 다른 PC에 안전하게 옮긴다(채팅이나 공개 글에 남기지 않는다).
3. 그 PC의 벗 앱에서 **설정 → 토큰 등록**에 링크를 붙여 넣고 **등록**을 누른다.
   - 프로젝트에 접속해 확인한 뒤 토큰을 이 PC의 토큰 저장소에 넣는다.
   - `Beot\<프로젝트>-agent` 작업 폴더에 에이전트 연결 파일(토큰 중계 주소)을 쓴다.
   - 열려 있던 터미널과 에이전트는 다시 연다.
- 이 연결은 프로젝트 화면과 에이전트용이다. 코드 제출(git push)은 `join`으로 들어온 PC의 작업 폴더에서 한다.
- 1.1.4까지는 토큰을 사용자 환경 변수(`BEOT_ROOM_TOKEN_<프로젝트>`)에 저장했다. 1.1.5 앱은 켤 때 이 변수를 지운다. 토큰이 새었을 수 있으면 **내 토큰 받기**로 새로 받아 이전 토큰을 끊는다.

#### 19.2 토큰 중계 1.1.5
에이전트는 프로젝트 토큰을 보지 않는다.
- 프로젝트 토큰은 이 PC의 토큰 저장소(`%LOCALAPPDATA%\Beot\tokens.json`, Windows 사용자 암호화)에만 있다.
- 작업 폴더의 연결 파일(`.mcp.json` 등)과 `.git\beot\env.ps1`에는 **중계 주소**(`http://127.0.0.1:47811/r/<폴더 번호>/mcp`)와 **중계 토큰**(`bp_…`, 토큰 중계가 내주는 이 PC 전용 토큰)만 있다. 중계 토큰은 이 PC 안에서만 쓸모가 있다.
- 벗 앱이 켜질 때 토큰 중계(`beot proxy`)를 함께 켠다. 토큰 중계는 이 PC에 프로세스 1개로 늘 돈다. 토큰 중계가 꺼지면 에이전트의 프로젝트 연결만 끊긴다. 벗 앱을 다시 켜면 돌아온다.
- 1.1.4에서 만든 작업 폴더는 1.1.5 앱을 처음 켤 때 저절로 옮겨진다. 직접 고친 연결 파일은 그대로 두고 앱이 1번 알린다. 그 파일은 지우고 **설정 쓰기**로 다시 만든다.
- 옮기기 전에 퍼진 옛 토큰(복사한 명령, 다른 앱의 설정)은 아직 쓸 수 있다. 프로젝트 화면의 **내 토큰 받기**로 새로 받으면 끊긴다.
- **경고:** 다른 프로그램이 47811 포트를 쓰면 토큰 중계가 켜지지 않고 앱이 알린다. 그 프로그램을 끄고 벗 앱을 다시 켠다.

### 20장 일 시작 제출 반려

#### 20.1 일 시작
1. 프로젝트 화면(리더가 알려 준 프로젝트 주소 뒤에 `/ui`)에서 내 일의 번호를 본다.
2. 다음을 실행한다. `<번호>`를 바꾼다.
```powershell
python join.py --start <번호>
```
3. 이 명령은 세 가지를 한다.
   - 규칙에 맞는 가지 이름을 만든다(`member/<내 이름>/…`).
   - 이 일 전용 작업 폴더를 만든다. 작업 폴더는 git으로 만든다.
   - 프로젝트에서 이 일을 맡는다.
4. 출력된 **작업 폴더**로 이동한다.
5. 에이전트를 바로 열려면 `--run claude` 또는 `--run codex`를 붙인다.
```powershell
python join.py --start <번호> --run claude
```

#### 20.2 작업하고 제출하기
1. 작업 폴더에서 에이전트에게 일을 시킨다.
2. 에이전트가 파일을 고치고 push한다.
3. 에이전트가 `task_submit`으로 제출한다. 제출하면 PR이 생긴다.
4. 제출한 뒤 PR 링크를 받으려면 다음을 실행한다.
```powershell
python join.py --link <번호>
```
- 선행 일이 있으면 앞선 일이 승인될 때까지 시작하지 못한다.

#### 20.3 반려되면
1. 프로젝트 화면에서 반려 사유를 읽는다.
2. `python join.py --start <번호>`를 다시 실행한다. 같은 가지로 이어 간다.
3. 고치고 다시 제출한다.

### 21장 에이전트에 프로젝트 연결하기

#### 21.1 앱의 설정에서 연결하기 (가장 쉽다)
1. 앱(`beot.exe`)을 열고 로그인한다. 홈 위쪽의 **계정 <닉네임>**(프로필)을 누른다. **설정**이 열린다.
2. **에이전트 MCP 연결**에서 들어온 프로젝트를 찾는다. **연결 확인**을 누르면 프로젝트 서버와 내 토큰이 맞는지 알려 준다.
3. 쓰는 에이전트 줄에서 **설정 쓰기**를 누른다. 그 에이전트가 읽는 프로젝트 설정 파일이 작업 폴더에 만들어진다(이미 있으면 그대로 둔다).
4. Claude Code, Codex, Gemini CLI는 **열기**를 누르면 작업 폴더에서 새 터미널 창으로 열린다. 연결되면 에이전트에 "작업 세션을 시작한다"라고 입력한다. Cursor와 VS Code는 그 프로그램에서 작업 폴더를 연다.
5. 손으로 하려면 **명령 복사**를 쓴다. 복사한 명령의 `<중계 토큰>`은 작업 폴더의 `.mcp.json`에 있는 값으로 바꾼다. 중계 토큰은 화면에 보이지 않는다.
- **채팅 붙여넣기:** **설정 → 에이전트 MCP 연결**의 **채팅용 문구 복사**를 누르면 연결 명령(중계 토큰 포함)이 복사된다. 에이전트 채팅창에 붙여 넣으면 에이전트가 실행한다. 실행한 뒤 Claude Code를 다시 연다. **중계 토큰이 대화 기록에 남으므로 믿는 에이전트 대화에만 붙여 넣는다.**

**Orca 봇을 붙이기(1.1.15):** 이 PC에 Orca가 있으면 같은 프로젝트 칸의 **더 보기**에 **Orca 봇** 줄이 있다. 봇을 고르고 **Orca 봇 연결**을 누른다. 자세한 절차는 [16.9](#169-orca-봇-연결-1115)를 본다.

**Notion을 에이전트에 연결하기:** 설정의 **Notion MCP**에서 **Claude Code에 Notion 추가**를 누른다. 그다음 Claude Code를 열고 `/mcp`에서 notion을 골라 Notion에 로그인한다. 로그인과 권한 허용은 직접 한다. 벗은 Notion 토큰을 다루지 않는다. 다른 에이전트는 **주소 복사**의 주소(유형 `http`)를 그 에이전트의 MCP 설정에 넣는다.

#### 21.2 터미널에서 연결 안내 보기
`join`은 끝난 뒤 연결 안내를 출력하지 않는다. 터미널에서 안내를 보려면 아래를 실행한다. `<내 작업 폴더>`를 바꾼다.
```powershell
python join.py --mcp --dest "<내 작업 폴더>"
```
**연결 값은 글로 보여 주지 않는다.** 1.1.5 작업 폴더의 `.mcp.json`에는 중계 주소와 중계 토큰이 있다([19.2](#192-토큰-중계-115)). 아래의 `<프로젝트 주소>/mcp`는 중계 주소로, `<프로젝트 토큰>`은 중계 토큰으로 읽는다. 정확한 값은 `--mcp` 출력에 있다.

1. **Claude Code (가장 쉽다):** 작업 폴더에서 연다. `.mcp.json`이 프로젝트를 자동으로 연결한다.
```powershell
cd "<내 작업 폴더>"
claude
```
   연 뒤 `/mcp`를 입력해 `beot`이 `connected`인지 확인한다(작업 폴더 안의 설정 파일은 서버 이름을 `beot`으로 쓴다). 손으로 추가하려면 다음을 쓴다. 이름은 `beot-<프로젝트 이름>`으로 써서 프로젝트가 여럿이어도 겹치지 않게 한다.
```powershell
claude mcp add --transport http beot-<프로젝트 이름> <프로젝트 주소>/mcp --header "Authorization: Bearer <프로젝트 토큰>"
```
2. **Codex:** 작업 폴더에서 토큰 환경 변수를 불러오고 옵션을 붙여 연다. 옵션 전체는 `--mcp` 출력에 있다.
```powershell
. .git\beot\env.ps1
```
3. **Gemini CLI, Cursor, VS Code, Antigravity CLI(agy), Pi:** `join --apps gemini,cursor,vscode,agy,pi`로 설정 파일을 만든다. Pi는 MCP 확장(pi-mcp-adapter)이 `.pi/mcp.json`을 읽는 경우를 기준으로 하며 시험하지 못했다. 그 뒤 작업 폴더에서 연다.
4. **그 밖의 MCP 에이전트:** 주소 `<프로젝트 주소>/mcp`, 유형 `http`, 헤더 `Authorization: Bearer <프로젝트 토큰>`을 그 에이전트의 MCP 설정에 넣는다.

연결되면 에이전트에 "작업 세션을 시작한다"라고 입력한다.

#### 21.3 추가 작업 폴더
프로젝트의 기본 작업 폴더가 아닌 폴더(예: 이 프로젝트를 위한 선작업 프로젝트)에서 일하는 에이전트도 프로젝트에 채팅과 보고를 할 수 있다. 코드는 프로젝트에 올리지 않는다.
1. 앱 **설정 → 에이전트 MCP 연결**에서 프로젝트 아래 **추가 작업 폴더** 줄에 폴더 전체 경로를 넣는다. 섹션 이름은 비우면 폴더 이름이다.
2. 모드를 고른다. **보고 전용**(기본)은 채팅과 보고만 한다. **문서 올리기**는 `docbox_put`으로 문서를 `문서함/<내 이름>/<섹션>/` 아래에 올린다.
3. 에이전트(Claude 등)를 고르고 **추가**를 누른다. 그 폴더에 연결 파일과 규칙 문서가 써진다. 폴더가 git 저장소가 아니어도 된다.
- 이 폴더용 **전용 토큰**(`sc_…`)이 쓰인다. 서버가 채팅 읽기와 쓰기, 프로젝트 검색, 기준 문서 읽기, 멤버와 채널 목록만 허용한다. 일 맡기, 제출, 파일 도구는 거부한다.
- 글 머리에 `[섹션]`이 서버에서 붙는다. 프로젝트 화면에서 배지로 보이고, 멤버 줄에 섹션별 마지막 글 시각이 보인다.
- 목록의 **해제**는 서버의 토큰도 끊는다(폴더 안 파일은 지우지 않는다). **다시 연결**은 새 토큰을 받아 연결 파일을 다시 쓴다.
- 한 프로젝트에 추가 폴더는 10개까지다. Codex는 추가 폴더에 연결할 수 없다.
- 프로젝트 서버가 이 기능 이전 버전이면 "프로젝트 서버가 거부했다"가 나온다. 리더에게 벗 업데이트를 부탁한다.

#### 21.4 터미널에서 쓰는 Codex와 CLI
herdr 같은 터미널에서 쓸 때의 순서다(1.1.11).
1. 작업 폴더에서 CLI(`claude`, `codex`, `agy`)를 **먼저** 켠다.
2. 연결 명령(`/벗 연결`)은 PowerShell 프롬프트가 아니라 **CLI 입력줄**에 쓴다.
- `/벗 연결` 안내는 Codex 앱과 Codex CLI(터미널)를 나눠 말한다.
- **Codex 앱:** automation(10분마다 `벗 확인`)이 세션을 깨운다([23.4](#234-앱-세션으로-같이-일하기)).
- **Codex CLI:** automation이 없다. 사람이 `벗 확인`이라고 쓴다.
- 자리를 비우면 앱 세션 대신 무인 도우미를 켠다([23.3](#233-무인-도우미)).
- 팀원 PC의 앱이 바뀐 안내 글을 작업 폴더에 쓴다. 팀원 PC를 올린다.

### 22장 파일 탭 프로젝트와 문서함

#### 22.1 사본 받기와 완료 제출
리더가 **로컬 보관** 프로젝트를 만들었으면 파일이 리더 PC의 원본에 있다. 같은 명령으로 사본을 받고 제출한다.
1. 일을 맡고 사본을 받는다. `<번호>`를 바꾼다.
```powershell
python join.py --start <번호>
```
2. 출력된 작업 폴더에서 파일을 고친다.
3. 끝나면 **완료**를 한다. `--summary`는 한 줄 설명이다.
```powershell
python join.py --finish <번호> --summary "무엇을 고쳤는지"
```
4. 리더가 검토한다. 승인되면 원본에 합쳐진다. 반려되면 사유를 읽고 `--start`를 다시 실행해 고친 뒤 다시 `--finish` 한다.

- 파일 하나는 50MB 이하여야 한다. 비밀 파일 이름(`.env`, 키 파일)은 올릴 때 경고한다.
- 올리는 곳은 `member/<내 이름>/…` 가지뿐이다. 원본 `main`에는 올릴 수 없다.
- **경고:** 사본은 이 PC에 남는다. 에이전트가 읽은 내용은 그 AI 서비스로 전송된다. 작업이 끝나면 사본 폴더를 지운다.
- 리더 PC가 꺼져 있으면 받기와 제출이 멈춘다.

#### 22.2 문서함에 바로 올리기
정리 문서처럼 일과 상관없는 글은 일을 제출하지 않아도 된다. 내 문서함 `문서함/<내 이름>/`에는 승인 없이 올린다.
1. 프로젝트 화면의 **파일** 탭을 연다.
2. **파일 선택**으로 파일을 고르고 **올리기**를 누른다. 하위 폴더는 **올릴 폴더**에 적는다.
3. 에이전트는 `docbox_put` 도구로 올린다. 글(UTF-8)만 된다.
- 다른 사람의 문서함과 문서함 밖에는 올릴 수 없다. 코드 변경은 일을 제출해서 승인받는다.
- 에이전트 설정 파일(`CLAUDE.md`, `.claude/` 등)은 문서함에도 올릴 수 없다.
- 한 사람의 문서함은 200MB까지다. 모든 팀원이 볼 수 있으니 비밀값은 올리지 않는다.

#### 22.3 검토자가 되면
리더가 [검토 권한]을 주면 화면에 "검토" 메뉴가 생긴다. 다른 사람의 제출물을 승인하거나 반려한다.
- 내가 제출한 일은 승인하거나 반려할 수 없다. 리더나 다른 검토자가 한다.
- 보호 파일(`CLAUDE.md`, `.claude/` 등)을 바꾼 일은 리더가 [보호 파일도 승인]을 줘야 승인한다. 없으면 반려만 한다.

### 23장 새 메시지 받기와 무인 도우미

쉬는 에이전트는 새 글을 모른다. 프로젝트 MCP 도구로 묻기만 해서는 깨지 않는다(시험에서 깨지 않았다). 기본은 무인 도우미다([23.3](#233-무인-도우미)). 무인 도우미를 켜지 않을 때만 23.1의 `beot watch --once`를 쓴다.

> **경고:** 메시지에 비밀값(API 키, 비밀번호, 토큰)을 쓰지 않는다. 메시지는 프로젝트의 모든 사람이 볼 수 있다.

#### 23.1 beot watch 백그라운드 모니터
1. 작업 폴더에서 다음을 실행한다. 새 메시지가 오면 한 줄씩 출력한다.
```powershell
beot watch
```
2. 에이전트의 백그라운드 모니터 기능에 이 명령을 연결한다. 모니터가 출력을 읽고 쉬는 에이전트를 깨운다.
3. 새 소식이 오면 한 번 출력하고 끝내려면 `beot watch --once`를 쓴다(소식이 올 때까지 기다린다). 1번만 깨운다. 출력을 처리한 뒤 `beot watch --once`를 다시 백그라운드로 켠다.
4. 예전에 `join --hooks`를 썼으면 `.claude/settings.local.json`의 `beot watch --poll` 훅을 지워도 된다. 그 훅은 이제 아무것도 하지 않는다.

#### 23.2 결정 요청
- 에이전트는 `decide`에 스스로 답하지 않는다.
- 사람이 프로젝트 화면에서 선택지를 눌러 답한다.

#### 23.3 무인 도우미
새 소식이 오면 에이전트(claude, codex)를 자동으로 1번 실행한다. 앱의 무인 도우미 카드에서 켜거나, 터미널에서 직접 켠다.
```powershell
beot agent --agent claude --room <프로젝트 이름>
```
- 내 일의 계획이 바뀌면("계획 바뀜", "없어진 일" 표지) 무인 도우미가 깨어나 바뀐 내용을 읽는다.
- 계획을 바꾸려면 에이전트가 `벗/` 계획 파일만 고친 가지를 push하고 `plan_propose`를 부른다. 리더가 승인한다. 보통 일의 제출에 계획 파일을 넣으면 거부된다.
- 기본 인증은 내가 설정한 API 키(`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`)다.
- API 키가 없으면 켜지지 않는다(종료 코드 2). 구독 로그인으로 실행하려면 약관 주의를 읽고 **실행할 때마다** `--accept-terms`를 붙인다. 동의는 저장하지 않는다.
- codex는 `OPENAI_API_KEY`가 있어도 실행마다 `--accept-terms`가 있어야 켜진다(키가 있어도 `~/.codex`의 구독 로그인을 쓸 수 있기 때문이다). 예약 작업으로 켜 두었다면 그 명령에도 붙인다.
- 하루 실행은 10번까지다. 횟수 파일은 작업 폴더 밖 `C:\Users\<내 이름>\Beot\.agent\<프로젝트 이름>.json`에 있다.
- 에이전트가 승인 없이 쓰는 벗 명령은 `beot file …`과 `beot watch …`뿐이다. `beot server` 등 관리 명령은 사람이 한다. 더 허용하려면 `--allow "Bash(pytest *)"`처럼 붙인다.
- 기록은 작업 폴더의 `.git\beot\agent.log`에 있다. 끄려면 Ctrl-C를 누른다.
- 구독 한도에 도달하면 무인 도우미는 한도 문구의 다시 시작 시각까지 실행하지 않는다(시각을 못 읽으면 60분). 같은 날 3번째면 멈춘다. 프로젝트의 에이전트 칸에 "한도 도달 · HH:MM에 다시 시작"이 보인다.
- 하루 실행 한도에 도달해도 무인 도우미는 프로젝트 채팅에 글을 올리지 않는다(1.1.15). 무인 도우미 카드의 "한도" 상태와 기록(로그)에만 남는다. 팀원 PC도 1.1.15로 올려야 한다.

**구독 크레딧으로 무인 도우미 쓰기 (Claude만, 1.2.0. 앱 카드는 1.2.2)**
- Claude 구독(Max · Ultra · Team)에는 API 크레딧이 붙는다. Pro는 대상이 아니다. 이 크레딧은 구독에 연결한 Console 조직 1개의 API 사용에만 붙는다. 구독 로그인으로 쓰는 대화형 Claude Code에는 붙지 않는다.
- 무인 도우미는 `claude -p`로 일한다. 그 조직의 API 키를 넣으면 이 크레딧을 쓴다.
1. claude.ai의 Settings > Billing > API credits > Link organization에서 Console 조직을 연결한다(구독 7일 뒤부터 된다).
2. Console에서 그 조직의 API 키를 만든다.
3. Console에서 자동 충전을 끈다.
4. 벗 앱의 설정 > "에이전트 API 키 (이 PC)" 카드를 연다(1.2.2).
5. API 키 칸에 키를 붙여 넣는다. 입력은 보이지 않는다.
6. 월 크레딧을 고른다(Max 100달러 · Ultra 200달러). 월 예산이 90%로 채워진다. Team 등은 "직접 입력"을 고르고 월 예산을 넣는다.
7. 실행 1번 상한(기본 1달러)과 청구일(claude.ai 구독의 청구일)을 확인한다. 모드는 "API 키 모드"로 둔다.
8. [저장]을 누른다. 키 칸이 비고 상태 줄에 "저장한 키: …끝 4자"가 보인다.
9. 에이전트 연결 카드의 [무인 도우미 켜기]를 누른다. 키 모드이면 약관 동의 안내가 뜨지 않는다.
10. 도우미 줄에서 이번 달 추정 사용액을 본다. 실제 잔액은 Console의 Billing · Usage 화면의 "Promotional credits" 항목에서 본다.
- 키와 예산은 이 PC의 Windows 사용자만 푸는 방식(DPAPI)으로 저장한다. 프로젝트 서버로 보내지 않는다. 벗은 키를 출력하지 않는다.
- 이번 달 추정은 이 PC에서 벗이 센 값이다. 실제 청구액과 다를 수 있다. 월 예산에 닿으면 무인 도우미가 멈춘다. 구독으로 자동 전환하지 않는다. 예산이나 상한을 올리고 [저장]한 뒤 [무인 도우미 켜기]를 다시 누른다.
- 키를 바꾸려면 새 키를 붙여 넣고 [저장]한다. 키 칸을 비우고 [저장]하면 키는 두고 예산 · 모드만 바뀐다. 키를 지우려면 [키 지우기]를 누른다(이 키로 켠 무인 도우미도 꺼진다). 키를 이미 다른 곳에 붙였으면 Console에서 키를 폐기한다.
- 구독 로그인으로 돌리려면 모드를 "구독 모드"로 바꾼다. Claude만 API 키 모드가 된다. Codex · Antigravity는 구독 모드만 된다.
- 앱 대신 사용자 환경 변수 `ANTHROPIC_API_KEY`에 키를 두는 옛 방법도 된다. 이 방법은 벗이 비용을 세지 않고 예산으로 멈추지 않는다. 환경 변수를 바꾼 뒤에는 벗 앱을 완전히 끄고 다시 켠다.
- 주의: 키를 채팅 · 문서 · 저장소 · 스크린샷에 붙이지 않는다. Console의 자동 충전을 꺼 두면 월 크레딧을 다 쓴 뒤 다음 달까지 API 요청이 멈춘다. 크레딧은 다음 달로 넘어가지 않는다. 팀원 PC마다 자기 키를 쓴다. Orca 봇의 키 사용은 이 책에서 다루지 않는다.

#### 23.4 앱 세션으로 같이 일하기
내가 Claude, Codex, Antigravity 앱에서 연 세션이 프로젝트의 일을 받는다. 나도 같은 세션에서 같이 일한다. 앱을 닫으면 무인 도우미가 잇는다.
1. 팀원 작업 폴더를 앱에서 연다. 리더 폴더는 연결하지 않는다(리더 폴더는 무인 도우미가 1차 검토를 한다).
2. 세션에 연결 명령을 쓴다. Claude: `/벗 연결`. Codex와 Antigravity: `벗 연결`.
3. 세션이 첫 안내와 구독 주의를 보여 준다. 읽고 "동의"라고 쓴다. 동의는 저장하지 않는다. 새로 연결할 때마다 다시 묻는다.
4. Codex 앱: 그 스레드에 10분마다 `벗 확인`을 하는 automation을 만든다. Codex CLI(터미널)는 automation이 없어 사람이 `벗 확인`이라고 쓴다([21.4](#214-터미널에서-쓰는-codex와-cli)). Antigravity: 확인하려면 `벗 확인`이라고 쓴다.
5. 끊으려면 `/벗 끊기`(Codex와 Antigravity: `벗 끊기`)를 쓴다.
- 한 폴더에 앱 세션은 1개만 연결한다. 한 멤버의 앱 세션은 PC 2대까지 쓴다(대기 요청 상한).
- 연결된 동안 같은 PC 팀원 폴더의 무인 도우미는 쉰다. 앱 칸에 "쉬는 중(앱 세션 연결)"이 보인다.
- 승인, 반려, 재배정, 결정 답은 앱 세션에서도 사람이 프로젝트 화면에서 한다.

| 멈추는 경우 | 프로젝트의 에이전트 칸 | 할 일 |
|---|---|---|
| PC가 잠들거나 꺼짐 | `<기기> · 꺼짐 (마지막 HH:MM)` | PC를 깨운다. 또는 다른 기기에서 `beot take N` |
| 구독 한도 | `<기기> · 한도 도달 · HH:MM에 다시 시작` | 기다린다. 급하면 리더가 재배정한다 |
| Antigravity 앱 세션 | `<기기> · 앱 세션(Antigravity, 늦게 깸)` | 급한 일은 Claude나 Codex 쪽이 맡는다 |
| 앱을 닫음 | 35분 뒤 무인 도우미로 바뀜 | 앱을 다시 켜면 `/벗 연결`을 다시 한다 |

### 이 부의 요약
- 들어가기는 앱의 **기존 입구로 들어가기**에 안내문을 붙여 넣는 방법이 가장 쉽다. 명령은 `python join.py --server example.com`이다.
- 입장은 사람이 직접 한다. 다른 서비스와 같은 비밀번호를 쓰지 않는다.
- 일은 `python join.py --start <번호>`로 시작하고 에이전트가 `task_submit`으로 제출한다. 반려되면 같은 명령으로 이어 간다.
- 1.1.5부터 에이전트는 프로젝트 토큰을 보지 않는다. 중계 주소(`127.0.0.1:47811`)와 중계 토큰만 쓴다.
- 다른 PC에서 쓰려면 프로젝트 화면의 **내 토큰 받기**로 링크를 받아 앱 **설정 → 토큰 등록**에 붙여 넣는다. 이전 토큰은 끊긴다.
- 에이전트 연결은 앱 **설정 → 에이전트 MCP 연결**에서 한다.
- 새 메시지는 무인 도우미(`beot agent`)나 앱 세션(`/벗 연결`)이 받는다.

## 5부 문제 해결과 알려진 한계

### 24장 문제 해결

#### 24.1 서버장 문제
| 증상 | 확인할 것 |
|---|---|
| `Active 상태가 아니다` | 도메인이 Cloudflare에서 Active인지, 토큰의 Zone 범위가 그 도메인인지 |
| `workers.dev 주소가 없다` | `--workers-subdomain 이름`을 붙인다 |
| 입구 응답을 확인하지 못했다 | 몇 분 뒤 `https://도메인/`을 연다. 같은 오류가 계속되면 `setup`을 다시 실행한다 |
| 리더가 "프로젝트 수를 넘었다"고 한다 | 리더가 `python -m beot start --close`로 쓰지 않는 프로젝트를 닫거나, `invite`로 한도를 늘려 새 토큰을 발급한다 |
| 리더가 "리더 토큰이 올바르지 않다"고 한다 | 폐기됐는지(`owner hosts`), 토큰을 끝까지 복사했는지 본다 |
| 팀원이 `join`에서 403(오류 1010) | 프로그램이 최신인지 본다(User-Agent 지정 버전). Bot Fight Mode를 끈다 |
| 앱의 권한 검사에 ✗가 있다 | Cloudflare에서 그 권한을 더한 새 토큰으로 [5.1](#51-설치-절차)의 3번부터 다시 한다 |

#### 24.2 리더 문제
| 증상 | 확인할 것 |
|---|---|
| `입구 오류 401` | 서버장에게 받은 리더 토큰이 맞는지, 폐기되지 않았는지 서버장에게 묻는다 |
| `동시에 열 수 있는 프로젝트 수를 넘었다` | 쓰지 않는 프로젝트를 `python -m beot start --close`로 닫는다. 더 필요하면 서버장에게 한도를 요청한다 |
| `입구가 옛 버전이라 두 번째 이후 프로젝트…` | 서버장이 앱의 **입구 업데이트**를 한 뒤 다시 만든다 |
| `프로젝트 ○○이(가) 이미 켜져 있다(포트 …)` | 같은 포트를 쓰는 프로젝트는 함께 켜지 못한다(옛 프로젝트 둘, 또는 같은 프로젝트를 두 번 켬). 켜진 프로젝트를 끈 뒤 켠다. 새로 만드는 프로젝트는 다른 포트를 받는다 |
| 팀원이 프로젝트를 찾지 못한다 | 프로젝트 코드 철자, 프로젝트 서버가 켜져 있는지, 프로젝트가 만료나 닫힘이 되지 않았는지 |
| 팀원이 코드가 틀렸다고 한다 | 24시간 만료, 이미 사용 → "코드 다시 받기"(수동 실행은 `server reinvite`) |
| 팀원이 "코드 입력 실패가 너무 많다"나 "로그인 실패가 너무 많다"고 한다 | 10분 기다린다. 같은 IP에서 5번 실패하면 막힌다 |
| 팀원이 화면에서 "토큰이 올바르지 않다" | 화면의 "접속 실패 기록"에서 사유를 본다 |
| 승인에서 "가지가 바뀌었다" | 팀원이 다시 제출해야 한다 |
| 터널 토큰을 잃었다 | `python -m beot start`가 서버장에게서 자동으로 다시 받는다(리더 토큰이 있어야 한다) |
| 수동 실행에서 팀원이 "프로젝트 서버에 연결하지 못했다" | 같은 네트워크인지, 프로젝트 주소(`http://`로 시작), 프로젝트 서버가 켜져 있는지, 방화벽 |
| 프로젝트 서버가 이상하게 응답한다 | 포트 8780을 다른 프로그램이 쓰는지 본다 |
| 반려했는데 PR 댓글이 없다 | 리더 에이전트에게 `events_since`로 `pr_comment_failed` 기록을 묻는다. 반려 자체는 기록된다 |
| `beot.exe`가 원격 데스크톱(AnyDesk 등)에서 멈추거나 창이 사라진다 | 원인을 확인하지 못했다(이슈 #1). `%LOCALAPPDATA%\Beot\launcher.log`의 마지막 줄(패닉, 창 오류)과 Windows 버전, 원격 프로그램 이름을 이슈에 알려 준다. 임시로 터미널에서 `beot.exe start --room 프로젝트이름`으로 켜고, 끌 때는 `beot.exe start --room 프로젝트이름 --stop`을 쓴다 |
| `No module named 'uvicorn'` | 시스템 `python`으로 실행했다. 벗 폴더의 가상환경을 켠다([9.2](#92-소스로-실행할-때의-주의)) |

수동 실행의 로그는 프로젝트 서버 창의 출력이다. 접속 실패는 화면의 "접속 실패 기록"에, 그 밖의 기록은 리더 에이전트의 `events_since`에서 본다.

| 작업 폴더가 이미 있다는 오류 | 그 폴더가 비어 있는지 본다. 내용이 있으면 리더에게 묻는다 |
| 403(오류 1010) | `join.py`가 최신인지 본다. 리더에게 새 `join.py`를 받는다 |
| 앱에서 에이전트 연결이 끊겼다 | 벗 앱이 켜져 있는지 본다. 토큰 중계가 꺼지면 에이전트의 프로젝트 연결만 끊긴다. 47811 포트를 다른 프로그램이 쓰는지 본다([19.2](#192-토큰-중계-115)) |

### 25장 알려진 한계

#### 25.1 공통
- 리더 PC가 꺼지면 팀원은 들어올 수 없다. 프로젝트와 로컬 보관의 git 원본은 그 PC가 켜져 있을 때만 쓸 수 있다.
- 닫지 않고 끄면 만료까지 프로젝트 주소와 터널이 남는다.
- 휴대폰 화면과 Windows가 아닌 PC는 지원하지 않는다.
- 이 PC 밖의 다른 PC에서 에이전트까지 실행하는 전체 흐름은 이 PC 안에서만 확인했다.
- 코드 서명이 없다. 앱 자동 업데이트는 확인값만 확인한다.

#### 25.2 수동 실행(LAN)의 한계
- 리더 PC의 LAN 주소가 바뀌면(DHCP) 프로젝트 주소가 바뀐다. 이미 `join`한 팀원의 설정(`.mcp.json`, git 원격 주소)이 모두 어긋난다. **고정 IP나 DHCP 예약을 먼저 정한다.** 주소가 바뀐 뒤의 복구 절차는 시험하지 않았다.
- LAN은 HTTP다. 신뢰하는 네트워크에서만 쓴다.
- 팀원 PC에 git-lfs가 없으면 큰 파일을 받지 못한다.
- 터널을 쓰는 프로젝트의 한계는 [8.6](#86-알아-둘-한계)이다.

#### 25.3 파일 탭의 비공개와 한계
파일 탭은 원본을 리더 PC에만 둔다. 접근은 초대된 팀원의 토큰으로만 된다. 그래도 아래 일은 막지 못한다.
1. **에이전트:** 팀원의 AI 에이전트는 받은 사본을 읽는다. 읽은 내용은 그 AI 서비스로 전송된다. 비공개로 둘 파일은 팀원이 에이전트에게 열어 주지 않게 정한다.
2. **팀원 PC의 사본:** 팀원에게서 접근을 끊어도 이미 받은 사본은 지워지지 않는다. 팀플이 끝나면 팀원에게 사본 삭제를 요청한다.
3. **리더 PC가 꺼지면 멈춘다:** 사본 받기와 제출이 멈춘다. 리더 PC가 유출되면 원본도 같이 유출된다. 백업 zip도 비공개로 둔다.
4. **Cloudflare 터널:** 전송이 Cloudflare 터널을 지난다. 연결은 암호화돼 있다. 터널을 지난다는 사실은 알고 쓴다.
5. **전체 읽기:** 폴더별 접근 범위가 없다. 팀원 전원이 원본 전체를 받는다.

#### 25.4 GitHub 방식의 한계
- 저장소가 공개다. 코드를 누구나 볼 수 있다.
- 팀원별 가지 제한이 안 된다. 팀원 A가 팀원 B의 `member/B/…` 가지를 바꾸거나 지울 수 있다(무료 개인 저장소는 사용자별 push 제한이 없다).
- 협업자 계정으로 실제 main push가 거부되는지는 리더 계정으로 대신 시험만 했다. 협업자 계정으로는 확인하지 못했다.
- 프로젝트 서버가 저장소 관리자 권한 토큰을 가진다. 프로젝트 서버 PC가 뚫리면 저장소가 넘어간다.

#### 25.5 지금은 없는 기능
- **IP 묶기(접속 IP 제한 설정):** 지웠다. 제한 설정 값이 남은 옛 프로젝트가 "IP · Tailscale 제한 설정을 쓴다"며 켜지지 않으면 `python -m beot server clear-binds`를 실행하고 `ROOM_BIND_IP`와 `ROOM_REQUIRE_TS`를 지운다.
- **Notion 연동(프로젝트의 Notion 내보내기, 일 동기화):** 지웠다. 에이전트가 자기 Notion을 읽는 **Notion MCP** 연결(앱 설정)은 그대로다([21.1](#211-앱의-설정에서-연결하기-가장-쉽다)). 옛 프로젝트에 남은 Notion 통합 토큰은 Windows 사용자 환경 변수 `BEOT_NOTION_TOKEN_<프로젝트>`에 있다. 설정 → 시스템 → 정보 → 고급 시스템 설정 → 환경 변수에서 직접 지운다. 남은 값은 읽지 않는다.
- **로그인 티켓:** 없어졌다. 앱은 프로필 비밀번호로 프로젝트 화면에 로그인한다.
- **사용자 환경 변수의 프로젝트 토큰(`BEOT_ROOM_TOKEN_<프로젝트>`):** 1.1.5에서 없어졌다. 토큰 저장소를 쓴다.

#### 25.6 1.1.9 ~ 1.2.2의 한계
- 대소문자만 다른 이름(`.MCP.JSON` · `.Codex\` · `.AGENTS\` 등)의 쓰기는 Claude Code 2.1.330(Windows)에서 막히는 것을 확인했다. 다른 Claude Code 판 · Windows 짧은 이름(8.3) · 파일 심볼릭 링크는 확인하지 못했다 (미확인). Claude Code를 올린 뒤에는 같은 시험을 다시 해야 한다. 도우미가 바뀐 설정 파일을 찾으면 멈춘다.
- API 키 저장은 Windows에서만 된다(1.2.2). 추정 금액과 Console의 실제 금액을 숫자로 대조하지는 않았다 (미확인).
- 봇 TF(1.2.0)의 도구 제한은 지시문 수준이다. 서버가 강제하지 않는다(봇별 서버 권한 분리가 없다). 실제 Orca에서의 주기 깨우기 · 사전 검사 결과 전달 · 결과 카드 위치는 사람 시험 전이다 (미확인).
- 15분을 넘는 봇 실행은 중복될 수 있다.
- 포터블은 한 PC에 1개다. 폴더를 옮기면 에이전트를 다시 연결한다.
- 에이전트가 사람의 비밀번호를 알면 막지 못한다. **에이전트에게 비밀번호를 알려 주지 않는다.**
- 에이전트 최종 검토 · Orca 봇은 리더 PC의 구독 한도를 쓴다.
- Orca 연결은 읽기 · 일 맡기 · 메모까지 확인했다. 일 제출, 주기 실행으로 스스로 깨어나기, 허가 직후 봇 깨우기는 확인하지 못했다 (미확인). Orca 봇은 일이 배정된 즉시가 아니라 정해 둔 주기나 채팅으로 깨어난다.
- Orca 봇 모드에서는 1차 통과와 최종 검토를 같은 봇이 한다. 서로 다른 모델이라는 보장이 없다. 마지막 방어선은 사람의 일별 허가(비밀번호)다.
- 트레이 알림을 눌러도 앱 창이 열리지 않을 수 있다. 벗 아이콘을 눌러 연다.
- 검토 화면의 PR 링크는 GitHub 방식 프로젝트에서만 보인다.
- GitHub 비공개 저장소를 쓰는 프로젝트에서 리더 폴더에 원격 저장소가 없으면 리더 에이전트가 제출을 받지 못해 사람이 검토한다.
- 화면의 언어는 한국어뿐이다. 언어 설정은 1.2.2에 없다.
- 외부 연결은 같은 PC(또는 Tailscale 주소)의 프로그램만 잇는다. 다른 PC의 프로그램을 잇는 순서는 아직 이 책에 없다([16.11](#1611-외부-연결-1116)).
- 외부 연결 화면의 그리기는 자동 시험이 없다. [16.11](#1611-외부-연결-1116)의 수동 확인으로 본다.
- 위의 1.1.15 한계(Orca 연결의 일 제출 · 주기 실행 깨어나기 · 허가 직후 깨우기 미확인 등)는 그대로다.

### 26장 비용과 한도

#### 26.1 서버장
- Workers 무료: 하루 요청 10만 번. 입구에서 프로젝트 코드를 찾을 때와 리더의 프로젝트 만들기와 알림만 Worker를 거친다. 팀원이 프로젝트에 들어간 뒤의 작업은 터널로 직접 가서 Worker를 거치지 않는다.
- 서버장 한 명이 이 한도를 모든 프로젝트와 나눠 쓴다.
- Durable Object(프로젝트 목록 저장)는 무료 계정에서 동작했다. 장기 사용량은 확인하지 않았다.
- 터널 사용료와 터널 개수 한도는 Cloudflare 요금 안내를 따른다. 벗은 프로젝트마다 터널 1개를 쓴다.
- 프로젝트 코드 추측 공격: 코드 공간은 약 20억이고, 맞혀도 프로젝트 주소만 알게 된다(비밀번호는 프로젝트 서버가 확인한다). 조회 속도 제한은 없다.
- 리더당 동시에 열 수 있는 프로젝트는 `--max`로 정한다(기본 2, 최대 20).
- 프로젝트 만료 기본은 14일이다(`--expire-days`).

#### 26.2 리더
- 한 PC에서 프로젝트는 최대 20개다. 포트는 8780~8799다.
- Cloudflare 터널은 요청 본문을 약 100MB, 응답 시간을 약 100초로 제한한다(Cloudflare 안내). 이보다 큰 파일은 터널로 올리지 않는다.
- 파일 탭의 파일 하나는 50MB 이하다. 문서함은 한 사람당 200MB까지다.
- GitHub 토큰은 만료를 90일 이하로 정하고 만료 전에 바꾼다.
- GitHub API에 속도 제한이 있다("GitHub 속도 제한"이 나오면 잠시 뒤 다시 한다).
- 입장 실패는 같은 주소에서 5번, 프로젝트 전체에서 20번이면 10분 동안 닫힌다.

#### 26.3 팀원
- 무인 도우미는 하루 실행 10번까지다. 구독 한도에 도달하면 한도 문구의 다시 시작 시각까지 쉰다.
- 무인 도우미를 구독 로그인으로 켜려면 약관 주의를 읽고 실행할 때마다 `--accept-terms`를 붙인다.
- 한 프로젝트에 추가 작업 폴더는 10개까지다.
- 한 멤버의 앱 세션은 PC 2대까지 쓴다.

### 이 부의 요약
- 증상별 표가 서버장, 리더, GitHub 방식, 팀원으로 나뉘어 있다. 증상의 글자로 찾는다.
- 리더 PC가 꺼지면 팀원은 프로젝트에 들어올 수 없다.
- 파일 탭은 비공개 작업에 쓰지만, 에이전트와 팀원 PC의 사본은 막지 못한다.
- GitHub 방식은 공개 저장소이고 팀원별 가지 제한이 안 된다.
- Workers 무료 한도(하루 10만 요청)는 서버장의 모든 프로젝트가 나눠 쓴다.
- 터널은 요청 본문 약 100MB, 응답 약 100초가 한계다.
- IP 묶기와 Notion 연동은 지금 없다.

| 프로젝트 코드 | 프로젝트를 찾는 값(예: `amber-river-moss-123`). 비밀번호가 아니다 |

| 로컬 보관 | 원본을 리더 PC의 git 저장소에 두는 방식. 비공개 작업에 쓴다 |
