# 벗 안내서: 서버장용

> **경고 1:** Cloudflare API 토큰과 서버장 관리 토큰은 채팅, 파일, 화면 공유에 남기지 않는다.
> **경고 2:** 서버장은 신뢰 기준이다. 서버장은 방 코드와 방 주소 목록을 볼 수 있다. 비밀번호(단어 코드)는 보지 못한다. 팀원은 아는 서버장의 도메인만 쓴다.
> **표시:** (미확인) = 시험하지 않았다. 아래 명령은 `example.com`로 시험했다.

## 0. 서버장이 무엇인가
- 도메인과 Cloudflare 계정을 가진 사람이다. **서버 PC는 없다.** 방 서버는 각 방장의 PC에서 돈다.
- 서버장이 하는 일: 한 번 설치하고, 방장에게 **방장 열쇠**을 준다.
- 방장은 그 토큰으로 방을 만든다. 팀원은 도메인에서 방 코드를 넣어 들어온다.
- 서버장마다 Cloudflare 계정이 따로다. 서버장 1의 방장 열쇠은 서버장 2의 도메인에서 쓸 수 없다.

## 0-1. 화면으로 설치 (권장)
서버장이 직접 하는 일은 3가지뿐이다: Cloudflare 계정과 도메인(Active), Cloudflare에서 토큰 복사, Bot Fight Mode 끄기(3절). 나머지는 화면에서 끝낸다.
1. `벗.exe`를 열고 **서버장 설정**을 누른다. 또는 `beot.exe owner setup --gui`를 실행한다.
2. **토큰 만들기**를 누른다. Cloudflare가 열린다. 권한이 미리 골라져 있다. 계속 → 토큰 만들기 → 값을 복사한다.
3. 화면의 토큰 칸에 붙여 넣고 **확인**을 누른다. 토큰은 파일에 저장하지 않는다.
4. 도메인 목록에서 도메인을 고른다. 권한 4개를 자동으로 검사한다. 없는 권한이 있으면 ✗로 보인다. Cloudflare에서 그 권한을 더한 새 토큰을 3번부터 다시 한다.
5. workers.dev 이름 칸이 나오면 이름을 넣는다. **설치**를 누른다. 단계별로 진행이 보인다. 실패하면 이유가 보이고, 고친 뒤 다시 눌러도 안전하다.
6. 서버장 계정(닉네임, 비밀번호)을 만든다. 관리 토큰을 복사하는 단계가 없다.
7. 방장 이름과 방 수를 넣고 **초대**를 누른다. 방장 열쇠가 한 번만 보인다. **복사**해서 방장에게 전달한다.
8. **입구 열기**로 입구를 확인하고 **끝내기**를 누른다.
- (미확인) 토큰 만들기 주소가 Cloudflare Tunnel 권한을 미리 고르는지. 문서에 그 키가 없다. 못 고르면 4번 검사가 ✗로 알려 준다. 그때 Cloudflare 화면에서 Account > Cloudflare Tunnel > Edit를 직접 더한다.
- 아래 1~9절은 같은 일을 명령으로 하는 방법이다.

## 1. 준비물
1. 도메인 하나. Cloudflare에 추가하고 상태가 **Active**가 될 때까지 기다린다.
2. Python 3와 이 프로그램(벗 폴더). 명령은 폴더에서 실행한다.
3. Cloudflare API 토큰. 아래 2절에서 만든다.
4. Cloudflare 계정에 `workers.dev` 주소. 없으면 설치 명령에 `--workers-subdomain 이름`을 붙인다(Cron에 필요).

## 2. Cloudflare API 토큰 만들기
1. Cloudflare 대시보드 > My Profile > API Tokens > Create Token > Custom token.
2. 권한은 아래를 기준으로 한다. 화면 이름이 다르면 화면을 따른다.

| 줄 | 항목 | 수준 |
|---|---|---|
| Account | Workers Scripts | Edit |
| Account | Cloudflare Tunnel | Edit |
| Zone | DNS | Edit |
| Zone | Workers Routes | Edit |

3. Account Resources는 내 계정, Zone Resources는 **Specific zone > 내 도메인**으로 정한다.
4. 만료일을 짧게 정한다(예: 7일). 설치가 끝나면 삭제해도 된다. 토큰은 Worker 비밀값으로 올라가서 방 만들기에 계속 쓰이므로, **삭제하면 새 방을 만들 수 없다.** 오래 쓰려면 만료 전에 새 토큰으로 `setup`을 다시 실행한다.
5. 토큰 값을 환경 변수에 저장한다. 입력은 화면에 보이지 않는다.
```powershell
$t = Read-Host "Cloudflare API 토큰" -AsSecureString; [Environment]::SetEnvironmentVariable("CLOUDFLARE_API_TOKEN", [Runtime.InteropServices.Marshal]::PtrToStringAuto([Runtime.InteropServices.Marshal]::SecureStringToBSTR($t)), "User")
```
환경 변수가 없으면 설치 명령이 숨김 입력으로 묻는다. 이 프로그램은 토큰을 파일에 저장하지 않는다.

## 3. Cloudflare 화면 설정
- **Bot Fight Mode: 끈다**(추천). 벗의 접속자는 브라우저가 아니라 프로그램(`join`, 에이전트)이라 도전 과제를 풀 수 없다. 켜 두면 막힐 수 있다. (미확인: 실제 에이전트가 막히는지는 T 시험에서 확인한다.)
- **공격 모드(Under Attack Mode): 켜지 않는다.** 모든 접속자에게 도전 과제를 내서 `join`과 에이전트가 막힌다.
- Access(이메일 인증)는 쓰지 않는다. 팀원이 이메일 등록 없이 코드만으로 들어와야 하기 때문이다.

## 4. 설치
```powershell
python beot_main.py owner setup --domain example.com
```
- `workers.dev` 주소가 없다는 안내가 나오면 `--workers-subdomain 이름`을 붙여 다시 실행한다.
- 이 명령이 하는 일: 토큰 검증, 도메인 Active 확인, **서버장 관리 토큰 생성**(이 PC 사용자 환경 변수 `BEOT_ADMIN_TOKEN_<도메인>`), Worker 올리기, 매일 03:17(UTC) 만료 점검(Cron) 설정, 입구 주소와 경로 만들기, 입구 응답 확인.
- 끝나면 `https://<도메인>/`에 "방 코드를 입력한다" 화면이 나온다.
- 다시 실행하면 갱신한다. 방 만료 기간을 바꾸려면 `--expire-days 7`처럼 붙인다(기본 14일).
- 새 주소가 퍼지는 데 몇 분이 걸릴 수 있다. 응답이 없다고 나오면 잠시 뒤 다시 확인한다.
- Cron은 설정 뒤 첫 실행까지 약 8분이 걸렸다(S1 시험).

## 5. 방장 초대
```powershell
python beot_main.py owner invite kim --max 2
```
- 방장 이름은 영문자·숫자·`-`·`_` 32자까지다. `--max`는 그 방장이 **동시에** 열 수 있는 방 수다(기본 2, 최대 20).
- 화면에 **방장 열쇠**(`bh_…`)이 한 번만 나온다. 방장에게 안전하게 전달한다. 다시 볼 수 없다.
- 방장에게 같이 알려 줄 것: **서버장 주소**(도메인). 방장은 `https://<도메인>`의 **방장** 탭에서 방을 만든다. 방장은 [안내서_방장.md](안내서_방장.md)를 따른다.

## 6. 운영
| 하고 싶은 일 | 명령 |
|---|---|
| 방장 목록과 방 수 | `python beot_main.py owner hosts` |
| 만료 점검 상태 | `python beot_main.py owner status` (Cron 마지막 실행, 닫은 방 수, 오류) |
| 방장 계정 풀기 | `python beot_main.py owner unbind kim` (방장이 비밀번호를 잃었을 때. 방장은 같은 방장 열쇠로 입구에서 계정을 다시 만든다) |
| 방장 지우기 | 서버장 화면의 **지우기**(폐기된 방장만) 또는 `python beot_main.py owner remove kim`. 열린 방이 있으면 안 된다(아래 `close-rooms`로 먼저 닫는다). 계정·세션도 같이 지운다. 되돌릴 수 없다 |
| 방장의 열린 방 닫기 | `python beot_main.py owner close-rooms kim` (터널·주소를 지운다. **폐기된 방장의 방도 닫는다.** 방장 PC의 방 데이터는 남는다). 순서: revoke → close-rooms → remove |
| 새 버전 알리기 | 벗을 새로 받은 서버장 PC에서 `VERSION` 파일을 올리고 `python beot_main.py owner setup`을 다시 실행한다. Worker가 그 버전을 "최신"으로 알리고, 이보다 낮은 버전으로 도는 방의 방장 화면에 새 버전 알림이 뜬다(닫으면 그 버전은 다시 안 뜬다) |
| 방장 폐기 | `python beot_main.py owner revoke kim` (새 방을 못 만든다. **폐기된 방장은 자기 방을 닫지 못한다.** 열린 방이 남아 있으면 명령이 알려 준다. `close-rooms`로 서버장이 닫는다) |
| 만료 기간 변경 | `python beot_main.py owner setup --expire-days 7` |
| 도메인이 여러 개일 때 | 명령 앞에 `--domain 도메인`을 붙인다 |

- **방 만료:** 방장 PC가 6시간마다 "살아 있음"을 알린다. 알림이 없는 날이 만료 기간(기본 14일)을 넘으면 Cron이 방의 터널과 주소를 지운다. 방장 PC의 저장물은 지우지 않는다.
- 서버장 관리 토큰을 잃으면 같은 PC에서 `setup`을 다시 실행해 새로 만든다. 이전 방장 열쇠은 계속 유효하다.

## 6-1. 서버장 화면 (입구의 "서버장" 탭)
명령 대신 브라우저로 방장 초대·목록·폐기·계정 풀기를 한다.
1. 관리 토큰을 클립보드에 넣는다(화면에 나오지 않는다). 도메인이 `example.com`이면:
```powershell
[Environment]::GetEnvironmentVariable("BEOT_ADMIN_TOKEN_BEOT_SPACE","User") | Set-Clipboard
```
2. 입구(`https://<도메인>`)의 **서버장** 탭 → "처음이면 · 서버장 관리 토큰으로 계정 만들기"를 펼친다. 닉네임, 비밀번호(8자 이상), 클립보드의 관리 토큰을 넣는다. **서버장 계정은 하나**다. 다음부터는 닉네임과 비밀번호만 넣는다.
3. 서버장 화면에서 방장 목록(방 수, 계정 여부), **새 방장 초대**(방장 열쇠는 한 번만 보인다), **폐기**, **계정 풀기**를 쓴다.
4. 서버장 비밀번호를 잃으면 이 PC에서 `python beot_main.py owner unbind-admin`을 실행하고 2번을 다시 한다.
5. 끝나면 클립보드를 다른 글자로 덮어쓴다.

## 7. 철거
```powershell
python beot_main.py owner teardown --yes
```
- 경로, 입구 주소, 열려 있는 모든 방의 터널과 주소, Worker(저장된 방 목록 포함)를 지운다. **열린 방이 모두 닫힌다.**
- 방장 PC의 방 데이터는 지우지 않는다. 이 PC의 관리 토큰 환경 변수는 남는다.

## 8. 비용·한도 (알려진 것과 모르는 것)
- Workers 무료: 하루 요청 10만 번. 입구에서 방 코드를 찾을 때와 방장의 방 만들기·알림만 Worker를 거친다. 팀원이 방에 들어간 뒤의 작업은 터널로 직접 가서 Worker를 거치지 않는다.
- 서버장 한 명이 이 한도를 모든 방과 나눠 쓴다.
- Durable Object(방 목록 저장)는 무료 계정에서 동작했다. 장기 사용량은 확인하지 않았다.
- **(미확인)** 터널 사용료와 터널 개수 한도.
- **(미확인)** 방 코드 추측 공격: 코드 공간은 약 20억이고, 맞혀도 방 주소만 알게 된다(비밀번호는 방장 서버가 확인한다). 조회 속도 제한은 없다.

## 9. 문제가 생겼을 때
| 증상 | 확인할 것 |
|---|---|
| `Active 상태가 아니다` | 도메인이 Cloudflare에서 Active인지, 토큰의 Zone 범위가 그 도메인인지 |
| `workers.dev 주소가 없다` | `--workers-subdomain 이름`을 붙인다 |
| 입구 응답을 확인하지 못했다 | 몇 분 뒤 `https://도메인/`을 연다. 같은 오류가 계속되면 `setup`을 다시 실행한다 |
| 방장이 "방 수를 넘었다"고 한다 | 방장이 `start.py --close`로 쓰지 않는 방을 닫거나, `invite`로 한도를 늘려 새 토큰을 발급한다 |
| 방장이 "방장 열쇠가 올바르지 않다"고 한다 | 폐기됐는지(`hosts`), 토큰을 끝까지 복사했는지 본다 |
| 팀원이 `join`에서 403(오류 1010) | 프로그램이 최신인지 본다(User-Agent 지정 버전). Bot Fight Mode를 끈다 |
